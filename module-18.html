Module 18 — Debugging Django

Now we start an extremely practical topic: Debugging.

In a Django project, knowing how to write code is only half the skill.

You also need to know:

When my code doesn't work, how do I find exactly what is wrong?

This is what debugging means.

1. What Is Debugging?

Debugging is the process of:

  1. Finding an error/problem
  2. Understanding why it happened
  3. Locating the problematic code
  4. Fixing it
  5. Testing again

Example:

You visit:

TEXT
/students/

and Django shows:

TEXT
TemplateDoesNotExist

Debugging means determining:

Which template is Django looking for, where is it searching, and why can't it find it?

2. Error vs Bug

These terms are related but different.

Error

A problem that prevents code from working correctly.

Example:

PYTHON
print(name

Missing ) → syntax error.

Bug

The program runs but behaves incorrectly.

Example:

PYTHON
price = 100
quantity = 5

total = price + quantity

The program runs, but the correct calculation should be:

PYTHON
total = price * quantity

So:

Error = problem in execution/code.
Bug = incorrect behavior or result.

3. Django Debug Mode

Open:

TEXT
settings.py

You'll find:

PYTHON
DEBUG = True

During development, Django gives detailed error information when something goes wrong.

For example:

TEXT
TemplateDoesNotExist at /students/

and below it you'll get a traceback showing where the error occurred.

4. Why Is DEBUG=True Useful?

Because Django can show:

  • Exception type
  • Error message
  • File name
  • Line number
  • Code around the error
  • Traceback
  • Request information
  • Django/Python information

This makes debugging much easier.

5. ⚠️ Never Use DEBUG=True in Production

Suppose your production website crashes.

If:

PYTHON
DEBUG = True

Django can expose sensitive internal information through the detailed error page.

Therefore:

PYTHON
DEBUG = False

should normally be used in production.

This is both an exam question and an important security concept.

6. Reading a Django Error Page

Suppose Django displays:

TEXT
TemplateDoesNotExist at /students/

students/list.html

Don't panic.

Read the error from top to bottom.

The important information is:

TEXT
Exception:
TemplateDoesNotExist

Message:
students/list.html

This immediately tells you:

Django couldn't find the requested template.

7. Traceback

A traceback shows the chain of function calls that led to the error.

For example:

TEXT
Traceback

File ".../urls.py", line 10
    path("students/", views.students)

File ".../views.py", line 15
    return render(...)

TemplateDoesNotExist

The most useful part is usually the last exception shown, along with the file/line information around where it occurred.

8. Debugging Strategy

When Django gives an error, follow this sequence:

TEXT
1. Read exception type
        ↓
2. Read error message
        ↓
3. Find file and line number
        ↓
4. Inspect surrounding code
        ↓
5. Check related configuration
        ↓
6. Fix
        ↓
7. Run again

Don't randomly change multiple files.

9. Error #1 — SyntaxError

Example:

PYTHON
def home(request)
    return HttpResponse("Hello")

There's a missing :.

Python reports something similar to:

TEXT
SyntaxError: expected ':'

Correct:

PYTHON
def home(request):
    return HttpResponse("Hello")

10. Syntax Errors in Templates

For example:

HTML
{% if user %}
    Hello

You forgot:

HTML
{% endif %}

Correct:

HTML
{% if user %}
    Hello
{% endif %}

Template syntax errors can appear when Django compiles the template.

11. Error #2 — NameError

Example:

PYTHON
def home(request):
    return HttpResponse(message)

But message was never defined.

You may get:

TEXT
NameError: name 'message' is not defined

Correct:

PYTHON
def home(request):
    message = "Hello"
    return HttpResponse(message)

12. Error #3 — ImportError

Suppose:

PYTHON
from django.http import HttpRespons

The actual class is:

PYTHON
HttpResponse

You may get an import-related error.

Correct:

PYTHON
from django.http import HttpResponse

Common causes:

  • Typo in import
  • Wrong module
  • Missing package
  • Circular imports in more advanced projects

13. Error #4 — ModuleNotFoundError

Example:

PYTHON
import some_package

but the package isn't installed.

Python may report:

TEXT
ModuleNotFoundError

For third-party packages, check the active virtual environment and installation.

For Django itself:

BASH
python -m django --version

14. Error #5 — TemplateDoesNotExist

This is one of the most common Django beginner errors.

Suppose your view says:

PYTHON
return render(request, "home.html")

but Django can't find it.

You may see:

TEXT
TemplateDoesNotExist at /
home.html

15. Why Does TemplateDoesNotExist Happen?

Common reasons:

Reason 1 — Wrong folder

You might have:

TEXT
templates/
    home.htm

but requested:

TEXT
home.html

Reason 2 — Wrong filename

PYTHON
render(request, "home.html")

but file is:

TEXT
homepage.html

Reason 3 — App not installed

If using app-level templates:

PYTHON
INSTALLED_APPS = [
    ...
    "students",
]

must include the app.

Reason 4 — Wrong path

Suppose:

TEXT
students/
└── templates/
    └── students/
        └── home.html

Then:

PYTHON
render(request, "students/home.html")

not:

PYTHON
render(request, "home.html")

16. Correct App Template Structure

Recommended:

TEXT
students/
│
├── templates/
│   └── students/
│       └── home.html
│
├── views.py
└── ...

Then:

PYTHON
return render(
    request,
    "students/home.html"
)

The extra students/ directory helps avoid template-name collisions between apps.

17. Error #6 — NoReverseMatch

This is another very important Django error.

Suppose URL:

PYTHON
path(
    "student/<int:id>/",
    views.student_detail,
    name="student_detail"
)

But template says:

HTML
<a href="{% url 'student_detail' %}">
    Student
</a>

Django needs the id parameter.

You might get:

TEXT
NoReverseMatch

18. Fixing NoReverseMatch

Provide the required parameter:

HTML
<a href="{% url 'student_detail' id=101 %}">
    Student
</a>

Or dynamically:

HTML
<a href="{% url 'student_detail' id=student.id %}">
    Student
</a>

19. NoReverseMatch Common Causes

Wrong URL name

URL:

PYTHON
name="student_detail"

Template:

HTML
{% url 'student' %}

Wrong.

Missing parameter

URL:

PYTHON
path(
    "student/<int:id>/",
    views.student_detail,
    name="student_detail"
)

Template:

HTML
{% url 'student_detail' %}

Missing id.

Wrong parameter name

URL:

PYTHON
<int:id>

Template:

HTML
{% url 'student_detail' student_id=101 %}

Wrong keyword.

Use:

HTML
{% url 'student_detail' id=101 %}

20. Error #7 — ViewDoesNotExist

Suppose:

PYTHON
path(
    "home/",
    views.hom
)

but the actual function is:

PYTHON
def home(request):

Django can't find the specified view.

Correct:

PYTHON
path(
    "home/",
    views.home
)

21. Error #8 — AttributeError

Example:

PYTHON
student = {
    "name": "Aman"
}

print(student.name)

A dictionary doesn't provide that access pattern in normal Python.

You'd use:

PYTHON
student["name"]

or in a Django template:

HTML
{{ student.name }}

A Python error may look like:

TEXT
AttributeError

22. Error #9 — TypeError

Example:

PYTHON
age = 20

print(age + " years")

Python cannot add an integer and string directly.

You'll get a TypeError.

Correct:

PYTHON
print(str(age) + " years")

or use an f-string:

PYTHON
print(f"{age} years")

23. Error #10 — DoesNotExist

This becomes especially important when we start using models.

Suppose:

PYTHON
student = Student.objects.get(id=100)

If no matching student exists, Django raises something like:

TEXT
Student.DoesNotExist

Later, you'll learn the cleaner solution:

PYTHON
from django.shortcuts import get_object_or_404

student = get_object_or_404(Student, id=100)

which converts the missing object into an HTTP 404 response.

24. Error #11 — OperationalError

You may encounter database errors such as:

TEXT
django.db.utils.OperationalError

Common causes can include:

  • Database configuration problems
  • Missing database table
  • Migration not applied
  • Database connection failure

For example, if you create a model but haven't applied migrations, you may encounter a missing-table problem.

We'll understand this much better in the Models/Migrations modules.

25. Error #12 — 404 Page Not Found

Suppose your URL configuration contains:

PYTHON
path("students/", views.students)

but you visit:

TEXT
/student/

Notice:

TEXT
students/

vs:

TEXT
student/

Django doesn't find a matching URL and returns:

TEXT
404 Not Found

26. URL 404 vs Object 404

Very important distinction.

URL doesn't exist:

TEXT
/students/abc/

doesn't match your URL pattern.

That's a URL routing 404.

URL exists but object doesn't:

TEXT
/student/999/

matches:

PYTHON
<int:id>

but student 999 doesn't exist.

That's an object/data 404.

These are different problems even though both result in HTTP 404.

27. Error #13 — CSRF Error

You'll encounter this in the Forms module.

A POST form may produce:

TEXT
403 Forbidden
CSRF verification failed

Often this means the template doesn't contain the required CSRF token.

Typical Django form:

HTML
<form method="POST">

    {% csrf_token %}

    ...
    
</form>

We'll study CSRF properly in Unit IV.

28. Error #14 — Port Already in Use

Suppose you start:

BASH
python manage.py runserver

but another process is already using port 8000.

You can use another port:

BASH
python manage.py runserver 8001

Then visit:

TEXT
http://127.0.0.1:8001/

29. Error #15 — Wrong Virtual Environment

Suppose Django was installed inside:

TEXT
venv

but VS Code is using another Python interpreter.

You might see:

TEXT
ModuleNotFoundError: No module named 'django'

even though you installed Django.

Check:

BASH
python -m django --version

and verify that the correct virtual environment/interpreter is active.

30. Django Debug Toolbar vs Django Debug Mode

Don't confuse:

TEXT
DEBUG = True

with a separate debugging tool such as Django Debug Toolbar.

DEBUG=True is a Django setting controlling development behavior and error reporting.

A debug toolbar is an additional development package/tool used for inspecting things such as:

  • SQL queries
  • request information
  • templates
  • performance

For your syllabus, the important concept is primarily:

PYTHON
DEBUG = True

31. Using print() for Debugging

A beginner-friendly technique:

PYTHON
def home(request):

    name = "Aman"

    print(name)

    return render(
        request,
        "home.html",
        {"name": name}
    )

The value appears in the terminal running Django.

You can inspect:

PYTHON
print(request.method)
print(request.GET)
print(request.POST)

during development.

32. Better Debugging With breakpoint()

Python provides:

PYTHON
breakpoint()

Example:

PYTHON
def student(request):

    students = ["Aman", "Rahul"]

    breakpoint()

    return render(
        request,
        "students.html",
        {"students": students}
    )

Execution pauses at that point when using a suitable debugger/terminal environment.

You can inspect variables.

This is more advanced than print() debugging.

33. Debugging in VS Code

VS Code provides a debugger where you can:

  • Set breakpoints
  • Run code step-by-step
  • Inspect variables
  • Watch expressions
  • See the call stack

A breakpoint is a point where program execution pauses so you can inspect what's happening.

34. Example Debugging Process

Suppose:

PYTHON
def student(request):

    student = {
        "name": "Aman",
        "age": 21
    }

    return render(
        request,
        "students/detail.html",
        {"student": student}
    )

You get:

TEXT
TemplateDoesNotExist
students/detail.html

Step 1

Read exception:

TEXT
TemplateDoesNotExist

Step 2

Read requested path:

TEXT
students/detail.html

Step 3

Check filesystem:

TEXT
students/
└── templates/
    └── students/
        └── detail.html

If instead you have:

TEXT
students/
└── templates/
    └── detail.html

the requested path is wrong for that structure.

Step 4

Fix either the path or template location.

Step 5

Reload.

That's systematic debugging.

35. Don't Change Everything at Once

A common beginner mistake is:

"It doesn't work, so I'll change views.py, urls.py, settings.py, and HTML simultaneously."

Don't.

Instead:

TEXT
Error
 ↓
Identify exact error
 ↓
Identify responsible layer
 ↓
Change minimum necessary code
 ↓
Test

36. Identify the Layer

Django applications can be thought of as layers:

TEXT
Browser
   ↓
URL
   ↓
View
   ↓
Model/Database
   ↓
Template
   ↓
Response

If the error is:

TEXT
NoReverseMatch

look first at:

TEXT
URLs + template URL tag

If:

TEXT
TemplateDoesNotExist

look at:

TEXT
Template path + settings + installed app

If:

TEXT
DoesNotExist

look at:

TEXT
Database query/object retrieval

This saves enormous time.

37. Error Diagnosis Table

Error Usually means
SyntaxError Invalid Python syntax
NameError Variable/name doesn't exist
ImportError Import problem
ModuleNotFoundError Module/package can't be found
TemplateDoesNotExist Template can't be found
NoReverseMatch URL reversing failed
ViewDoesNotExist Referenced view can't be found
AttributeError Object doesn't have requested attribute
TypeError Wrong/incompatible type operation
DoesNotExist Requested model object doesn't exist
OperationalError Database/SQL-related operational issue
404 URL/resource not found
403 Permission/CSRF/access forbidden
500 Server-side application error

38. ⭐ Very Important: Read the Last Exception

Suppose the traceback contains:

TEXT
File ...
File ...
File ...
File ...

TemplateDoesNotExist

Don't get overwhelmed by the entire traceback.

Start with:

What exception occurred?

Then:

What message accompanies it?

Then:

Which line in my code triggered it?

Teacher:

What is NoReverseMatch?

Teacher:

Answer:

A traceback is a report showing the sequence of function calls that led to an exception, along with information about where the error occurred.

Teacher:

Difference between 404 and 500?

Answer:

A 404 indicates that the requested resource or URL was not found, while a 500 indicates an unexpected server-side error occurred while processing the request.

51. Debugging Checklist ⭐

Whenever your Django application isn't working:

1. Check terminal

Look for:

TEXT
Exception
Error
Traceback

2. Check browser

Look at:

TEXT
404
403
500

3. Read the exception

For example:

TEXT
TemplateDoesNotExist

4. Check exact line

Don't just read the filename.

5. Check spelling

Especially:

TEXT
URLs
view names
template names
variable names
imports

6. Check configuration

Especially:

TEXT
INSTALLED_APPS
TEMPLATES
DATABASES
URL patterns

7. Test again

Don't assume the fix worked until you reload/test.

52. ⭐ Master Debugging Flow

Memorize this:

TEXT
                    ERROR
                      ↓
             Read exception type
                      ↓
             Read error message
                      ↓
             Find file + line
                      ↓
              Identify Django layer
                      ↓
             Check relevant code
                      ↓
                 Fix it
                      ↓
                  Test again

This is much better than randomly modifying code.
