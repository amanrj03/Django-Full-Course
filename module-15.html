Module 15 — Django Template Filters in Depth

Now we'll properly master Django Template Filters.

You already know:

HTML
{{ name }}

A filter lets you modify or transform the value before displaying it.

For example:

HTML
{{ name|upper }}

If:

TEXT
name = "aman"

the output is:

TEXT
AMAN

1. What Is a Template Filter?

A template filter takes a value and transforms it.

Syntax:

HTML
{{ value|filter }}

Think of it as:

TEXT
value
  ↓
filter
  ↓
modified value

Example:

HTML
{{ name|upper }}
TEXT
aman
 ↓
upper
 ↓
AMAN

2. Why Do We Need Filters?

Suppose the view gives:

PYTHON
name = "aman"

You could change it in Python:

PYTHON
name = name.upper()

But sometimes the transformation is purely for presentation.

Instead, the template can handle it:

HTML
{{ name|upper }}

This keeps simple presentation formatting inside the template.

3. The Pipe |

The pipe character:

TEXT
|

is used to apply a filter.

Example:

HTML
{{ name|upper }}

Read this as:

Take name and apply the upper filter.

4. upper

Converts text to uppercase.

HTML
{{ name|upper }}

If:

TEXT
name = "Aman"

output:

TEXT
AMAN

5. lower

Converts text to lowercase.

HTML
{{ name|lower }}

If:

TEXT
name = "DJANGO"

output:

TEXT
django

6. title

Converts words to title case.

HTML
{{ sentence|title }}

If:

TEXT
hello django world

output:

TEXT
Hello Django World

7. capfirst

capfirst capitalizes the first character.

HTML
{{ name|capfirst }}

For:

TEXT
aman

output:

TEXT
Aman

8. length

Returns the length of a value.

HTML
{{ name|length }}

If:

TEXT
name = Aman

output:

TEXT
4

For a list:

HTML
{{ students|length }}

If:

PYTHON
students = ['Aman', 'Rahul', 'Rohit']

output:

TEXT
3

9. default

This is one of the most useful filters.

Syntax:

HTML
{{ value|default:"fallback" }}

Example:

HTML
{{ name|default:"Guest" }}

If:

TEXT
name = ""

output:

TEXT
Guest

10. default_if_none

There is an important difference between:

TEXT
default

and:

TEXT
default_if_none

default_if_none only replaces the value when it is actually None.

Example:

HTML
{{ name|default_if_none:"Guest" }}

If:

PYTHON
name = None

output:

TEXT
Guest

But it doesn't have exactly the same behavior as default for other false/empty values.

11. default vs default_if_none

Remember:

TEXT
default
    ↓
fallback for empty/false-ish values

default_if_none
    ↓
fallback specifically for None

This is a good viva question.

12. Filter Arguments

Some filters accept arguments.

Example:

HTML
{{ name|default:"Guest" }}

Here:

TEXT
default

is the filter and:

TEXT
"Guest"

is its argument.

Another:

HTML
{{ text|truncatechars:20 }}

13. truncatechars

This filter shortens text.

Example:

HTML
{{ description|truncatechars:20 }}

It limits the rendered text to the specified number of characters, including the ellipsis when truncation occurs.

Useful for:

  • blog previews
  • product descriptions
  • summaries
  • cards

14. Example

Suppose:

PYTHON
description = "Django is a high level Python web framework."

Template:

HTML
<p>{{ description|truncatechars:20 }}</p>

Django produces a shortened version with an ellipsis when necessary.

You don't need to memorize the exact output for every string; understand the purpose.

15. wordcount

The:

HTML
{{ text|wordcount }}

filter returns the number of words.

For:

TEXT
"Django is powerful"

output:

TEXT
3

16. join

Suppose your view sends:

PYTHON
subjects = [
    'Python',
    'Django',
    'SQL'
]

Template:

HTML
{{ subjects|join:", " }}

Output:

TEXT
Python, Django, SQL

The argument:

TEXT
", "

specifies what should be placed between elements.

17. Different Join Separators

You can write:

HTML
{{ subjects|join:" | " }}

Output:

TEXT
Python | Django | SQL

Or:

HTML
{{ subjects|join:" - " }}

Output:

TEXT
Python - Django - SQL

18. add

The add filter attempts to add its argument to the value.

Example:

HTML
{{ age|add:"1" }}

If:

TEXT
age = 21

it can produce:

TEXT
22

It can also concatenate compatible values, so don't think of it as exclusively numeric addition.

19. cut

cut removes all occurrences of a specified string.

Example:

HTML
{{ name|cut:" " }}

If:

TEXT
name = "Aman Ranjan"

the spaces are removed:

TEXT
AmanRanjan

20. slugify

slugify converts text into a slug-like format.

Example:

HTML
{{ title|slugify }}

If:

TEXT
title = "Django Web Development"

it can produce:

TEXT
django-web-development

This is useful when creating readable URL slugs.

21. first

For a list:

HTML
{{ students|first }}

returns the first item.

If:

PYTHON
students = ['Aman', 'Rahul', 'Rohit']

output:

TEXT
Aman

22. last

Similarly:

HTML
{{ students|last }}

returns:

TEXT
Rohit

23. random

The random filter returns a randomly selected item from a sequence.

Example:

HTML
{{ students|random }}

If:

PYTHON
students = ['Aman', 'Rahul', 'Rohit']

the result can be one of those values.

Because it is random, the output isn't predictable.

24. length on a String vs List

The same filter can work on different types.

String:

TEXT
"Aman"
HTML
{{ name|length }}

→

TEXT
4

List:

PYTHON
['Aman', 'Rahul', 'Rohit']
HTML
{{ students|length }}

→

TEXT
3

25. Filter Chaining

This is very important.

You can apply multiple filters:

HTML
{{ name|upper|length }}

Suppose:

TEXT
name = aman

Processing:

TEXT
aman
 ↓ upper
AMAN
 ↓ length
4

Output:

TEXT
4

26. Another Chain

HTML
{{ name|lower|capfirst }}

Suppose:

TEXT
name = aMAN

First:

TEXT
aMAN
 ↓ lower
aman

then:

TEXT
aman
 ↓ capfirst
Aman

Output:

TEXT
Aman

27. Order Matters

Consider:

HTML
{{ name|upper|length }}

versus:

HTML
{{ name|length|upper }}

The first makes sense:

TEXT
name → uppercase → length

The second tries to apply upper to the result of length, which is a number and isn't equivalent.

So:

Filters are applied from left to right.

28. floatformat

This is useful for decimal numbers.

Suppose:

PYTHON
price = 125.6789

Template:

HTML
{{ price|floatformat:2 }}

Output:

TEXT
125.68

It formats the value to approximately two decimal places according to Django's floatformat rules.

29. floatformat:0

Example:

HTML
{{ price|floatformat:0 }}

For:

TEXT
125.6789

it produces a rounded integer-style representation.

30. date

Suppose the view sends a Python date/datetime value:

PYTHON
today

You can format it:

HTML
{{ today|date:"d-m-Y" }}

Example output:

TEXT
12-09-2026

31. Common Date Format Characters

Some useful Django date-format characters:

TEXT
d → day, 2 digits
m → month, 2 digits
Y → 4-digit year
y → 2-digit year
M → short month name
F → full month name

So:

HTML
{{ date|date:"d M Y" }}

might produce:

TEXT
12 Sep 2026

And:

HTML
{{ date|date:"F d, Y" }}

might produce:

TEXT
September 12, 2026

32. time

For a time/datetime value:

HTML
{{ value|time:"H:i" }}

can display something like:

TEXT
20:30

33. urlencode

urlencode is used to encode values for safe use in URLs.

Example:

HTML
{{ value|urlencode }}

This becomes useful when constructing URLs from dynamic values.

34. linebreaks

The linebreaks filter can convert plain text line breaks into suitable HTML paragraphs and line breaks.

Example:

HTML
{{ message|linebreaks }}

Useful when displaying user-entered text where line breaks matter.

35. striptags

This filter removes HTML tags from a string.

Example:

HTML
{{ content|striptags }}

If content contains HTML markup, the tags are removed from the resulting text.

This can be useful when you need plain-text-like output.

36. safe

As you learned in Module 13:

HTML
{{ content|safe }}

marks the value as safe for HTML rendering.

Example:

PYTHON
content = "<b>Hello</b>"

Without safe, Django normally escapes the markup.

With:

HTML
{{ content|safe }}

the <b> element can be interpreted as HTML.

⚠️ Security warning

Never blindly apply safe to untrusted user input.

It can create an XSS vulnerability.

37. escape

Django also provides:

HTML
{{ content|escape }}

which explicitly escapes HTML-sensitive characters.

However, remember that Django templates already autoescape normal variable output by default in typical configurations.

38. Autoescape

Suppose:

PYTHON
message = "<script>alert('Hello')</script>"

Template:

HTML
{{ message }}

Django normally escapes the HTML rather than allowing the supplied markup to execute as HTML.

That's part of Django's security model.

39. safe vs escape

safe escape
Marks content as safe HTML Escapes HTML-sensitive characters
Can allow HTML rendering Prevents HTML from being interpreted as markup
Dangerous for untrusted input Useful for safely displaying text

40. Filter With an Object

Suppose:

PYTHON
student = {
    'name': 'aman'
}

Template:

HTML
{{ student.name|upper }}

Output:

TEXT
AMAN

You can apply filters to resolved values, not just simple variables.

41. Filter With a Model Field

Later, when we work with models, you might have:

HTML
{{ student.name|title }}

or:

HTML
{{ product.price|floatformat:2 }}

This is extremely common in real Django applications.

42. Multiple Filters on Model Data

For example:

HTML
{{ product.name|title|truncatechars:30 }}

Processing:

TEXT
Product name
    ↓
title
    ↓
truncatechars
    ↓
display

43. Important Rule: Filters Don't Change the Original Variable

Suppose:

HTML
{{ name|upper }}
{{ name }}

If:

TEXT
name = aman

the first outputs:

TEXT
AMAN

and the second still outputs:

TEXT
aman

The filter changes the value for that template expression; it doesn't permanently modify the original context variable.

44. Common Mistake — Wrong Syntax

Wrong:

HTML
{{ name upper }}

Correct:

HTML
{{ name|upper }}

The pipe is required.

45. Common Mistake — Wrong Argument Syntax

Wrong:

HTML
{{ name|default("Guest") }}

That's Python/function-call style.

Correct DTL syntax:

HTML
{{ name|default:"Guest" }}

46. Common Mistake — Using Python Methods

You might be tempted to write:

HTML
{{ name.upper() }}

Don't treat DTL like Python.

Use:

HTML
{{ name|upper }}

This is one of the easiest ways to remember why filters exist.

47. Common Mistake — Assuming Every Filter Exists

Don't invent Python methods inside templates.

For example:

HTML
{{ name|capitalize }}

is not the standard Django filter name you should use.

Django has specific built-in filter names, such as:

TEXT
capfirst
upper
lower
title

48. Practical Example — Product Page

View:

PYTHON
def product(request):

    product = {
        'name': 'gaming laptop',
        'price': 79999.456,
        'description': 'A powerful laptop for gaming and development.'
    }

    return render(
        request,
        'product.html',
        {'product': product}
    )

Template:

HTML
<h1>{{ product.name|title }}</h1>

<p>₹{{ product.price|floatformat:2 }}</p>

<p>
    {{ product.description|truncatechars:30 }}
</p>

This is a very realistic use of filters.

49. Practical Example — Student List

View:

PYTHON
def students(request):

    students = [
        'aman',
        'rahul',
        'rohit'
    ]

    return render(
        request,
        'students.html',
        {'students': students}
    )

Template:

HTML
<h1>Students</h1>

<p>Total students: {{ students|length }}</p>

<p>First student: {{ students|first|title }}</p>

<p>Last student: {{ students|last|title }}</p>

Output:

TEXT
Total students: 3
First student: Aman
Last student: Rohit

55. Viva Questions

Q1. What is a Django template filter?

A template filter transforms or processes a template value before it is rendered.

Q2. What symbol is used to apply a filter?

The pipe | symbol.

Q3. Can filters be chained?

Yes. Multiple filters can be applied from left to right.

Q4. What does upper do?

Converts text to uppercase.

Q5. What does length do?

Returns the length of a value when applicable.

Q6. What does default do?

Provides a fallback value when the value is empty or false according to the filter's behavior.

56. Viva — default vs default_if_none

Teacher:

What's the difference?

Answer:

default provides its fallback for values that evaluate as false, while default_if_none provides the fallback specifically when the value is None.

57. Viva — Filter Chaining

Teacher:

In what order are filters applied?

Answer:

Filters are applied from left to right.

For:

HTML
{{ name|upper|length }}

the order is:

TEXT
name
 ↓
upper
 ↓
length

58. Viva — safe

Teacher:

Why can safe be dangerous?

Answer:

Because it marks content as safe HTML. If the content contains untrusted malicious HTML or JavaScript, marking it safe can bypass normal escaping and potentially create an XSS vulnerability.

59. Viva — Template vs Python

Teacher:

Why use {{ name|upper }} instead of name.upper()?

Answer:

Django templates use the Django Template Language rather than arbitrary Python code. The upper template filter is the appropriate DTL mechanism for presentation-level uppercase formatting.

🎯 Module 15 Coding Challenge

Given this view:

PYTHON
def student(request):

    student = {
        'name': 'aman ranjan',
        'course': 'computer science',
        'marks': 87.5678,
        'subjects': ['Python', 'Django', 'SQL']
    }

    return render(
        request,
        'student.html',
        {'student': student}
    )

Write a template that displays:

TEXT
Name: Aman Ranjan
Course: COMPUTER SCIENCE
Marks: 87.57
Number of subjects: 3
Subjects: Python, Django, SQL

You should use:

  • title
  • upper
  • floatformat
  • length
  • join

A clean solution is:

HTML
<h1>Name: {{ student.name|title }}</h1>

<p>Course: {{ student.course|upper }}</p>

<p>Marks: {{ student.marks|floatformat:2 }}</p>

<p>
    Number of subjects:
    {{ student.subjects|length }}
</p>

<p>
    Subjects:
    {{ student.subjects|join:", " }}
</p>

If you understand why every filter is used, you've mastered this module.
