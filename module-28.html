Module 28 — Django ORM in Depth

This is one of the most important Django modules for coding rounds.

Until now, we learned how to create models and database tables. Now we learn how to actually work with the data.

The central concept is:

Django ORM lets you interact with the database using Python code instead of writing SQL for every query.

1. What Is ORM?

ORM = Object-Relational Mapping

Django's ORM provides a Python interface to your database.

For example, SQL:

SQL
SELECT * FROM students_student;

can be represented using Django ORM as:

PYTHON
Student.objects.all()

Conceptually:

TEXT
Python code
     ↓
Django ORM
     ↓
SQL generated by Django
     ↓
Database

You don't normally need to manually write that SQL.

2. Why Do We Use ORM?

Without ORM, you would frequently have to write SQL:

SQL
SELECT * FROM students_student
WHERE age > 18;

With Django:

PYTHON
Student.objects.filter(age__gt=18)

Benefits include:

  • Python-based database interaction
  • Less repetitive SQL
  • Database backend abstraction
  • Query composition
  • Integration with Django models
  • Easier application development

3. Our Example Model

We'll use this throughout the module:

PYTHON
from django.db import models


class Student(models.Model):

    name = models.CharField(max_length=100)

    age = models.IntegerField()

    email = models.EmailField()

    course = models.CharField(max_length=50)

    marks = models.IntegerField(default=0)

    is_active = models.BooleanField(default=True)

Suppose our database contains:

id name age course marks is_active
1 Aman 21 CSE 85 True
2 Rahul 22 ECE 72 True
3 Priya 20 CSE 91 True
4 Neha 17 CSE 65 False

4. objects

You'll constantly see:

PYTHON
Student.objects

What is objects?

It is Django's default model manager.

The manager provides the interface for performing database queries.

For example:

PYTHON
Student.objects.all()

So:

TEXT
Student
   ↓
objects
   ↓
Query database

5. What Is a QuerySet?

When you do:

PYTHON
students = Student.objects.all()

Django returns a:

QuerySet

A QuerySet represents a collection of database records and provides methods for querying them.

Example:

PYTHON
students = Student.objects.all()

Conceptually:

TEXT
QuerySet
 ├── Student 1
 ├── Student 2
 ├── Student 3
 └── Student 4

6. all()

The simplest query:

PYTHON
Student.objects.all()

means:

Get all Student records.

Example:

PYTHON
students = Student.objects.all()

for student in students:
    print(student.name)

Output:

TEXT
Aman
Rahul
Priya
Neha

7. Important: QuerySets Are Lazy

This is an important Django concept.

When you write:

PYTHON
students = Student.objects.all()

Django doesn't necessarily immediately execute the database query at that exact line.

QuerySets are generally lazy.

The query is evaluated when Django actually needs the results.

For example:

PYTHON
students = Student.objects.all()

then:

PYTHON
for student in students:
    print(student.name)

causes the QuerySet to be evaluated.

8. Why Is Lazy Evaluation Useful?

Suppose:

PYTHON
students = Student.objects.all()

Then you add:

PYTHON
students = students.filter(age__gte=18)

Django can construct a combined query before it is evaluated.

Conceptually:

TEXT
QuerySet
 ↓
filter()
 ↓
filter()
 ↓
order_by()
 ↓
Database query

This allows efficient query construction.

9. filter()

One of the most important ORM methods:

PYTHON
Student.objects.filter(...)

It returns records matching the conditions.

Example:

PYTHON
Student.objects.filter(age=21)

Meaning:

Get students whose age is 21.

10. Filtering by Course

PYTHON
Student.objects.filter(course="CSE")

Result:

TEXT
Aman
Priya
Neha

because these students have CSE.

11. Multiple Conditions

You can provide multiple keyword arguments:

PYTHON
Student.objects.filter(
    course="CSE",
    age=21
)

This means:

TEXT
course = CSE
AND
age = 21

So multiple keyword conditions behave like AND.

12. filter() Returns a QuerySet

Even if only one record matches:

PYTHON
students = Student.objects.filter(id=1)

the result is still a QuerySet.

It can contain:

TEXT
0 records
1 record
many records

This differs from get().

13. get()

get() is used when you expect exactly one object.

Example:

PYTHON
student = Student.objects.get(id=1)

If exactly one student exists:

TEXT
Student object

is returned.

14. get() Exceptions

This is extremely important.

If no record matches:

PYTHON
Student.objects.get(id=999)

Django raises:

TEXT
Student.DoesNotExist

If multiple records match:

PYTHON
Student.objects.get(course="CSE")

and several students have CSE, Django raises:

TEXT
Student.MultipleObjectsReturned

Therefore:

Use get() when you expect exactly one object.

15. filter() vs get()

Memorize this table:

filter() get()
Returns QuerySet Returns one model object
Can return zero/many Must return exactly one
No DoesNotExist exception just because there are zero matches Raises DoesNotExist
Multiple matches are allowed Multiple matches raise MultipleObjectsReturned

Example:

PYTHON
Student.objects.filter(age=21)

vs:

PYTHON
Student.objects.get(id=1)

16. exclude()

exclude() returns records that do not match the condition.

Example:

PYTHON
Student.objects.exclude(course="CSE")

Meaning:

Get students whose course is not CSE.

17. Example

Suppose:

TEXT
Aman   CSE
Rahul  ECE
Priya  CSE
Neha   CSE

Then:

PYTHON
Student.objects.exclude(course="CSE")

returns:

TEXT
Rahul

18. Comparison Lookups

Django ORM provides lookup expressions.

Instead of:

PYTHON
Student.objects.filter(age > 18)

you write:

PYTHON
Student.objects.filter(age__gt=18)

Notice the double underscore:

TEXT
__

Case-insensitive version:

PYTHON
Student.objects.filter(

27. startswith

PYTHON
Student.objects.filter(
    name__startswith="A"
)

Gets names beginning with A.

28. endswith

PYTHON
Student.objects.filter(
    name__endswith="n"

Gets names ending in n.

29. in

Suppose you want students from CSE or ECE:

PYTHON
Student.objects.filter(
    course__in=["CSE", "ECE"]
)

This means:

TEXT
course IN ('CSE', 'ECE')

30. range

Suppose you want marks from 70 to 90:

PYTHON
Student.objects.filter(
    marks__range=(70, 90)
)

Conceptually:

TEXT
70 <= marks <= 90

The lookup uses the database/backend's range semantics; for ordinary numeric values this corresponds to an inclusive range.

31. isnull

Suppose:

PYTHON
phone = models.CharField(
    max_length=15,
    null=True
)

To find records where phone is NULL:

PYTHON
Student.objects.filter(
    phone__isnull=True
)

To find records where phone is not NULL:

PYTHON
Student.objects.filter(
    phone__isnull=False
)

Example:

PYTHON

    marks__gte=70

    "-marks"

Conceptually:

TEXT

      ↓
age >= 18
      ↓

      ↓

45. Filtering Multiple Conditions

You can also do:

PYTHON
Student.objects.filter(
    age__gte=18,
    marks__gte=70
)

This represents an AND condition.

46. OR Conditions Using Q

Suppose you want:

TEXT
course = CSE
OR
course = ECE

You can use Q.

PYTHON
from django.db.models import Q

Then:

PYTHON
Student.objects.filter(
    Q(course="CSE") |
    Q(course="ECE")
)

The | means OR.

47. AND With Q

PYTHON
Student.objects.filter(
    Q(course="CSE") &
    Q(marks__gte=80)
)

Meaning:

TEXT
course = CSE
AND
marks >= 80

48. NOT With Q

Use ~:

PYTHON
Student.objects.filter(
    ~Q(course="CSE")
)

Meaning:

TEXT
course != CSE

Conceptually:

TEXT
& → AND
| → OR
~ → NOT

This is an important advanced ORM feature.

You can create a record using:

PYTHON
Student.objects.create(
    name="Aman",
    age=21,
    email="aman@gmail.com",
    course="CSE",
    marks=85

This creates and saves the object.

Conceptually:

TEXT
Student.objects.create(...)
        ↓
Create object
        ↓
Save to database

50. create() vs save()

create()

PYTHON
student = Student.objects.create(
    name="Aman",
    age=21
)

Creates and saves immediately.

save()

PYTHON
student = Student(
    name="Aman",
    age=21
)

student.save()

You create the object first and then explicitly save it.

51. Updating an Object

Suppose:

PYTHON
student = Student.objects.get(id=1)

Change:

PYTHON
student.marks = 90

Then:

PYTHON
student.save()

Flow:

TEXT
Get object
   ↓
Change attribute
   ↓
save()
   ↓
Database updated

52. Updating Using update()

You can update directly through a QuerySet:

PYTHON
Student.objects.filter(
    id=1
).update(
    marks=90
)

This performs a database update without first loading each matching object into Python.

It returns the number of rows matched/updated by the operation.

53. update() Important Difference

Compare:

PYTHON
student.marks = 90
student.save()

with:

PYTHON
Student.objects.filter(
    id=1
).update(
    marks=90
)

The second performs a bulk database update.

One important consequence:

QuerySet.update() does not call each model instance's save() method.

So custom save() logic/signals that depend on save() behavior should be considered carefully.

54. Deleting

Get an object:

PYTHON
student = Student.objects.get(id=1)

Then:

PYTHON
student.delete()

Or directly:

PYTHON
Student.objects.filter(
    id=1
).delete()

55. QuerySet Delete

Example:

PYTHON
Student.objects.filter(
    is_active=False
).delete()

This deletes all matching records.

Be extremely careful with bulk deletes.

56. get_object_or_404()

You learned this earlier, but now it becomes more useful.

Instead of:

PYTHON
student = Student.objects.get(id=id)

you can write:

PYTHON
from django.shortcuts import get_object_or_404

student = get_object_or_404(
    Student,
    id=id
)

If it doesn't exist, Django raises an HTTP 404.

This is especially useful in views.

63. Pagination-Style Slicing

You can use:

PYTHON

to retrieve a slice of the QuerySet.

Important:

QuerySet slicing resembles Python slicing, but not every arbitrary Python slice operation is supported.

64. latest() and earliest()

If you have:

PYTHON

you can use:

PYTHON

PYTHON

65. get() With Primary Key

You can use:

PYTHON
Student.objects.get(pk=1)

instead of:

PYTHON
Student.objects.get(id=1)

pk means primary key.

This is especially useful if your primary key field isn't named id.

66. QuerySet vs Model Instance

This distinction is extremely important.

QuerySet

PYTHON
Student.objects.filter(age=21)

returns a QuerySet.

Model instance

PYTHON
Student.objects.get(id=1)

returns one Student instance.

So:

TEXT
filter() → QuerySet
get()    → Model instance

67. QuerySet vs List

A QuerySet is not simply a normal Python list.

It provides Django-specific functionality:

PYTHON
filter()
exclude()
order_by()
values()
exists()
count()

It also supports lazy evaluation and database-aware query construction.

68. ORM and SQL

For:

PYTHON
Student.objects.filter(
    age__gte=18
)

Django conceptually generates SQL similar to:

SQL
SELECT ...
FROM ...
WHERE age >= 18;

The exact SQL depends on the database backend and Django's query construction.

This is why ORM is called an object-relational mapping layer.

69. Important Security Point

Django ORM generally parameterizes values rather than simply concatenating user input into SQL.

For example:

PYTHON
Student.objects.filter(
    name=user_input
)

is preferable to manually constructing SQL like:

PYTHON
"SELECT ... WHERE name = '" + user_input + "'"

The latter can introduce SQL injection vulnerabilities.

ORM helps protect against SQL injection when used correctly.

70. Common Mistakes

Mistake 1

Using:

PYTHON
Student.objects.get(course="CSE")

when multiple CSE students exist.

This causes:

TEXT
MultipleObjectsReturned

Use:

PYTHON
Student.objects.filter(course="CSE")

instead.

Mistake 2

Using:

PYTHON
Student.objects.get(id=999)

without handling the possibility that it doesn't exist.

Could raise:

TEXT
Student.DoesNotExist

In a view, often use:

PYTHON
get_object_or_404(Student, id=999)

Mistake 3

Forgetting double underscore:

Wrong:

PYTHON
age_gt=18

Correct:

PYTHON
age__gt=18

Mistake 4

Confusing:

PYTHON
filter()

with:

PYTHON
get()

Remember:

TEXT
filter → many/zero → QuerySet
get    → exactly one → object

Mistake 5

Using:

PYTHON
student.delete()

without checking which student you're deleting.

Always be careful with destructive operations.

71. Viva Masterclass

Q1. What is Django ORM?

Django ORM is an Object-Relational Mapping system that allows developers to interact with database records using Python objects and query methods.

Q2. What is objects?

objects is the default model manager used to perform database queries.

Q3. What is a QuerySet?

A QuerySet is a collection-like representation of database query results that supports filtering, ordering, slicing, and other query operations.

Q4. What does all() do?

PYTHON
Student.objects.all()
Returns a QuerySet containing all Student records.

Q5. Difference between filter() and get()?

filter() returns a QuerySet and can return zero or multiple records, while get() expects exactly one record and raises exceptions if zero or multiple records match.

Q6. What happens if get() finds nothing?

It raises the model's DoesNotExist exception.

Q7. What happens if get() finds multiple objects?

It raises MultipleObjectsReturned.

Q8. What does __gt mean?

PYTHON
age__gt=18

means:

TEXT
age > 18

Q9. What does __gte mean?

TEXT
age >= 18

Q10. What does __icontains mean?

Performs a case-insensitive containment lookup.

Q11. What does order_by("-marks") do?

Sorts results by marks in descending order.

Q12. What does exists() do?

Checks whether a query has at least one matching result and returns a Boolean.

Q13. What does count() do?

Returns the number of records represented by the QuerySet.

Q14. What does create() do?

Creates and saves a model instance in the database.

Q15. What is lazy evaluation?

QuerySets are generally lazy, meaning Django delays executing the database query until the results are actually needed.
