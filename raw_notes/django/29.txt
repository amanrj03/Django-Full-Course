# Module 29 — Django Shell & CRUD

Now we're going to **actually work with database records**.

CRUD is one of the most important practical topics in Django:

> **C — Create**
> **R — Read**
> **U — Update**
> **D — Delete**

By the end, you should be able to perform all four operations using Django ORM and explain them in a viva.

---

# 1. What Is CRUD?

CRUD represents the four basic database operations:

| CRUD | Meaning | Django           |
| ---- | ------- | ---------------- |
| C    | Create  | Create a record  |
| R    | Read    | Retrieve records |
| U    | Update  | Modify records   |
| D    | Delete  | Remove records   |

Example:

```text
Student
    ↓
Create → Add student
Read   → View student
Update → Change student details
Delete → Remove student
```

# 5. CREATE — Method 1

Create an object:

```python
student = Student(
    name="Aman",
    age=21,
    email="aman@gmail.com",
    course="CSE",
    marks=85
)
```

At this point:

> The object exists in Python memory, but it has not necessarily been saved to the database yet.

Now:

```python
student.save()
```

This saves it.

---

# 6. CREATE — Method 2: `objects.create()`

A shorter approach:

```python
student = Student.objects.create(
    name="Aman",
    age=21,
    email="aman@gmail.com",
    course="CSE",
    marks=85
)
```

This:

1. Creates the object
2. Saves it to the database

So:

```text
Student(...)
     ↓
Python object
     ↓
save()
     ↓
Database
```

whereas:

```text
Student.objects.create(...)
     ↓
Create + Save
```

---

# 7. `create()` vs `save()`

### Method 1

```python
student = Student(
    name="Aman"
)

student.save()
```

### Method 2

```python
student = Student.objects.create(
    name="Aman"
)
```

The second is shorter.

### Viva answer:

> `objects.create()` creates and saves the model instance immediately, while instantiating a model with `Model(...)` only creates the Python object until `save()` is called.

# 9. `__str__()` — Very Useful

By default, Django may display:

```text

```

You can make it more readable.

In `models.py`:

```python
class Student(models.Model):

    name = models.CharField(max_length=100)
    age = models.IntegerField()
    email = models.EmailField()

    def __str__(self):
        return self.name
```


might display:

```text

```

This is especially useful in:

* Debugging

# 12. `get()` Requires Exactly One Result

Remember:

```python
Student.objects.get(id=1)
```

expects exactly one object.

If none exists:

```text
Student.DoesNotExist
```

If multiple records match:

```text
MultipleObjectsReturned
```

For a unique primary key lookup, multiple matches aren't possible, but other conditions can produce multiple results.

# 24. `save()` vs `update()`

This is an important viva question.

### `save()`

```python
student.marks = 95
student.save()
```

Works with a model instance.

### `update()`

```python
Student.objects.filter(id=1).update(
    marks=95
)
```

Works on a QuerySet and performs a direct bulk database update.

Remember an important consequence:

> `QuerySet.update()` does not call each model instance's `save()` method.

So if your model has custom `save()` behavior, don't assume `update()` will execute it.

# 31. `get_or_create()`

Django provides a useful method:

```python
Student.objects.get_or_create(...)
```

Suppose:

```python
student, created = Student.objects.get_or_create(
    email="aman@gmail.com",
    defaults={
        "name": "Aman",
        "age": 21,
        "course": "CSE"
    }
)
```

It attempts to:

1. Find an existing matching object
2. If it doesn't exist, create one

It returns:

```text
(object, created)
```

where:

```text
created = True
```

if a new object was created.

Otherwise:

```text
created = False
```

if an existing object was found.

---

# 32. Why `get_or_create()` Is Useful

Suppose you want to make sure a record exists without writing:

```python
try:
    ...
except:
    ...
```

yourself.

You can use:

```python
get_or_create()
```

This is especially useful for initialization/setup-type operations.

---

# 33. `update_or_create()`

Another useful method:

```python
Student.objects.update_or_create(...)
```

It:

* Updates an existing matching object
* Or creates it if it doesn't exist

Example:

```python
student, created = Student.objects.update_or_create(
    email="aman@gmail.com",
    defaults={
        "name": "Aman",
        "age": 22,
        "marks": 95
    }
)
```

The lookup fields are used to find the object, while `defaults` contains values to update/create.

---

# 34. `get_or_create()` vs `update_or_create()`

| Method               | Behavior                  |
| -------------------- | ------------------------- |
| `get_or_create()`    | Get existing or create    |
| `update_or_create()` | Update existing or create |

# 39. Important Difference: `delete()` vs `update()`

Both can operate on QuerySets:

```python
Student.objects.filter(...).update(...)
```

and:

```python
Student.objects.filter(...).delete()
```

But they perform completely different actions:

```text
update() → changes records
delete() → removes records
```

# 40. Using `get_object_or_404()` in Views

Shell:

```python
student = Student.objects.get(id=1)
```

View:

```python
from django.shortcuts import get_object_or_404

student = get_object_or_404(
    Student,
    id=1
)
```

Why?

Because a web request should normally produce an HTTP 404 response rather than an unhandled `DoesNotExist` exception.

# 41. CRUD in a Django View

Let's make a simple read view:

```python
from django.shortcuts import render
from .models import Student


def student_list(request):

    students = Student.objects.all()

    return render(
        request,
        "students.html",
        {"students": students}
    )
```

Template:

```html
{% for student in students %}

    <p>
        {{ student.name }}
        - {{ student.age }}
        - {{ student.marks }}
    </p>

{% endfor %}
```

This is:

```text
Database
   ↓
ORM
   ↓
View
   ↓
Context
   ↓
Template
```

# 42. Create Through a View

Example:

```python
from django.shortcuts import redirect, render
from .forms import StudentForm
from .models import Student


def create_student(request):

    if request.method == "POST":

        form = StudentForm(request.POST)

        if form.is_valid():

            Student.objects.create(
                name=form.cleaned_data["name"],
                age=form.cleaned_data["age"],
                email=form.cleaned_data["email"],
                course=form.cleaned_data["course"]
            )

            return redirect("student_list")

    else:
        form = StudentForm()

    return render(
        request,
        "create_student.html",
        {"form": form}
    )
```

Notice how many previous modules are now connecting:

```text
Form
 ↓
Validation
 ↓
ORM
 ↓
Create
 ↓
Redirect
```

---

# 43. Update Through a View

Conceptually:

```python
from django.shortcuts import get_object_or_404, redirect, render


def update_student(request, id):

    student = get_object_or_404(
        Student,
        id=id
    )

    if request.method == "POST":

        form = StudentForm(request.POST)

        if form.is_valid():

            student.name = form.cleaned_data["name"]
            student.age = form.cleaned_data["age"]
            student.email = form.cleaned_data["email"]
            student.course = form.cleaned_data["course"]

            student.save()

            return redirect("student_list")

    else:
        form = StudentForm(
            initial={
                "name": student.name,
                "age": student.age,
                "email": student.email,
                "course": student.course,
            }
        )

    return render(
        request,
        "update_student.html",
        {"form": form}
    )
```

Don't worry if this seems long. We're going to build complete CRUD projects later.

# 44. Delete Through a View

A safer basic pattern is to use POST for destructive operations:

```python
from django.shortcuts import get_object_or_404, redirect


def delete_student(request, id):

    student = get_object_or_404(
        Student,
        id=id
    )

    if request.method == "POST":

        student.delete()

        return redirect("student_list")
```

Template:

```html
<form method="POST">
    {% csrf_token %}

    <button type="submit">
        Delete
    </button>
</form>
```

Notice:

```text
POST
+
CSRF
+
delete()
+
redirect()
```

We've now combined Modules 23, 24, 25, 27, 28, and 29.
