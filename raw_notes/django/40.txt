---

# 11. What Is `ModelForm`?

A `ModelForm` creates a form based on a Django model.

Instead of manually writing:

```python
name = forms.CharField(...)
email = forms.EmailField(...)
age = forms.IntegerField(...)
```

Django derives the form fields from:

```python
class Student(models.Model):
```

---

# 12. `Meta.model`

```python
class Meta:
    model = Student
```

This tells Django:

> This form is associated with the Student model.

---

# 13. `Meta.fields`

```python
fields = [
    "name",
    "email",
    "course",
    "age",
    "marks",
]
```

This determines which model fields appear in the form.

You can also use:

```python
fields = "__all__"
```

but explicitly listing fields is often safer and clearer.

# 22. Step 9 — Create Student

Now implement **Create**.

In `views.py`:

```python
from django.shortcuts import (
    render,
    redirect
)

from .forms import StudentForm


def student_create(request):

    if request.method == "POST":

        form = StudentForm(
            request.POST
        )

        if form.is_valid():

            form.save()

            return redirect(
                "student_list"
            )

    else:

        form = StudentForm()

    return render(
        request,
        "students/student_form.html",
        {
            "form": form
        }
    )
```

---

# 23. Understand Create Flow

Initial request:

```text
GET /students/create/
```

creates an empty form:

```python
form = StudentForm()
```

Then:

```text
POST /students/create/
```

creates a bound form:

```python
form = StudentForm(request.POST)
```

Then:

```python
form.is_valid()
```

checks validation.

If valid:

```python
form.save()
```

creates the Student database record.

Then:

```python
redirect("student_list")
```

returns to the list.

---

# 24. Why `form.save()`?

Because this is a `ModelForm`.

It knows:

```text
Form fields
     ↓
Model fields
     ↓
Create model object
     ↓
Save to database
```

So:

```python
form.save()
```

is effectively handling the model creation for us.

# 29. Step 12 — Update Student

Now implement **Update**.

In `views.py`:

```python
from django.shortcuts import (
    get_object_or_404
)


def student_update(request, id):

    student = get_object_or_404(
        Student,
        id=id
    )

    if request.method == "POST":

        form = StudentForm(
            request.POST,
            instance=student
        )

        if form.is_valid():

            form.save()

            return redirect(
                "student_list"
            )

    else:

        form = StudentForm(
            instance=student
        )

    return render(
        request,
        "students/student_form.html",
        {
            "form": form
        }
    )
```

---

# 30. The Important Part of Update

Look carefully:

```python
form = StudentForm(
    request.POST,
    instance=student
)
```

The:

```python
instance=student
```

is what tells the ModelForm:

> "Update this existing student rather than creating a new student."

---

# 31. Update Without `instance`

If you write:

```python
form = StudentForm(request.POST)
```

then:

```python
form.save()
```

normally creates a **new object**.

But:

```python
form = StudentForm(
    request.POST,
    instance=student
)
```

means:

```text
Existing student
       ↓
Update it
```

This is a very important coding question.

---

The GET request:

```text

```

It displays:

```text

```

Then the user submits POST.

```text

```

The deletion happens.

This is much safer than deleting data immediately on GET.

# 45. Add Validation

In `forms.py`:

```python
from django import forms
from .models import Student


class StudentForm(forms.ModelForm):

    class Meta:
        model = Student

        fields = [
            "name",
            "email",
            "course",
            "age",
            "marks",
        ]

    def clean_marks(self):

        marks = self.cleaned_data["marks"]

        if marks < 0 or marks > 100:

            raise forms.ValidationError(
                "Marks must be between 0 and 100."
            )

        return marks
```

---

# 46. Understand `clean_marks()`

This method:

```python
clean_marks()
```

is called for the `marks` field.

We retrieve:

```python
marks = self.cleaned_data["marks"]
```

Then:

```python
if marks < 0 or marks > 100:
```

checks the business rule.

If invalid:

```python
raise forms.ValidationError(...)
```

If valid:

```python
return marks
```

---

# 48. Full Form

```python
from django import forms
from .models import Student


class StudentForm(forms.ModelForm):

    class Meta:

        model = Student

        fields = [
            "name",
            "email",
            "course",
            "age",
            "marks",
        ]


    def clean_marks(self):

        marks = self.cleaned_data["marks"]

        if marks < 0 or marks > 100:

            raise forms.ValidationError(
                "Marks must be between 0 and 100."
            )

        return marks


    def clean_age(self):

        age = self.cleaned_data["age"]

        if age < 5 or age > 100:

            raise forms.ValidationError(
                "Enter a valid age."
            )

        return age
```

# 55. Complete Delete Security

Our delete view could become:

```python
@login_required
@permission_required(
    "students.delete_student",
    raise_exception=True
)
def student_delete(request, id):

    student = get_object_or_404(
        Student,
        id=id
    )

    if request.method == "POST":

        student.delete()

        return redirect(
            "student_list"
        )

    return render(
        request,
        "students/student_confirm_delete.html",
        {
            "student": student
        }
    )
```

```text

       ↓

       ↓

       ↓
POST?
       ↓

       ↓
Delete
       ↓

```

That's a strong production-style pattern.

# 56. Important: GET Shouldn't Delete

Never do:

```python
def delete_student(request, id):

    student = get_object_or_404(
        Student,
        id=id
    )

    student.delete()

    return redirect("student_list")
```

if that deletion is triggered by a GET request.

Why?

Because GET should generally be safe/read-only.

A crawler, prefetcher, link checker, or accidental browser request shouldn't cause destructive state changes.

Prefer:

```text
GET
 ↓
Confirmation page

POST
 ↓
Delete
```

# 62. Why Doesn't Create Use GET?

A GET request should generally be safe and shouldn't change server state.

So:

```text
GET /students/create/
```

only displays the form.

Then:

```text
POST /students/create/
```

actually creates the student.

# 66. Common Viva Questions

### Q1. What is CRUD?

> Create, Read, Update and Delete.

### Q2. What is a ModelForm?

> A Django form class that is associated with a model and can generate form fields and save model instances.

### Q3. Why use `instance` during update?

> It tells the ModelForm which existing model instance should be updated instead of creating a new record.

### Q4. Why use `get_object_or_404()`?

> It retrieves an object or raises an HTTP 404 response if the object doesn't exist.

### Q5. Why use `redirect()` after saving?

> To follow the POST-Redirect-GET pattern and prevent duplicate form submissions on refresh.

### Q6. Why use CSRF token?

> To protect POST requests against CSRF attacks.

### Q7. Why shouldn't deletion happen through GET?

> GET should generally be safe and read-only; destructive operations should use an appropriate state-changing method such as POST.

### Q8. Why use `ModelForm` instead of manually creating every form field?

> It reduces repetitive code and connects form validation and saving directly to the model.

### Q9. Where does `form.save()` save data?

> It saves the model instance to the configured database.

### Q10. How does update differ from create?

```python
# Create
StudentForm(request.POST)

# Update
StudentForm(
    request.POST,
    instance=student
)
```
