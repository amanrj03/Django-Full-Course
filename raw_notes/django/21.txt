# Module 21 — Django Forms

Now we move from **manual HTML forms** to Django's built-in **Forms framework**.

This is a very important module because Django Forms combine:

```text
HTML generation
+
Input handling
+
Validation
+
Error handling
+
Cleaned data
```

into a structured Python class.

---

# 1. Why Django Forms?

Previously, we created a form manually:

```html id="9m0q83"
<form method="POST">

    {% csrf_token %}

    <input type="text" name="name">

    <input type="email" name="email">

    <button type="submit">
        Submit
    </button>

</form>
```

Then manually processed:

```python id="4wq1fs"
name = request.POST.get("name")
email = request.POST.get("email")
```

For a small form, that's okay.

But imagine 20 fields.

You would need to manually handle:

* HTML fields
* validation
* required fields
* error messages
* type conversion
* redisplaying values
* security
* invalid input

Django Forms simplify this.

---

# 2. What Is a Django Form?

A Django Form is a **Python class that describes and processes form fields**.

Example:

```python id="l8c9v7"
from django import forms

class StudentForm(forms.Form):

    name = forms.CharField()

    age = forms.IntegerField()

    email = forms.EmailField()
```

This class describes a form containing:

```text id="qg7a3w"
name
age
email
```

---

# 3. Where Do We Put Forms?

Django apps commonly have:

```text id="x8b2k1z"
students/
├── views.py
├── models.py
├── forms.py
├── urls.py
└── ...
```

Django doesn't necessarily create `forms.py` automatically with `startapp`.

You can create it yourself.

# 10. Rendering the Form

Now let's display it in a template.

View:

```python id="c6e9so"
from django.shortcuts import render
from .forms import StudentForm


def student_form(request):

    form = StudentForm()

    return render(
        request,
        "student_form.html",
        {"form": form}
    )
```

Template:

```html id="y1p4wc"
<form method="POST">

    {% csrf_token %}

    {{ form }}

    <button type="submit">
        Submit
    </button>

</form>
```

Django generates HTML for the form fields.

# 11. What Does `{{ form }}` Do?

When you write:

```html id="s9t1kb"
{{ form }}
```

Django renders the form's fields as HTML.

Conceptually, it produces fields corresponding to:

```text id="djw3pd"
Name
Age
Email
```

You don't have to manually create every `<input>`.

---

# 12. `{{ form.as_p }}`

A common rendering method is:


It renders each field wrapped in a paragraph structure.

Example conceptually:

```html id="r1s0q4"

    <input ...>
</p>

<p>
    <label>Age:</label>
    <input ...>
</p>
```

---

# 13. `{{ form.as_table }}`

You can write:

```html id="f0p5h1"

```

This renders the form as table rows.

Typically you'd place it inside:

```html id="4s2qla"

</table>
```

---

# 14. `{{ form.as_ul }}`

Another rendering option:


It renders the fields as list items.

Typically:

```html id="8t5mna"

</ul>
```

---

# 15. Comparison

| Syntax                | Typical output structure |
| --------------------- | ------------------------ |
| `{{ form }}`          | Default form rendering   |
| `{{ form.as_p }}`     | Paragraphs               |
| `{{ form.as_table }}` | Table rows               |
| `{{ form.as_ul }}`    | List items               |

For exams, know all four.

# 16. Important: Rendering Is Not Validation

This is very important.

Creating:

```python id="gq3q7k"
form = StudentForm()
```

only creates a form instance.

It doesn't mean submitted data is valid.

For submitted data:

```python id="b5zj8u"
form = StudentForm(request.POST)
```

then:

```python id="4p3f8k"
form.is_valid()
```

performs validation.

---

# 17. Unbound vs Bound Form

This terminology is important.

### Unbound form

```python id="v0y6nq"
form = StudentForm()
```

It has no submitted data.

Used when initially displaying the form.

### Bound form

```python id="f6nq8w"
form = StudentForm(request.POST)
```

It contains submitted data and can be validated.

# 19. `is_valid()`

The most important Django Forms method:

```python id="2d6f5m"
form.is_valid()
```

It validates the submitted data.

Example:

```python id="3a7x8q"
if form.is_valid():
    print("Valid")
else:
    print("Invalid")
```

It returns:

```text id="2vl9po"
True
```

or:

```text id="y5w3cf"
False
```

# 20. Complete GET + POST Form View

This is a pattern you should memorize.

```python id="x8n4fk"
from django.shortcuts import render
from .forms import StudentForm


def student_form(request):

    if request.method == "POST":

        form = StudentForm(request.POST)

        if form.is_valid():

            print("Form is valid")

    else:

        form = StudentForm()

    return render(
        request,
        "student_form.html",
        {"form": form}
    )
```

Let's understand it carefully.

---

# 21. First Visit — GET

When the user opens:

```text id="4p7v2z"
/student-form/
```

the browser sends:

```text id="j4m0nd"
GET
```

So:

```python id="7b8k3a"

```

is false.

Django executes:

```python id="9j4yqf"

```

An empty/unbound form is displayed.

---

# 22. Submission — POST

User fills:

```text id="w3g4dy"

Age: 21
Email: aman@example.com
```

and clicks Submit.

Browser sends:

```text id="z8w1n5"
POST
```

Django executes:

```python id="4j7z3v"
form = StudentForm(request.POST)
```

Now the form is bound to submitted data.

---

# 23. Validation

Then:

```python id="k9q3sd"
if form.is_valid():
```

Django validates:

```text id="j2q6mb"
name
age
email
```

If everything is valid:

```text id="h7m1as"
True
```

Otherwise:

```text id="p4j8zc"
False
```

# 24. `cleaned_data`

If the form is valid:

```python id="y3x6qk"
form.cleaned_data
```

contains the cleaned/validated values.

Example:

```python id="c8k0nw"
if form.is_valid():

    name = form.cleaned_data["name"]
    age = form.cleaned_data["age"]
    email = form.cleaned_data["email"]
```

This is preferred over directly using:

```python id="8m0k0v"
request.POST.get("name")
```

after form validation.

---

# 25. Why `cleaned_data`?

Suppose:

```python id="9v3qkf"
age = forms.IntegerField()
```

The browser sends form data as strings.

After validation, Django can convert the valid value into the appropriate Python type.

So:

```python id="3u7m2a"
form.cleaned_data["age"]
```

can be an integer.

This is one of the major benefits of Django Forms.

---

# 26. Example

Form:

```python id="j4a9m3"
class StudentForm(forms.Form):

    name = forms.CharField()

    age = forms.IntegerField()
```

Submitted:

```text id="h7o3sa"
name = "Aman"
age = "21"
```

After:

```python id="v5r1mq"
form.is_valid()
```

you can access:

```python id="2k3c7n"
form.cleaned_data["name"]
```

and:

```python id="y0z6sw"
form.cleaned_data["age"]
```

The second value can be an integer rather than the original raw string.

# 45. Complete View

```python id="r3y8tk"
from django.shortcuts import render
from .forms import StudentForm


def student_form(request):

    if request.method == "POST":

        form = StudentForm(request.POST)

        if form.is_valid():

            name = form.cleaned_data["name"]
            age = form.cleaned_data["age"]
            email = form.cleaned_data["email"]
            course = form.cleaned_data["course"]
            dob = form.cleaned_data["dob"]

            print(name)
            print(age)
            print(email)
            print(course)
            print(dob)

    else:

        form = StudentForm()

    return render(
        request,
        "student_form.html",
        {"form": form}
    )
```

# 46. Complete Flow

Memorize this:

```text id="k6d8ra"
                User opens page
                      ↓
                     GET
                      ↓
             StudentForm()
                      ↓
               Empty form
                      ↓
                  User fills
                      ↓
                    POST
                      ↓
          StudentForm(request.POST)
                      ↓
                 is_valid()
                /          \
              Yes           No
               ↓             ↓
        cleaned_data      form.errors
               ↓             ↓
          Process data    Show errors
```

This is the core Django Forms workflow.

# 47. Why Use `forms.Form` Instead of Manual HTML?

### Manual approach:

```text id="4x2z9m"
HTML fields
    ↓
request.POST
    ↓
manual validation
    ↓
manual conversion
    ↓
manual errors
```

### Django Form:

```text id="m6y9q1"
Form class
    ↓
request.POST
    ↓
is_valid()
    ↓
cleaned_data
    ↓
errors
```

Much cleaner.


# 49. `Form` vs `ModelForm`

You will eventually encounter:

```python id="v8w2jp"
forms.Form
```

and:

```python id="x6z0ka"
forms.ModelForm
```

### `Form`

You manually define form fields.

```python id="2q4m7k"
class StudentForm(forms.Form):
    name = forms.CharField()
```

### `ModelForm`

Django can generate form fields based on a model.

```python id="h5t1sx"
class StudentForm(forms.ModelForm):
    class Meta:
        model = Student
        fields = "__all__"
```

We'll study this later.

# 50. Common Mistake — Forgetting `request.POST`

Wrong:

```python id="j4y7z2"
form = StudentForm()
```

when processing submitted data.

Correct:

```python id="c3n8w1"
form = StudentForm(request.POST)
```

Otherwise Django doesn't have the submitted data to validate.

---

# 51. Common Mistake — Calling `cleaned_data` Before Validation

Wrong:

```python id="f2q7k9"
form = StudentForm(request.POST)

name = form.cleaned_data["name"]
```

Correct:

```python id="w6n3p4"
form = StudentForm(request.POST)

if form.is_valid():

    name = form.cleaned_data["name"]
```

`cleaned_data` should be used after successful validation.

# 55. Viva — Bound vs Unbound

### Teacher:

> What is an unbound form?

Answer:

> A form created without submitted data, such as `StudentForm()`, generally used to initially display an empty form.

### Teacher:

> What is a bound form?

Answer:

> A form created with submitted data, such as `StudentForm(request.POST)`, which can then be validated.

---

# 56. Viva — `is_valid()`

### Teacher:

> What does `is_valid()` do?

Answer:

> It runs the form's validation process and returns `True` if the submitted data is valid and `False` otherwise.

---

# 57. Viva — `cleaned_data`

### Teacher:

> What is `cleaned_data`?

Answer:

> `cleaned_data` is a dictionary containing the cleaned and validated form values after successful validation.

---

# 58. Viva — Why Not `request.POST`?

### Teacher:

> Why use `cleaned_data` instead of directly processing `request.POST` after validation?

Answer:

> `cleaned_data` contains values after Django has performed the form field's validation and appropriate conversion, making it safer and easier to work with.

---

# 59. Viva — `forms.Form` vs `ModelForm`

Answer:

> `forms.Form` requires fields to be explicitly defined, while `forms.ModelForm` can generate form fields from a Django model and is commonly used when a form corresponds to database data.
