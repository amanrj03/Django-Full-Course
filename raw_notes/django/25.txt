# 1. Why Do We Need a Database?

So far, we've worked with data like:

```python
students = [
    {"name": "Aman", "age": 21},
    {"name": "Rahul", "age": 22},
]
```

But where is this data stored?

It's only in Python memory.

If the Django server stops:

```text
Server stops
    ↓
Python memory cleared
    ↓
Data lost
```

We need **persistent storage**.

That's where a database comes in.

```text
Django application
       ↓
   Database
       ↓
Persistent data
```

---

# 2. What Is a Database?

A **database** is an organized collection of data that can be stored, retrieved, updated, and deleted efficiently.

For example, a college application might store:

```text
Students
Courses
Teachers
Departments
Marks
Attendance
```

---

# 3. What Is a Database Table?

A relational database stores data in **tables**.

Imagine a `Student` table:

| id | name  | age | email                                     |
| -: | ----- | --: | ----------------------------------------- |
|  1 | Aman  |  21 | [aman@gmail.com](mailto:aman@gmail.com)   |
|  2 | Rahul |  22 | [rahul@gmail.com](mailto:rahul@gmail.com) |
|  3 | Priya |  20 | [priya@gmail.com](mailto:priya@gmail.com) |

The table consists of:

* **Columns** → properties/fields
* **Rows** → individual records

---

# 4. Column

A column represents a particular type of information.

For example:

```text
id
name
age
email
```

In Django, these correspond to **model fields**.

---

# 5. Row

A row represents one record.

For example:

```text
1 | Aman | 21 | aman@gmail.com
```

is one student record.

In Django, this eventually corresponds to a **model instance**.

---

# 6. Primary Key

A **primary key** uniquely identifies each row in a table.

Example:

| id | name  | age |
| -: | ----- | --: |
|  1 | Aman  |  21 |
|  2 | Rahul |  22 |
|  3 | Priya |  20 |

Here:

```text
id
```

is the primary key.

It should uniquely identify a record.

---

# 7. Why Is `id` Important?

Suppose we want to retrieve Aman.

We can identify him using:

```text
id = 1
```

For example:

```text
/student/1/
```

This connects to the URL parameter concepts we learned earlier.

---

# 8. What Database Does Django Use by Default?

A new Django project normally uses:

# SQLite

In `settings.py`, you'll see something similar to:

```python
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.sqlite3",
        "NAME": BASE_DIR / "db.sqlite3",
    }
}
```

SQLite is lightweight and stores the database in a file.

The file is usually:

```text
db.sqlite3
```

---

# 9. Other Databases Django Supports

Django can work with databases such as:

```text
SQLite
PostgreSQL
MySQL
MariaDB
Oracle
```

For learning and small development projects, SQLite is very convenient.

For larger production systems, PostgreSQL is a common choice.

# 10. What Is a Django Model?

Now the most important definition:

> **A Django model is a Python class that represents data and describes the structure of a database table.**

For example:

```python
class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField()
    email = models.EmailField()
```

This Python class describes a `Student` table.

Conceptually:

```text
Python Model
      ↓
Database Table
```

---

# 11. Where Do We Define Models?

Inside:

```text
students/models.py
```

A newly created Django app already contains:

```python
from django.db import models
```

We define our model there.

# 12. Creating Your First Model

Suppose we want to store students.

Open:

```text
students/models.py
```

Write:

```python
from django.db import models


class Student(models.Model):

    name = models.CharField(max_length=100)

    age = models.IntegerField()

    email = models.EmailField()
```

That's our first Django model.

### Age

# 14. Model → Table

Our model:

```python
class Student(models.Model):

    name = models.CharField(max_length=100)
    age = models.IntegerField()
    email = models.EmailField()
```

conceptually becomes a table similar to:

| id | name  | age | email                                     |
| -: | ----- | --: | ----------------------------------------- |
|  1 | Aman  |  21 | [aman@gmail.com](mailto:aman@gmail.com)   |
|  2 | Rahul |  22 | [rahul@gmail.com](mailto:rahul@gmail.com) |

Notice something:

We didn't define:

```python
id
```

yet Django normally creates an automatic primary-key field if you don't explicitly define one.

---

# 15. Automatic Primary Key

When you define:

```python
class Student(models.Model):
    name = models.CharField(max_length=100)
```

Django automatically adds a primary key unless you've configured a different primary key.

In modern Django versions, the exact automatically generated field type can depend on your configuration/default settings, but conceptually you should remember:

> **Django automatically provides a primary key when you don't define one.**

You can access it using:

```python
student.pk
```

or commonly:

```python
student.id
```

when the automatically created field is named `id`.

---

# 16. `pk` vs `id`

Suppose:

```python
student = Student.objects.get(...)
```

You can access:

```python
student.id
```

And Django also provides:

```python
student.pk
```

`pk` means:

> **Primary Key**

The advantage of `pk` is that it works regardless of what the actual primary-key field is called.

# 27. Model vs Database Table

This distinction is very important.

### Model

Python class:

```python
class Student(models.Model):
    name = models.CharField(max_length=100)
```

### Table

Database representation:

```text
Student table
--------------------
id
name
age
email
```

So:

```text
Django Model
     ↓
Database Table
```

---

# 28. Model Object vs Database Row

Similarly:

### Model instance

```python
student = Student(
    name="Aman",
    age=21,
    email="aman@gmail.com"
)
```

### Database row

Eventually:

| id | name | age | email                                   |
| -: | ---- | --: | --------------------------------------- |
|  1 | Aman |  21 | [aman@gmail.com](mailto:aman@gmail.com) |

Therefore:

```text
Model class     → Table
Model instance  → Row
Model field     → Column
```

This is an **excellent viva answer**.

# 29. What Is ORM?

ORM stands for:

# Object-Relational Mapping

Django provides an ORM that allows us to interact with the database using Python objects and methods instead of writing SQL for every operation.

For example, instead of SQL:

```sql
SELECT * FROM students;
```

you can use Django ORM:

```python
Student.objects.all()
```

---

# 30. Why Is ORM Useful?

Without ORM, you might write SQL:

```sql
SELECT * FROM students
WHERE age > 18;
```

With Django ORM:

```python
Student.objects.filter(age__gt=18)
```

The ORM translates the Python-style operation into database-specific SQL.

Conceptually:

```text
Python code
    ↓
Django ORM
    ↓
SQL
    ↓
Database
```

We'll study ORM deeply in **Module 28 onward**.

---

# 31. Do We Need to Write SQL?

Not necessarily.

For many common operations, Django ORM allows you to work with:

```python
Student.objects.all()
Student.objects.get(...)
Student.objects.filter(...)
Student.objects.create(...)
```

rather than manually writing SQL.

However, understanding basic SQL is still useful.

---

# 32. Creating a Model Does NOT Immediately Create the Table

This is extremely important.

Suppose you write:

```python
class Student(models.Model):
    name = models.CharField(max_length=100)
```

The database table isn't simply created just because you saved `models.py`.

You need Django's **migration system**.

---

# 33. First: Register the App

Before using migrations, make sure the app is in:

```python
INSTALLED_APPS
```

For example:

```python
INSTALLED_APPS = [
    ...
    "students",
]
```

Without registering the app, Django won't properly include its models in the project.

---

# 34. `makemigrations`

Run:

```bash
python manage.py makemigrations
```

Django detects model changes and creates migration files describing those changes.

Conceptually:

```text
models.py
   ↓
makemigrations
   ↓
migration file
```

For example:

```text
students/
└── migrations/
    ├── __init__.py
    └── 0001_initial.py
```

---

# 35. `migrate`

Then run:

```bash
python manage.py migrate
```

This applies migrations to the database.

Conceptually:

```text
Migration files
      ↓
python manage.py migrate
      ↓
Database tables
```

---

# 36. `makemigrations` vs `migrate`

This is a **must-know viva question**.

| Command          | Purpose                                    |
| ---------------- | ------------------------------------------ |
| `makemigrations` | Creates migration files from model changes |
| `migrate`        | Applies migrations to the database         |

Easy way to remember:

```text
makemigrations
→ Make instructions

migrate
→ Apply instructions
```

---

# 37. Complete Process

Suppose we create:

```python
class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField()
```

Then:

### Step 1

Save `models.py`.

### Step 2

Run:

```bash
python manage.py makemigrations
```

### Step 3

Run:

```bash
python manage.py migrate
```

Now Django creates/updates the database schema.

---

# 38. What Is a Migration?

A migration is a **versioned set of database schema changes** generated from changes to Django models.

Suppose initially:

```python
class Student(models.Model):
    name = models.CharField(max_length=100)
```

Later you add:

```python
age = models.IntegerField()
```

Run:

```bash
python manage.py makemigrations
```

Django creates another migration describing:

```text
Add age field to Student
```

Then:

```bash
python manage.py migrate
```

applies it.

We'll study migrations deeply in Module 27.

# 41. Example: Student List

Suppose database contains:

| id | name  | age |
| -: | ----- | --: |
|  1 | Aman  |  21 |
|  2 | Rahul |  22 |
|  3 | Priya |  20 |

The view can retrieve them:

```python
def students(request):

    students = Student.objects.all()

    return render(
        request,
        "students.html",
        {"students": students}
    )
```

The template:

```html
<h1>Students</h1>

{% for student in students %}

    <p>
        {{ student.name }} - {{ student.age }}
    </p>

{% endfor %}
```

The final page might show:

```text
Students

Aman - 21
Rahul - 22
Priya - 20
```

Notice how our previous knowledge of **dynamic templates** now connects with models.

# 45. `objects`

You will frequently see:

```python
Student.objects
```

This is Django's model manager, commonly used to perform database queries.

For example:

```python
Student.objects.all()
```

gets all students.

```python
Student.objects.filter(age=21)
```

gets students whose age is 21.

```python
Student.objects.get(id=1)
```

gets one specific object if exactly one matching object exists.

We'll cover all of these in the ORM modules.
