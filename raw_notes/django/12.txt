# Module 12 — Introduction to Django Templates

Now we start **Unit III: Templates, Debugging and Testing**.

Until now, our views have mostly returned:

```python
return HttpResponse("Hello World")
```

That works for simple responses, but imagine building a real website with:

* headings
* buttons
* navigation bars
* tables
* forms
* images
* CSS
* dynamic data

Putting all of that HTML inside Python would become a mess.

That's exactly why **Django Templates** exist.

---

# 1. What Is a Template?

A Django template is usually an **HTML file** containing the structure of a webpage and special Django Template Language (DTL) syntax for dynamic content.

For example:

```html
<h1>Welcome to my website</h1>
<p>Hello {{ name }}</p>
```

The HTML defines the page structure, while:

```text
{{ name }}
```

allows Django to insert dynamic data.

---

# 2. Why Do We Need Templates?

Without templates:

```python
def home(request):
    return HttpResponse(
        "<html>"
        "<body>"
        "<h1>Hello Aman</h1>"
        "<p>Welcome</p>"
        "</body>"
        "</html>"
    )
```

This becomes difficult to maintain.

With templates:

### Python:

```python
def home(request):
    return render(request, 'home.html')
```

### HTML:

```html
<h1>Hello Aman</h1>
<p>Welcome</p>
```

Much cleaner.

---

# 3. MVT Connection

Remember Django's MVT architecture:

```text
Model
  ↓
Data

View
  ↓
Logic

Template
  ↓
Presentation
```

So:

> **Template is primarily responsible for presentation/UI.**

The view decides what data should be sent to the template.

The template decides how that data should be displayed.

---

# 4. Basic Template Flow

The flow becomes:

```text
Browser
   ↓
URL
   ↓
View
   ↓
Template
   ↓
HTML Response
   ↓
Browser
```

For example:

```text
/students/
     ↓
students.urls
     ↓
views.home()
     ↓
home.html
     ↓
Browser
```

---

# 5. Creating a Template

Let's assume our project looks like:

```text
College/
│
├── manage.py
│
├── College/
│   ├── settings.py
│   └── urls.py
│
└── students/
    ├── views.py
    ├── urls.py
    └── ...
```

There are multiple ways to organize templates.

A common beginner-friendly approach is to create:

```text
templates/
```

inside the app:

```text
students/
├── templates/
│   └── students/
│       └── home.html
├── views.py
└── urls.py
```

The extra `students` directory helps avoid template-name collisions between apps.

---

# 6. Create `home.html`

Create:

```text
students/templates/students/home.html
```

Put:

```html
<!DOCTYPE html>
<html>
<head>
    <title>Students</title>
</head>
<body>

    <h1>Welcome to Students App</h1>
    <p>This is my first Django template.</p>

</body>
</html>
```

---

# 7. How Does Django Find This Template?

Django's template system needs to know where templates are located.

If you're using the common app-template structure:

```text
students/templates/students/home.html
```

make sure your app is included in:

```python
INSTALLED_APPS
```

in `settings.py`.

For example:

```python
INSTALLED_APPS = [
    ...
    'students',
]
```

Django can then discover templates inside installed apps when `APP_DIRS` is enabled.

---

# 8. `APP_DIRS`

Look at the default template configuration in `settings.py`:

```python
TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [],
        'APP_DIRS': True,
        ...
    },
]
```

The important part for our app template structure is:

```python
APP_DIRS = True
```

This tells Django's template engine to look for templates inside installed apps.

---

# 9. Rendering a Template

Now go to:

```text
students/views.py
```

Import:

```python
from django.shortcuts import render
```

Then:

```python
def home(request):
    return render(request, 'students/home.html')
```

That's it.

---

# 10. What Is `render()`?

The `render()` shortcut combines several operations for you.

Conceptually:

```text
render()
   ↓
Find template
   ↓
Process template
   ↓
Generate HTML
   ↓
Return HttpResponse
```

So:

```python
return render(
    request,
    'students/home.html'
)
```

means:

> Render this template and return the generated HTML as an HTTP response.

---

# 11. `render()` Syntax

The basic syntax is:

```python
render(request, template_name)
```

For example:

```python
return render(
    request,
    'students/home.html'
)
```

Later we'll use:

```python
render(
    request,
    'students/home.html',
    context
)
```

to send dynamic data.

---

# 12. Complete Example

### `students/views.py`

```python
from django.shortcuts import render

def home(request):
    return render(
        request,
        'students/home.html'
    )
```

### `students/templates/students/home.html`

```html
<!DOCTYPE html>
<html>
<head>
    <title>Students</title>
</head>
<body>

    <h1>Welcome to Students App</h1>

</body>
</html>
```

### `students/urls.py`

```python
from django.urls import path
from . import views

urlpatterns = [
    path('', views.home, name='home'),
]
```

### Project `College/urls.py`

```python
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('students/', include('students.urls')),
]
```

Now visit:

```text
http://127.0.0.1:8000/students/
```

and Django renders:

```text
Welcome to Students App
```

---

# 13. What Actually Happens?

Let's follow the complete request:

```text
Browser
   |
   | GET /students/
   ↓
College/urls.py
   |
   | students/
   ↓
students/urls.py
   |
   | ''
   ↓
views.home(request)
   |
   ↓
render(request, 'students/home.html')
   |
   ↓
Django Template Engine
   |
   ↓
home.html
   |
   ↓
HTML response
   |
   ↓
Browser
```

This flow is extremely important.

---

# 14. Template vs View

A common viva question:

### What should go in a view?

Usually:

* request handling
* application logic
* retrieving data
* deciding which response to return

### What should go in a template?

Usually:

* HTML
* presentation
* displaying data
* template logic such as loops and conditions

For example:

### View:

```python
def student(request):
    students = [...]
    return render(
        request,
        'students.html',
        {'students': students}
    )
```

### Template:

```html
<h1>Students</h1>

{% for student in students %}
    <p>{{ student }}</p>
{% endfor %}
```

The view obtains/prepares the data.

The template displays it.

---

# 15. Dynamic Templates

The real power of templates is that they're not static.

Suppose your view has:

```python
def home(request):
    name = "Aman"

    return render(
        request,
        'students/home.html',
        {'name': name}
    )
```

The third argument is called the **context**.

---

# 16. What Is Context?

Context is the data passed from a view to a template.

Example:

```python
context = {
    'name': 'Aman',
    'age': 21
}
```

Then:

```python
return render(
    request,
    'students/home.html',
    context
)
```

The template can access those values.

---

# 17. Displaying Context Data

In:

```text
home.html
```

write:

```html
<h1>Hello {{ name }}</h1>

<p>Age: {{ age }}</p>
```

Django replaces:

```text
{{ name }}
```

with:

```text
Aman
```

and:

```text
{{ age }}
```

with:

```text
21
```

The browser receives the final HTML, not the template syntax.

---

# 18. Important Template Syntax

Django Template Language has several important forms.

### Variable:

```text
{{ variable }}
```

### Tag:

```text
{% tag %}
```

### Comment:

```text
{# comment #}
```

These three are extremely important.

---

# 19. Variables

Example:

```html
<h1>{{ name }}</h1>
```

If the context is:

```python
{'name': 'Aman'}
```

Django produces:

```html
<h1>Aman</h1>
```

---

# 20. Why Are There Double Curly Braces?

Django uses:

```text
{{ }}
```

to indicate that it should evaluate and display a template variable.

For example:

```html
<p>{{ username }}</p>
```

means:

> Display the value of `username`.

---

# 21. Template Tags

Tags use:

```text
{% %}
```

Example:

```html
{% if age >= 18 %}
    <p>Adult</p>
{% endif %}
```

Unlike variables, tags generally control template behavior.

We'll study them in detail in the next modules.

---

# 22. Template Comments

Django has:

```html
{# This is a comment #}
```

It won't appear in the rendered HTML.

For multi-line comments, Django provides:

```html
{% comment %}
This is a
multi-line comment.
{% endcomment %}
```

---

# 23. Template Variables Can Be Dictionary Values

Suppose your view sends:

```python
student = {
    'name': 'Aman',
    'age': 21,
    'course': 'CSE'
}

return render(
    request,
    'student.html',
    {'student': student}
)
```

Template:

```html
<h1>{{ student.name }}</h1>
<p>{{ student.age }}</p>
<p>{{ student.course }}</p>
```

Output:

```text
Aman
21
CSE
```

Django's dot syntax can access dictionary keys and other supported attributes/methods.

---

# 24. Template Variables With Objects

Later, when we learn models, you'll have:

```python
student.name
student.age
```

In a template you can write:

```html
{{ student.name }}
{{ student.age }}
```

This is one reason templates are so useful with Django models.

---

# 25. What If a Variable Doesn't Exist?

Suppose template contains:

```html
<p>{{ xyz }}</p>
```

but `xyz` wasn't supplied in the context.

Django generally renders an empty string rather than raising a normal Python `NameError`.

So it might display:

```text
[blank]
```

This can sometimes make template bugs harder to notice.

---

# 26. Context Dictionary

You can directly pass a dictionary:

```python
return render(
    request,
    'students/home.html',
    {
        'name': 'Aman',
        'course': 'Django'
    }
)
```

Template:

```html
<h1>{{ name }}</h1>
<p>Course: {{ course }}</p>
```

# 27. Better Practice — Named Context Variable

You can also create:

```python
context = {
    'name': 'Aman',
    'course': 'Django'
}

return render(
    request,
    'students/home.html',
    context
)
```

This is easier to read when you have lots of data.

---

# 28. `render()` vs `HttpResponse()`

This is a common viva question.

### `HttpResponse`

```python
return HttpResponse("Hello")
```

Directly returns content.

### `render`

```python
return render(
    request,
    'home.html'
)
```

Loads and processes a template, then returns an HTTP response.

So:

```text
HttpResponse
    ↓
Direct content

render()
    ↓
Template
    ↓
HTML response
```

---

# 29. Does `render()` Return an HTTP Response?

Yes.

Conceptually:

```python
response = render(
    request,
    'home.html'
)
```

returns an `HttpResponse` object.

This is an excellent viva point.

---

# 30. Template Folder Structure

A recommended app-based structure:

```text
students/
│
├── migrations/
├── templates/
│   └── students/
│       ├── home.html
│       ├── list.html
│       └── detail.html
│
├── views.py
├── models.py
└── urls.py
```

Why:

```text
templates/students/
```

instead of simply:

```text
templates/
```

?

Because different apps might have templates with the same filename.

For example:

```text
students/templates/students/home.html
teachers/templates/teachers/home.html
```

Then they don't conflict.

---

# 31. Template Namespacing

Suppose both apps have:

```text
home.html
```

If you use:

```text
templates/home.html
```

in multiple apps, Django can encounter ambiguity depending on template search order.

Instead:

```text
students/templates/students/home.html
teachers/templates/teachers/home.html
```

Then:

```python
render(request, 'students/home.html')
```

and:

```python
render(request, 'teachers/home.html')
```

are clearly separated.

---

# 32. Project-Level Templates

Another common approach is a project-level directory:

```text
College/
├── manage.py
├── College/
├── students/
└── templates/
    └── home.html
```

Then configure:

```python
TEMPLATES = [
    {
        ...
        'DIRS': [BASE_DIR / 'templates'],
        ...
    }
]
```

This tells Django to look in that project-level templates directory.

---

# 33. App Templates vs Project Templates

### App templates

```text
students/templates/students/home.html
```

Useful for templates belonging specifically to an app.

### Project-level templates

```text
templates/home.html
```

Useful for templates shared across the project.

Both approaches are valid.

# 34. Important Settings

Look at:

```python
TEMPLATES = [
    {
        'BACKEND':
            'django.template.backends.django.DjangoTemplates',

        'DIRS': [],

        'APP_DIRS': True,

        'OPTIONS': {
            'context_processors': [
                ...
            ],
        },
    },

```

For now, remember:

### `BACKEND`

Specifies Django's template backend.

### `DIRS`

Specifies additional template directories.

### `APP_DIRS`

Allows Django to search installed apps' template directories.

# 35. Common Error — TemplateDoesNotExist

Suppose your view says:

```python
return render(
    request,
    'students/home.html'
)
```

but the file isn't where Django expects it.

You may see:

```text
TemplateDoesNotExist
```

Possible reasons:

* wrong filename
* wrong folder
* app not installed
* incorrect `DIRS`
* `APP_DIRS=False`
* typo in template path

---

# 36. Example of Wrong Path

Actual file:

```text
students/templates/students/home.html
```

Correct:

```python
render(
    request,
    'students/home.html'
)
```

But if you write:

```python
render(
    request,
    'home.html'
)
```

Django may not find the template depending on your configured template locations.

# 37. Common Error — App Not Installed

Suppose you have:

```text
students/
└── templates/
    └── students/
        └── home.html
```

but forgot to add:

```python
'students'
```

to:


# 39. What Happens Before the Browser Sees It?

The browser does **not** receive:

```html
<h1>Hello {{ name }}</h1>
```

Instead Django processes the template first.

Conceptually:

```text
Template:
<h1>Hello {{ name }}</h1>

        ↓ Django

Final HTML:
<h1>Hello Aman</h1>

        ↓

Browser
```

This is important.

---

# 40. Template Engine

The component responsible for processing Django templates is the **Django template engine**.

It:

1. Loads the template
2. Receives context
3. Evaluates template syntax
4. Produces final HTML
5. Returns it as part of the response

---

# 41. Very Important Distinction

Django template language is **not Python**.

For example:

```html
{% if age >= 18 %}
```

looks somewhat like Python, but template syntax has its own rules.

Don't assume you can write arbitrary Python code inside a template.

Django intentionally limits template logic so presentation doesn't become a full programming environment.

---

# 42. Should We Put Business Logic in Templates?

Generally, no.

Bad design:

```text
Template
   ↓
Huge complicated application logic
```

Better:

```text
View
   ↓
Prepare/process data
   ↓
Template
   ↓
Display data
```

Templates should primarily focus on presentation.

---

# 43. Viva Questions

### Q1. What is a Django template?

> A Django template is typically an HTML file containing presentation markup and Django Template Language syntax for displaying dynamic data and controlling presentation.

### Q2. Why are templates used?

> Templates separate presentation logic from Python application logic and make HTML easier to maintain.

### Q3. What is `render()`?

> `render()` is a Django shortcut that loads a template, combines it with context data, and returns an HTTP response.

### Q4. What is context?

> Context is the data passed from a view to a template.

### Q5. What does `{{ variable }}` mean?

> It is Django Template Language syntax used to display a variable's value.

### Q6. What does `{% ... %}` represent?

> It represents a Django template tag used for template operations such as conditions and loops.

---

# 44. Very Important Viva

### Teacher:

> What is the difference between `{{ }}` and `{% %}`?

Answer:

> `{{ }}` is used primarily to display or resolve variable values, while `{% %}` is used for template tags that perform operations such as conditions, loops, and template inheritance.

---

# 45. Another Viva

### Teacher:

> Does `render()` directly return HTML text?

Better answer:

> `render()` loads and renders a template using the supplied context and returns an `HttpResponse` containing the rendered content.

# 48. Exam Question

### Explain the flow of data from a Django view to a template.

Strong answer:

> The view receives the HTTP request, prepares the required data, and passes that data as a context dictionary to the `render()` function. Django's template engine loads the specified template, resolves the template variables using the context, generates the final HTML, and returns it as an HTTP response to the client.

That's an excellent long-answer/viva response.
