# 5. Registration Form

Create:

```text
accounts/forms.py
```

We'll use Django's `UserCreationForm`.

```python
from django import forms
from django.contrib.auth.models import User
from django.contrib.auth.forms import UserCreationForm


class RegisterForm(UserCreationForm):

    email = forms.EmailField(
        required=True
    )

    class Meta:

        model = User

        fields = [
            "username",
            "email",
            "password1",
            "password2",
        ]
```

---

# 6. Why `UserCreationForm`?

Django already provides a form specifically designed for creating users.

It handles things such as:

```text
username
password
password confirmation
password validation
```

So we don't need to manually implement password hashing.

---

# 7. `password1` and `password2`

The registration form asks for:

```text
Password
Confirm password
```

These correspond to:

```python
password1
password2
```

Django checks that they match.

For example:

```text
Password:
StrongPassword123

Confirm:
StrongPassword123
```

Valid.

But:

```text
Password:
StrongPassword123

Confirm:
abc123
```

Invalid.

---

# 8. Password Validation

Django's authentication system can apply password validators configured in:

```python
AUTH_PASSWORD_VALIDATORS
```

These can enforce rules such as:

```text
not too similar to personal information
minimum length
not commonly used
not entirely numeric
```

This is another reason not to build password handling from scratch.

# 9. Registration View

Now open:

```text
accounts/views.py
```

Write:

```python
from django.shortcuts import (
    render,
    redirect
)

from .forms import RegisterForm


def register(request):

    if request.method == "POST":

        form = RegisterForm(
            request.POST
        )

        if form.is_valid():

            form.save()

            return redirect(
                "login"
            )

    else:

        form = RegisterForm()

    return render(
        request,
        "accounts/register.html",
        {
            "form": form
        }
    )
```

```text

```


Then user submits:


```python

```

```python

```

checks validation.

If valid:

```python

```

creates the user.

Then:


sends the user to login.

# 13. Login Form

We'll create our own login form:

```python
from django import forms


class LoginForm(forms.Form):

    username = forms.CharField(
        max_length=150
    )

    password = forms.CharField(
        widget=forms.PasswordInput
    )
```

So our complete `forms.py` becomes:

```python
from django import forms

from django.contrib.auth.models import User
from django.contrib.auth.forms import (
    UserCreationForm
)


class RegisterForm(UserCreationForm):

    email = forms.EmailField(
        required=True
    )

    class Meta:

        model = User

        fields = [
            "username",
            "email",
            "password1",
            "password2",
        ]


class LoginForm(forms.Form):

    username = forms.CharField(
        max_length=150
    )

    password = forms.CharField(
        widget=forms.PasswordInput
    )
```

# 14. Login View

Now:

```python
from django.contrib.auth import (
    authenticate,
    login,
    logout
)

from .forms import (
    RegisterForm,
    LoginForm
)
```

Then:

```python
def login_view(request):

    if request.method == "POST":

        form = LoginForm(
            request.POST
        )

        if form.is_valid():

            username = form.cleaned_data[
                "username"
            ]

            password = form.cleaned_data[
                "password"
            ]

            user = authenticate(
                request,
                username=username,
                password=password
            )

            if user is not None:

                login(request, user)

                return redirect(
                    "dashboard"
                )

            form.add_error(
                None,
                "Invalid username or password"
            )

    else:

        form = LoginForm()

    return render(
        request,
        "accounts/login.html",
        {
            "form": form
        }
    )
```

# 27. Complete `views.py`

Your `accounts/views.py` can now look like:

```python
from django.shortcuts import (
    render,
    redirect
)

from django.contrib.auth import (
    authenticate,
    login,
    logout
)

from django.contrib.auth.decorators import (
    login_required
)

from .forms import (
    RegisterForm,
    LoginForm
)


def register(request):

    if request.method == "POST":

        form = RegisterForm(
            request.POST
        )

        if form.is_valid():

            form.save()

            return redirect(
                "login"
            )

    else:

        form = RegisterForm()

    return render(
        request,
        "accounts/register.html",
        {
            "form": form
        }
    )


def login_view(request):

    if request.method == "POST":

        form = LoginForm(
            request.POST
        )

        if form.is_valid():

            username = form.cleaned_data[
                "username"
            ]

            password = form.cleaned_data[
                "password"
            ]

            user = authenticate(
                request,
                username=username,
                password=password
            )

            if user is not None:

                login(request, user)

                return redirect(
                    "dashboard"
                )

            form.add_error(
                None,
                "Invalid username or password"
            )

    else:

        form = LoginForm()

    return render(
        request,
        "accounts/login.html",
        {
            "form": form
        }
    )


@login_required
def dashboard(request):

    return render(
        request,
        "accounts/dashboard.html"
    )


@login_required
def profile(request):

    return render(
        request,
        "accounts/profile.html"
    )


def logout_view(request):

    if request.method == "POST":

        logout(request)

        return redirect(
            "login"
        )

    return redirect(
        "dashboard"
    )
```

# 29. What Happens Behind the Scenes?

Suppose Aman logs in.

### Step 1

Browser sends:

```text
POST /login/
```

with:

```text
username=aman
password=...
```

### Step 2

Django validates the form.

### Step 3

```python
authenticate(...)
```

checks the credentials.

### Step 4

```python
login(request, user)
```

establishes authentication using Django's session framework.

### Step 5

The browser receives the session cookie.

### Step 6

Later:

```text
GET /dashboard/
```

includes the session cookie.

### Step 7

Django identifies the authenticated user.

### Step 8

Your view sees:

```python
request.user
```

as Aman.

Wrong:

```python

    request,
    username=username,
    password=password

    return redirect("dashboard")
```

# 47. Common Mistake: Calling `authenticate()` After Login

You don't normally need to call:

```python
authenticate()
```

on every dashboard request.

The authentication/session system handles the authenticated user association.

Your view can simply use:

```python
request.user
```

---

# 48. Common Mistake: Storing Passwords Yourself

Don't do:

```python
request.session["password"] = password
```

Don't do:

```python
user.password = password
```

for normal password setting.

Use Django's authentication/password APIs.

---

# 49. Common Mistake: Trusting Username From the URL

Suppose:

```text
/profile/aman/
```

and you simply assume:

```text
aman = current user
```

That's not a secure authorization mechanism.

For the current authenticated user, use:

```python
request.user
```

For object access, enforce authorization server-side.

---

# 50. Very Important Security Concept

Imagine:

```text
Aman → logged in
Rahul → logged in
```

Aman visits:

```text
/profile/
```

You should use:

```python
request.user
```

to identify Aman.

Don't accept:

```text
/profile/rahul/
```

and automatically assume Aman is allowed to view Rahul's private information.

Authentication tells you:

> Who is making the request?

Authorization tells you:

> Is that user allowed to access this resource?

# 53. Viva Questions

### Q1. What is `authenticate()`?

> It verifies the supplied credentials using Django's authentication system and returns a User object if authentication succeeds, otherwise `None`.

---

### Q2. What does `login()` do?

> It establishes the authenticated user's session so subsequent requests can identify the user.

---

### Q3. What does `logout()` do?

> It logs the user out by ending the authenticated session state.

---

### Q4. Why is `login()` required after `authenticate()`?

> Because `authenticate()` verifies credentials, while `login()` establishes the authenticated session.

---

### Q5. What is `UserCreationForm`?

> It is Django's built-in form for creating users with proper password handling and validation.

---

### Q6. Why use `UserCreationForm`?

> It avoids manually implementing user creation and password hashing/validation logic.

---

### Q7. What is `@login_required`?

> A decorator that restricts a view to authenticated users.

---

### Q8. What happens when an unauthenticated user accesses a protected view?

> Django redirects them to the configured login URL, commonly preserving the original destination using a `next` parameter.

---

### Q9. What is `request.user`?

> It represents the user associated with the current request.

---

### Q10. What is the relationship between login and sessions?

> Django's authentication system uses the session framework to maintain authenticated state across requests.

# 54. Interview Question

### "Explain the Django login process."

Strong answer:

> "The user submits a login form using POST. I validate the form and obtain the username and password from `cleaned_data`. I pass them to `authenticate()`. If it returns a User object, I call `login(request, user)`, which establishes the authenticated session. On subsequent requests, Django uses the session information to associate the request with the authenticated user, which is available through `request.user`. If authentication fails, I return the form with an appropriate error."

# 63. Coding Question

### Complete basic login.

```python
def login_view(request):

    if request.method == "POST":

        username = request.POST.get(
            "username"
        )

        password = request.POST.get(
            "password"
        )

        user = authenticate(
            request,
            username=username,
            password=password
        )

        if user is not None:

            login(request, user)

            return redirect(
                "dashboard"
            )

        return HttpResponse(
            "Invalid credentials"
        )

    return render(
        request,
        "login.html"
    )
```
