# 3. Complete Django Request Flow

This is **extremely important for viva**.

Suppose the browser requests:

```text
/students/
```

The flow is:

```text
Browser
   ↓
HTTP Request
   ↓
Project urls.py
   ↓
App urls.py
   ↓
View
   ↓
Model / ORM
   ↓
Database
   ↓
View
   ↓
Context
   ↓
Template
   ↓
HttpResponse
   ↓
Browser
```

Remember:

> **URL → View → Model → Template → Response**

Not every request necessarily uses all components, but this is the common pattern.




# 14. `path()` vs `re_path()`

Normal URL:

```python
path(
    "student/<int:id>/",
    views.student
)
```

Regex:

```python
re_path(
    r"^student/(?P<id>\d+)/$",
    views.student
)
```

Use `path()` when Django's converters are enough.

Use `re_path()` when you genuinely need regex matching.

# 26. Form Validation

Built-in:

```python
required=True
max_length=100
min_length=3
min_value=0
max_value=100
```

Custom field validation:

```python
def clean_name(self):

    name = self.cleaned_data["name"]

    if " " in name:
        raise forms.ValidationError(
            "Spaces are not allowed."
        )

    return name
```

Cross-field validation:

```python
def clean(self):

    cleaned_data = super().clean()

    password = cleaned_data.get("password")
    confirm = cleaned_data.get("confirm")

    if password != confirm:

        raise forms.ValidationError(
            "Passwords do not match."
        )

    return cleaned_data
```

# 27. CSRF

CSRF:

> Cross-Site Request Forgery.

For POST forms:

```django
{% csrf_token %}
```

Django's CSRF middleware checks the token.

Typical failure:

```text
403 Forbidden
```

Never disable CSRF just to make a POST form work.

# 28. POST-Redirect-GET

Correct:

```python
if form.is_valid():

    form.save()

        "student_list"
    )
```

Flow:

```text

 ↓

 ↓
Redirect
 ↓
```

To prevent accidental duplicate form submission on refresh.

# 51. `instance=` — Extremely Important


Without `instance`:

```text

```

With `instance`:

```text

 ↓

```

This is a **very common coding/viva question**.

# 68. Cookie vs Session

Very important viva question.

| Cookie                        | Session                           |
| ----------------------------- | --------------------------------- |
| Stored by browser             | Usually stored server-side        |
| Client sends cookie data      | Browser commonly sends session ID |
| Can directly store small data | Used for server-managed state     |
| Client-controlled             | Better for server-managed state   |
| `request.COOKIES`             | `request.session`                 |

Django's default database-backed sessions typically store session data server-side and use a `sessionid` cookie to identify the session.

# 74. 401 vs 403

A common trap.

### 401

Generally means authentication is required/failed.

### 403

Means the server understands the request but refuses access.

In Django:

```text
CSRF failure → commonly 403
permission denied → commonly 403
```

# 78. The Most Important Django Coding Pattern

If you get a form-based coding question, think:

```python
def my_view(request):

    if request.method == "POST":

        form = MyForm(
            request.POST
        )

        if form.is_valid():

            # process data

            return redirect(
                "success"
            )

    else:

        form = MyForm()

    return render(
        request,
        "form.html",
        {
            "form": form
        }
    )
```

This pattern solves a huge number of Django questions.
