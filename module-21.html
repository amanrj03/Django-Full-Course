Module 21 — Django Forms

Now we move from manual HTML forms to Django's built-in Forms framework.

This is a very important module because Django Forms combine:

TEXT
HTML generation
+
Input handling
+
Validation
+
Error handling
+
Cleaned data

into a structured Python class.

1. Why Django Forms?

Previously, we created a form manually:

HTML
<form method="POST">

    {% csrf_token %}

    <input type="text" name="name">

    <input type="email" name="email">

    <button type="submit">
        Submit
    </button>

</form>

Then manually processed:

PYTHON
name = request.POST.get("name")
email = request.POST.get("email")

For a small form, that's okay.

But imagine 20 fields.

You would need to manually handle:

  • HTML fields
  • validation
  • required fields
  • error messages
  • type conversion
  • redisplaying values
  • security
  • invalid input

Django Forms simplify this.

2. What Is a Django Form?

A Django Form is a Python class that describes and processes form fields.

Example:

PYTHON
from django import forms

class StudentForm(forms.Form):

    name = forms.CharField()

    age = forms.IntegerField()

    email = forms.EmailField()

This class describes a form containing:

TEXT
name
age
email

3. Where Do We Put Forms?

Django apps commonly have:

TEXT
students/
├── views.py
├── models.py
├── forms.py
├── urls.py
└── ...

Django doesn't necessarily create forms.py automatically with startapp.

You can create it yourself.

4. Creating forms.py

Inside your app:

TEXT
students/forms.py

Write:

PYTHON
from django import forms

Then:

PYTHON
class StudentForm(forms.Form):

    name = forms.CharField()

    age = forms.IntegerField()

    email = forms.EmailField()

5. Understanding forms.Form

This:

PYTHON
class StudentForm(forms.Form):

means:

Create a Django form named StudentForm.

It inherits from:

PYTHON
forms.Form

Django then provides the form-processing functionality.

6. CharField

For text:

PYTHON
name = forms.CharField()

Example:

PYTHON
class StudentForm(forms.Form):

    name = forms.CharField()

This corresponds conceptually to a text input.

7. IntegerField

For integer values:

PYTHON
age = forms.IntegerField()

Django can validate that the submitted value can be interpreted as an integer.

8. EmailField

For email:

PYTHON
email = forms.EmailField()

Django provides email-format validation.

For example:

TEXT
aman@example.com

is structurally email-like.

Whereas:

TEXT
hello

would normally fail the field's email validation.

9. Complete Form

PYTHON
from django import forms


class StudentForm(forms.Form):

    name = forms.CharField()

    age = forms.IntegerField()

    email = forms.EmailField()

This is enough for Django to know that your form has three fields.

10. Rendering the Form

Now let's display it in a template.

View:

PYTHON
from django.shortcuts import render
from .forms import StudentForm


def student_form(request):

    form = StudentForm()

    return render(
        request,
        "student_form.html",
        {"form": form}
    )

Template:

HTML
<form method="POST">

    {% csrf_token %}

    {{ form }}

    <button type="submit">
        Submit
    </button>

</form>

Django generates HTML for the form fields.

11. What Does {{ form }} Do?

When you write:

HTML
{{ form }}

Django renders the form's fields as HTML.

Conceptually, it produces fields corresponding to:

TEXT
Name
Age
Email

You don't have to manually create every <input>.

12. {{ form.as_p }}

A common rendering method is:

HTML
{{ form.as_p }}

It renders each field wrapped in a paragraph structure.

Example conceptually:

HTML
<p>
    <label>Name:</label>
    <input ...>
</p>

<p>
    <label>Age:</label>
    <input ...>
</p>

13. {{ form.as_table }}

You can write:

HTML
{{ form.as_table }}

This renders the form as table rows.

Typically you'd place it inside:

HTML
<table>
    {{ form.as_table }}
</table>

14. {{ form.as_ul }}

Another rendering option:

HTML
{{ form.as_ul }}

It renders the fields as list items.

Typically:

HTML
<ul>
    {{ form.as_ul }}
</ul>

15. Comparison

Syntax Typical output structure
{{ form }} Default form rendering
{{ form.as_p }} Paragraphs
{{ form.as_table }} Table rows
{{ form.as_ul }} List items

For exams, know all four.

16. Important: Rendering Is Not Validation

This is very important.

Creating:

PYTHON
form = StudentForm()

only creates a form instance.

It doesn't mean submitted data is valid.

For submitted data:

PYTHON
form = StudentForm(request.POST)

then:

PYTHON
form.is_valid()

performs validation.

17. Unbound vs Bound Form

This terminology is important.

Unbound form

PYTHON
form = StudentForm()

It has no submitted data.

Used when initially displaying the form.

Bound form

PYTHON
form = StudentForm(request.POST)

It contains submitted data and can be validated.

19. is_valid()

The most important Django Forms method:

PYTHON
form.is_valid()

It validates the submitted data.

Example:

PYTHON
if form.is_valid():
    print("Valid")
else:
    print("Invalid")

It returns:

TEXT
True

or:

TEXT
False

20. Complete GET + POST Form View

This is a pattern you should memorize.

PYTHON
from django.shortcuts import render
from .forms import StudentForm


def student_form(request):

    if request.method == "POST":

        form = StudentForm(request.POST)

        if form.is_valid():

            print("Form is valid")

    else:

        form = StudentForm()

    return render(
        request,
        "student_form.html",
        {"form": form}
    )

Let's understand it carefully.

21. First Visit — GET

When the user opens:

TEXT
/student-form/

the browser sends:

TEXT
GET

So:

PYTHON
if request.method == "POST":

is false.

Django executes:

PYTHON
form = StudentForm()

An empty/unbound form is displayed.

22. Submission — POST

User fills:

TEXT
Name: Aman
Age: 21
Email: aman@example.com

and clicks Submit.

Browser sends:

TEXT
POST

Django executes:

PYTHON
form = StudentForm(request.POST)

Now the form is bound to submitted data.

23. Validation

Then:

PYTHON
if form.is_valid():

Django validates:

TEXT
name
age
email

If everything is valid:

TEXT
True

Otherwise:

TEXT
False

24. cleaned_data

If the form is valid:

PYTHON
form.cleaned_data

contains the cleaned/validated values.

Example:

PYTHON
if form.is_valid():

    name = form.cleaned_data["name"]
    age = form.cleaned_data["age"]
    email = form.cleaned_data["email"]

This is preferred over directly using:

PYTHON
request.POST.get("name")

after form validation.

25. Why cleaned_data?

Suppose:

PYTHON
age = forms.IntegerField()

The browser sends form data as strings.

After validation, Django can convert the valid value into the appropriate Python type.

So:

PYTHON
form.cleaned_data["age"]

can be an integer.

This is one of the major benefits of Django Forms.

26. Example

Form:

PYTHON
class StudentForm(forms.Form):

    name = forms.CharField()

    age = forms.IntegerField()

Submitted:

TEXT
name = "Aman"
age = "21"

After:

PYTHON
form.is_valid()

you can access:

PYTHON
form.cleaned_data["name"]

and:

PYTHON
form.cleaned_data["age"]

The second value can be an integer rather than the original raw string.

27. Form Errors

Suppose the user enters:

TEXT
Age = abc

but:

PYTHON
age = forms.IntegerField()

Validation fails.

Then:

PYTHON
form.is_valid()

returns:

TEXT
False

and Django stores validation errors in the form.

28. Displaying Errors

If your template contains:

HTML
<form method="POST">

    {% csrf_token %}

    {{ form }}

    <button type="submit">
        Submit
    </button>

</form>

Django can render the associated field errors along with the form.

You can also access them explicitly.

29. form.errors

In Python:

PYTHON
form.errors

contains validation errors.

Example:

PYTHON
if not form.is_valid():

    print(form.errors)

Useful for debugging and understanding validation.

30. Required Fields

By default, many Django form fields are required.

Example:

PYTHON
name = forms.CharField()

If the user submits it empty, validation generally fails.

31. required=False

You can make a field optional:

PYTHON
phone = forms.CharField(
    required=False
)

Now the user can leave it blank.

32. label

You can customize the field label:

PYTHON
name = forms.CharField(
    label="Student Name"
)

Django can use:

TEXT
Student Name

instead of deriving the default label from name.

33. initial

You can provide an initial/default displayed value:

PYTHON
name = forms.CharField(
    initial="Aman"
)

The form initially displays:

TEXT
Aman

The user can modify it unless other restrictions apply.

34. help_text

You can provide additional information:

PYTHON
name = forms.CharField(
    help_text="Enter your full name"
)

This can help explain what the field expects.

35. max_length

For text:

PYTHON
name = forms.CharField(
    max_length=100
)

This limits the accepted string length during form validation and can influence the generated HTML widget.

36. min_length

You can also specify:

PYTHON
name = forms.CharField(
    min_length=3
)

The submitted value must satisfy the minimum length requirement.

37. IntegerField Options

Example:

PYTHON
age = forms.IntegerField(
    min_value=18,
    max_value=100
)

Now the form expects an integer within that range.

For example:

TEXT
21 → valid
17 → invalid
101 → invalid

38. EmailField

Example:

PYTHON
email = forms.EmailField()

Django validates that the value has a valid email-like structure.

39. ChoiceField

For a fixed set of choices:

PYTHON
course = forms.ChoiceField(
    choices=[
        ("cse", "Computer Science"),
        ("it", "Information Technology"),
        ("ece", "Electronics")
    ]
)

The first element is the submitted value.

The second is the human-readable label.

40. Understanding Choices

PYTHON
("cse", "Computer Science")

means:

TEXT
submitted value → cse
displayed label → Computer Science

This distinction is very important.

41. BooleanField

Example:

PYTHON
agree = forms.BooleanField()

This is useful for things such as:

TEXT
I agree to the terms

You can customize whether it is required.

42. DateField

Example:

PYTHON
dob = forms.DateField()

Django can validate and convert the submitted date according to the field's configuration.

43. Multiple Fields

A realistic form:

PYTHON
from django import forms


class StudentForm(forms.Form):

    name = forms.CharField(
        max_length=100
    )

    age = forms.IntegerField(
        min_value=16,
        max_value=100

        ]

45. Complete View

PYTHON
from django.shortcuts import render
from .forms import StudentForm


def student_form(request):

    if request.method == "POST":

        form = StudentForm(request.POST)

        if form.is_valid():

            name = form.cleaned_data["name"]
            age = form.cleaned_data["age"]
            email = form.cleaned_data["email"]
            course = form.cleaned_data["course"]
            dob = form.cleaned_data["dob"]

            print(name)
            print(age)
            print(email)
            print(course)
            print(dob)

    else:

        form = StudentForm()

    return render(
        request,
        "student_form.html",
        {"form": form}
    )

49. Form vs ModelForm

You will eventually encounter:

PYTHON
forms.Form

and:

PYTHON
forms.ModelForm

Form

You manually define form fields.

PYTHON
class StudentForm(forms.Form):
    name = forms.CharField()

ModelForm

Django can generate form fields based on a model.

PYTHON
class StudentForm(forms.ModelForm):
    class Meta:
        model = Student
        fields = "__all__"

We'll study this later.

50. Common Mistake — Forgetting request.POST

Wrong:

PYTHON
form = StudentForm()

when processing submitted data.

Correct:

PYTHON
form = StudentForm(request.POST)

Otherwise Django doesn't have the submitted data to validate.

51. Common Mistake — Calling cleaned_data Before Validation

Wrong:

PYTHON
form = StudentForm(request.POST)

name = form.cleaned_data["name"]

Correct:

PYTHON
form = StudentForm(request.POST)

if form.is_valid():

    name = form.cleaned_data["name"]

cleaned_data should be used after successful validation.

52. Common Mistake — Forgetting CSRF

For a POST form:

HTML
<form method="POST">

    {% csrf_token %}

    {{ form.as_p }}

</form>

We'll study CSRF in detail in Module 23.

53. Common Mistake — Not Returning the Form

Suppose validation fails.

You generally want to render the bound form again:

PYTHON
return render(
    request,
    "student_form.html",
    {"form": form}
)

This allows Django to display validation errors and submitted values appropriately.

54. Viva Questions

Q1. What is a Django Form?

A Django Form is a Python class used to define, render, validate, and process user input.

Q2. Which module provides Django Forms?

PYTHON
from django import forms

Q3. What is forms.Form?

It is the base class used to create standard Django forms.

Q4. What is forms.CharField?

A form field designed primarily for text input and validation.

Q5. What is forms.IntegerField?

A form field that validates and converts integer input.

55. Viva — Bound vs Unbound

Teacher:

What is an unbound form?

Answer:

A form created without submitted data, such as StudentForm(), generally used to initially display an empty form.

Teacher:

What is a bound form?

Answer:

A form created with submitted data, such as StudentForm(request.POST), which can then be validated.

56. Viva — is_valid()

Teacher:

What does is_valid() do?

Answer:

It runs the form's validation process and returns True if the submitted data is valid and False otherwise.

57. Viva — cleaned_data

Teacher:

What is cleaned_data?

Answer:

cleaned_data is a dictionary containing the cleaned and validated form values after successful validation.

58. Viva — Why Not request.POST?

Teacher:

Why use cleaned_data instead of directly processing request.POST after validation?

Answer:

cleaned_data contains values after Django has performed the form field's validation and appropriate conversion, making it safer and easier to work with.

59. Viva — forms.Form vs ModelForm

Answer:

forms.Form requires fields to be explicitly defined, while forms.ModelForm can generate form fields from a Django model and is commonly used when a form corresponds to database data.
