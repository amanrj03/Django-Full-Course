Module 13 — Django Template Language (DTL)

Now we move into the core of Django templates.

You already know how to create an HTML template and pass data from a view. Now we need to learn how Django actually works with that data inside the HTML file.

This is called Django Template Language (DTL).

1. What Is DTL?

DTL = Django Template Language

It is Django's template syntax used to:

  • Display data
  • Work with variables
  • Use conditions
  • Use loops
  • Apply filters
  • Include/reuse templates
  • Generate dynamic HTML

For example:

HTML
<h1>Hello {{ name }}</h1>

If the view sends:

PYTHON
{'name': 'Aman'}

Django renders:

HTML
<h1>Hello Aman</h1>

2. DTL Is Not Python

This is extremely important for viva.

DTL is designed for templates and presentation. It is not simply Python embedded inside HTML.

For example, you cannot normally write arbitrary Python code such as:

PYTHON
for i in range(10):

inside a Django template.

Instead, DTL provides its own syntax:

HTML
{% for i in numbers %}
{% endfor %}

3. Three Main DTL Syntaxes

You should memorize these three.

1. Variable

HTML
{{ variable }}

Used to display data.

2. Tag

HTML
{% tag %}

Used for template operations.

Examples:

HTML
{% if %}
{% for %}
{% url %}
{% block %}

3. Comment

HTML
{# comment #}

Used for comments.

4. DTL Variable

Suppose your view is:

PYTHON
from django.shortcuts import render

def home(request):
    return render(
        request,
        'home.html',
        {'name': 'Aman'}
    )

Template:

HTML
<h1>Hello {{ name }}</h1>

Output:

TEXT
Hello Aman

5. How Does Django Find name?

The context is:

PYTHON
{
    'name': 'Aman'
}

Therefore Django creates a template context containing:

TEXT
name → Aman

When the template encounters:

TEXT
{{ name }}

it resolves the variable and outputs:

TEXT
Aman

6. Multiple Variables

View:

PYTHON
def home(request):

    context = {
        'name': 'Aman',
        'age': 21,
        'course': 'CSE'
    }

    return render(
        request,
        'home.html',
        context
    )

Template:

HTML
<h1>{{ name }}</h1>
<p>Age: {{ age }}</p>
<p>Course: {{ course }}</p>

Output:

TEXT
Aman
Age: 21
Course: CSE

7. Variable Names Are Case-Sensitive

Suppose context contains:

PYTHON
{
    'name': 'Aman'
}

Then:

HTML
{{ name }}

works.

But:

HTML
{{ Name }}

does not refer to the same context variable.

So be careful with spelling and capitalization.

8. Dictionary Data

Suppose your view contains:

PYTHON
student = {
    'name': 'Aman',
    'age': 21,
    'course': 'CSE'
}

return render(
    request,
    'student.html',
    {'student': student}
)

You can access dictionary values using dot notation:

HTML
<h1>{{ student.name }}</h1>
<p>{{ student.age }}</p>
<p>{{ student.course }}</p>

Output:

TEXT
Aman
21
CSE

9. Important: Dot Notation

Django template syntax uses:

TEXT
{{ object.attribute }}

It can resolve different types of things, including dictionary lookups and attributes.

For example:

HTML
{{ student.name }}

can resolve the name value from the context object.

This becomes extremely useful when we start using Django Models.

10. Nested Data

Suppose:

PYTHON
student = {
    'name': 'Aman',
    'address': {
        'city': 'Phagwara',
        'state': 'Punjab'
    }
}

Pass:

PYTHON
{
    'student': student
}

Template:

HTML
<p>Name: {{ student.name }}</p>
<p>City: {{ student.address.city }}</p>
<p>State: {{ student.address.state }}</p>

Django can traverse the nested structure using dot notation.

11. Lists

Suppose:

PYTHON
students = [
    'Aman',
    'Rahul',
    'Rohit'
]

Pass:

PYTHON
return render(
    request,
    'students.html',
    {'students': students}
)

A loop can later display the values:

HTML
{% for student in students %}
    <p>{{ student }}</p>
{% endfor %}

We'll study loops in depth in a later module.

12. Accessing List Elements

Django templates can resolve numeric indexes using dot notation.

Suppose:

PYTHON
students = ['Aman', 'Rahul', 'Rohit']

Then:

HTML
{{ students.0 }}

gives:

TEXT
Aman

And:

HTML
{{ students.1 }}

gives:

TEXT
Rahul

This is useful to know for viva questions.

13. What If a Variable Doesn't Exist?

Suppose your context is:

PYTHON
{
    'name': 'Aman'
}

but template contains:

HTML
{{ age }}

Since age isn't available, Django generally renders an empty string.

So you may see:

TEXT
[blank]

rather than a Python NameError.

14. DTL Comments

Single-line comment:

HTML
{# This is a comment #}

It won't be rendered as visible HTML.

For multiple lines:

HTML
{% comment %}
This is a
multi-line comment.
{% endcomment %}

15. DTL Tags

Tags are written using:

HTML
{% ... %}

Some important tags are:

HTML
{% if %}
{% else %}
{% elif %}
{% endif %}

{% for %}
{% endfor %}

{% url %}

{% extends %}
{% block %}

{% include %}

We'll learn each of these throughout the next modules.

16. Variable vs Tag

This is a common viva question.

Variable:

HTML
{{ name }}

Purpose:

Display/resolve a value.

Tag:

HTML
{% if age >= 18 %}

Purpose:

Perform a template operation.

Remember:

TEXT
{{ }} → value
{% %} → operation

17. Filters

DTL also provides filters.

Filters modify or process values before displaying them.

Syntax:

HTML
{{ variable|filter }}

For example:

HTML
{{ name|upper }}

If:

TEXT
name = Aman

output:

TEXT
AMAN

The pipe:

TEXT
|

means:

Apply this filter to the value.

18. upper Filter

Example:

HTML
{{ name|upper }}

If:

TEXT
name = Aman

output:

TEXT
AMAN

19. lower Filter

HTML
{{ name|lower }}

If:

TEXT
name = AMAN

output:

TEXT
aman

20. title Filter

HTML
{{ name|title }}

For example:

TEXT
hello django world

becomes approximately:

TEXT
Hello Django World

21. length Filter

You can determine the length of a value.

HTML
{{ name|length }}

If:

TEXT
name = Aman

output:

TEXT
4

For a list:

HTML
{{ students|length }}

it gives the number of items.

22. default Filter

Suppose:

PYTHON
name = ''

You can write:

HTML
{{ name|default:"Guest" }}

If name is empty, the output is:

TEXT
Guest

This is very useful.

23. Filter Chaining

You can apply multiple filters.

Example:

HTML
{{ name|upper|length }}

If:

TEXT
name = aman

First:

TEXT
aman
 ↓ upper
AMAN
 ↓ length
4

Output:

TEXT
4

24. safe Filter

Django templates automatically escape potentially unsafe HTML in many normal variable-rendering situations.

Suppose context contains:

PYTHON
{
    'message': '<b>Hello</b>'
}

Template:

HTML
{{ message }}

Django will normally escape the HTML rather than interpret it as markup.

This helps protect against certain XSS attacks.

25. What Does safe Do?

If you intentionally trust the content and write:

HTML
{{ message|safe }}

Django treats the value as safe HTML for rendering.

For example:

HTML
{{ message|safe }}

can render:

HTML
<b>Hello</b>

as bold text.

Important security rule:

Never blindly use:

HTML
{{ user_input|safe }}

on untrusted user input.

That can introduce Cross-Site Scripting (XSS) vulnerabilities.

26. Autoescaping

Django templates generally use automatic HTML escaping.

Suppose:

PYTHON
message = '<script>alert("Hello")</script>'

and template:

HTML
{{ message }}

Django escapes the HTML so the browser doesn't simply execute the supplied markup as HTML.

This is one of Django's built-in security features.

27. Important Viva Question

What is autoescaping?

Strong answer:

Autoescaping is a Django template feature that automatically escapes potentially unsafe HTML characters when rendering variables, helping protect against XSS attacks.

28. Filter vs Tag

Another common viva question.

Filter:

HTML
{{ name|upper }}

Changes/processes a value.

Tag:

HTML
{% if user %}

Controls template behavior.

Therefore:

TEXT
Filter → modifies a value
Tag    → performs template operation

30. truncatechars

Suppose:

TEXT
description =
"This is a very long description of a Django project."

You can write:

HTML
{{ description|truncatechars:20 }}

to display a shortened version.

The exact output depends on the value and truncation rules.

31. join

Suppose:

PYTHON
subjects = ['Python', 'Django', 'SQL']

Template:

HTML
{{ subjects|join:", " }}

Output:

TEXT
Python, Django, SQL

32. add

Example:

HTML
{{ age|add:"1" }}

If:

TEXT
age = 21

it can produce:

TEXT
22

Be aware that Django's add filter uses Python-like addition behavior where possible and can also concatenate compatible values.

33. date

If a context variable is a Python date/datetime object:

HTML
{{ date|date:"d-m-Y" }}

could display:

TEXT
12-09-2026

Date formatting becomes particularly useful when working with models.

34. Filters Use a Colon for Arguments

Some filters accept arguments.

Example:

HTML
{{ name|default:"Guest" }}

Here:

TEXT
default

is the filter and:

TEXT
"Guest"

is its argument.

Another example:

HTML
{{ description|truncatechars:20 }}

Suppose you write:

HTML

    <p>Adult</p>

HTML
{% endif %}

Correct:

HTML
{% if age >= 18 %}
    <p>Adult</p>

38. DTL and Security

Django templates provide several security protections, but you still have to use them correctly.

Important things to remember:

  • Don't blindly mark user input as safe
  • Don't put passwords into templates unnecessarily
  • Don't disable escaping without understanding why
  • Validate data in appropriate application layers
  • Use CSRF protection for forms

We'll study CSRF later in the Forms unit.

39. A Very Important Concept: Template Context

Suppose your view:

PYTHON
def home(request):

    context = {
        'username': 'Aman',
        'age': 21
    }

    return render(
        request,
        'home.html',
        context
    )

Think of context as a bridge:

TEXT
Python View
     |
     | context
     ↓
Template

The template can access:

HTML
{{ username }}
{{ age }}

40. What If You Change the Context?

Suppose you change:

PYTHON
'name': 'Aman'

to:

PYTHON
'name': 'Rahul'

without changing the template:

HTML
<h1>Hello {{ name }}</h1>

the output automatically becomes:

TEXT
Hello Rahul

This is the main idea behind dynamic templates.

41. Real-World Example

Imagine an e-commerce website.

The view gets:

PYTHON
product = {
    'name': 'Laptop',
    'price': 55000,
    'stock': 10
}

The template can display:

HTML
<h1>{{ product.name }}</h1>
<p>₹{{ product.price }}</p>
<p>Stock: {{ product.stock }}</p>

The HTML structure remains the same while the data changes.

That's what makes Django templates powerful.

42. Important Viva Questions

Q1. What is DTL?

DTL stands for Django Template Language. It is Django's template syntax for displaying dynamic data and controlling template presentation.

Q2. Is DTL Python?

No. DTL is Django's own template language and does not allow arbitrary Python code in templates.

Q3. What does {{ }} mean?

It is used to resolve and display template variables.

Q4. What does {% %} mean?

It represents template tags used for operations such as conditions, loops, URL generation, and template inheritance.

Q5. What does | mean in a template?

It applies a template filter to a value.

43. Viva — Filters

Q: What is a template filter?

Answer:

A template filter modifies or processes a value before it is displayed in a template.

Example:

HTML
{{ name|upper }}

Q: What does upper do?

Converts text to uppercase.

Q: What does lower do?

Converts text to lowercase.

Q: What does length do?

Returns the length of a value when applicable.

Q: What does default do?

Provides a fallback value when the variable is empty or otherwise evaluates as false according to the filter's behavior.

44. Important Security Viva

Teacher:

Why does Django escape HTML in templates?

Answer:

Django's automatic escaping helps prevent malicious HTML or JavaScript from being interpreted as markup, reducing the risk of Cross-Site Scripting attacks.

Teacher:

What does safe do?

Answer:

The safe filter marks a value as safe HTML for template rendering, so it should only be used when the content is trusted or has been properly sanitized.

50. One Important Correction to Remember

DTL's dot lookup is more powerful than simply saying:

"Dot notation only accesses object attributes."

Django resolves dot lookups through several mechanisms, including dictionary lookup, attribute lookup, list-index lookup, and callable handling according to its template rules.

For beginner coding, you'll most commonly encounter:

HTML
{{ student.name }}
{{ student.address.city }}
{{ students.0 }}
