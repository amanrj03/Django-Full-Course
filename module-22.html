Module 22 — Form Validation in Django

This module is very important for coding questions and viva, because teachers often ask:

  • How does Django validate form data?
  • What is cleaned_data?
  • Difference between clean_<field>() and clean().
  • How do you create custom validation?
  • How do you validate two fields together?
  • How do you display validation errors?
  • How do min_length, max_length, min_value, etc. work?

1. What is Form Validation?

Form validation means checking whether the data entered by the user is:

  1. Present when required
  2. Of the correct type
  3. Within allowed limits
  4. In the correct format
  5. Logically valid according to our application's rules

For example, suppose we have:

PYTHON
class StudentForm(forms.Form):
    name = forms.CharField()
    age = forms.IntegerField()
    email = forms.EmailField()

A user might enter:

TEXT
Name: Aman
Age: abc
Email: hello

The form should reject this data.

Django automatically performs many basic validations for us.

2. The Most Important Line: is_valid()

When a form receives submitted data:

PYTHON
form = StudentForm(request.POST)

we check:

PYTHON
if form.is_valid():

Example:

PYTHON
def student_form(request):

    if request.method == "POST":
        form = StudentForm(request.POST)

        if form.is_valid():
            print("Valid data")
        else:
            print("Invalid data")

    else:
        form = StudentForm()

    return render(request, "student_form.html", {"form": form})

Important

is_valid() does much more than simply return True or False.

It triggers Django's validation process.

Conceptually:

TEXT
request.POST
     ↓
Bound Form
     ↓
form.is_valid()
     ↓
Validation
     ↓
Valid? ─────── No ──→ form.errors
   │
  Yes
   ↓
form.cleaned_data

3. What is cleaned_data?

After successful validation:

PYTHON
form.cleaned_data

contains the cleaned and converted data.

Example:

PYTHON
class StudentForm(forms.Form):
    name = forms.CharField()
    age = forms.IntegerField()

User submits:

TEXT
name = "Aman"
age = "21"

Notice that HTTP form data arrives essentially as strings.

Django converts the age into an integer.

After:

PYTHON
form.is_valid()

we can do:

PYTHON
form.cleaned_data["name"]

Result:

TEXT
Aman

and:

PYTHON
form.cleaned_data["age"]

Result:

PYTHON
21

which is an integer.

Very important rule

Do not use:

PYTHON
form.cleaned_data

before:

PYTHON
form.is_valid()

Correct:

PYTHON
if form.is_valid():
    age = form.cleaned_data["age"]

15. Field-Level Custom Validation

Now we reach one of the most important topics.

Suppose Django's built-in validators are not enough.

For example:

Student name should not contain numbers.

We can create custom validation.

16. clean_<field>()

For validating a specific field, use:

PYTHON
clean_<fieldname>()

For example:

PYTHON
clean_name()

Complete example:

PYTHON
from django import forms

class StudentForm(forms.Form):

    name = forms.CharField()
    age = forms.IntegerField()

    def clean_name(self):
        name = self.cleaned_data["name"]

        if any(char.isdigit() for char in name):
            raise forms.ValidationError(
                "Name should not contain numbers."
            )

        return name

Let's understand this carefully.

17. How clean_name() Works

Suppose user enters:

TEXT
Aman123

Django first performs the normal validation for the field.

Then Django calls:

PYTHON
clean_name()

Inside:

PYTHON
name = self.cleaned_data["name"]

we get the already cleaned name.

Then:

PYTHON
if any(char.isdigit() for char in name):

checks whether any character is a digit.

If yes:

PYTHON
raise forms.ValidationError(
    "Name should not contain numbers."
)

The form becomes invalid.

If everything is fine:

PYTHON
return name

The returned value becomes the cleaned value for that field.

18. Why Must We Return the Value?

This is a common viva/coding question.

Correct:

PYTHON
def clean_name(self):
    name = self.cleaned_data["name"]

    if len(name) < 3:
        raise forms.ValidationError("Too short")

    return name

The return is important because Django uses the returned value as the cleaned value.

You can even modify it:

PYTHON
def clean_name(self):
    name = self.cleaned_data["name"]
    return name.strip().title()

So:

TEXT
"  aman ranjan  "

can become:

TEXT
"Aman Ranjan"

19. Another clean_<field>() Example

Suppose username cannot contain spaces.

PYTHON
class RegisterForm(forms.Form):

    username = forms.CharField()

    def clean_username(self):
        username = self.cleaned_data["username"]

        if " " in username:
            raise forms.ValidationError(
                "Username cannot contain spaces."
            )

        return username

Suppose password must contain at least one digit.

PYTHON
class RegisterForm(forms.Form):

    password = forms.CharField(

    def clean_password(self):

21. clean() — Cross-Field Validation

This is another very important viva question.

Use:

PYTHON
clean()

when validation depends on multiple fields together.

For example:

TEXT
Password
Confirm Password

We need to compare both.

22. Password Confirmation Example

PYTHON
from django import forms

class RegisterForm(forms.Form):

    password = forms.CharField(
        widget=forms.PasswordInput
    )

    confirm_password = forms.CharField(
        widget=forms.PasswordInput
    )

    def clean(self):
        cleaned_data = super().clean()

        password = cleaned_data.get("password")
        confirm_password = cleaned_data.get("confirm_password")

        if password and confirm_password:
            if password != confirm_password:
                raise forms.ValidationError(
                    "Passwords do not match."
                )

        return cleaned_data

23. Why super().clean()?

This line:

PYTHON
cleaned_data = super().clean()

calls Django's parent implementation of clean().

It gives us the cleaned field data that has already passed field-level validation.

Then:

PYTHON
password = cleaned_data.get("password")

gets the password.

And:

PYTHON
confirm_password = cleaned_data.get("confirm_password")

gets the confirmation.

Then:

PYTHON
if password != confirm_password:

compares them.

24. clean_<field>() vs clean()

This is extremely important for viva.

Method Purpose
clean_name() Validate one specific field
clean_email() Validate one specific field
clean_age() Validate one specific field
clean() Validate multiple fields together

Easy rule

One field → clean_<field>()
Multiple fields → clean()

25. Example: Age Validation

Built-in validation:

PYTHON
age = forms.IntegerField(
    min_value=18,
    max_value=60
)

This is preferable when the rule is simple.

But suppose:

Students under 18 cannot register for a particular course.

Now validation depends on both:

TEXT
age
course

So we use:

PYTHON
def clean(self):

Example:

PYTHON
class StudentForm(forms.Form):

    age = forms.IntegerField()
    course = forms.ChoiceField(
        choices=[
            ("cse", "CSE"),
            ("mba", "MBA")
        ]
    )

    def clean(self):
        cleaned_data = super().clean()

        age = cleaned_data.get("age")
        course = cleaned_data.get("course")

        if age is not None and course == "mba" and age < 18:
            raise forms.ValidationError(
                "Student must be at least 18 for MBA."
            )

        return cleaned_data

26. add_error()

Sometimes you want to add an error to a specific field.

Django provides:

PYTHON
self.add_error()

Example:

PYTHON
class StudentForm(forms.Form):

    age = forms.IntegerField()

    def clean(self):
        cleaned_data = super().clean()

        age = cleaned_data.get("age")

        if age is not None and age < 18:
            self.add_error(
                "age",
                "Student must be at least 18."
            )

        return cleaned_data

Now the error belongs specifically to:

TEXT
age

rather than being a non-field/form-wide error.

28. Field Error vs Non-Field Error

Suppose we have:

PYTHON
password
confirm_password

and they don't match.

This error doesn't belong naturally to only one field.

Using:

PYTHON
raise forms.ValidationError(
    "Passwords do not match."
)

creates a non-field/form-level error.

In the template, you can display:

HTML
{{ form.non_field_errors }}

29. Using add_error() Instead

If you want the error associated with a specific field:

PYTHON
self.add_error(
    "confirm_password",
    "Passwords do not match."
)

Now the error appears against:

TEXT
confirm_password

This can make the UI clearer.

30. Complete Validation Example

Let's build a realistic registration form.

PYTHON
from django import forms


class RegisterForm(forms.Form):

    username = forms.CharField(
        min_length=5,
        max_length=20
    )

    email = forms.EmailField()

    age = forms.IntegerField(
        min_value=18,
        max_value=60
    )

    password = forms.CharField(
        min_length=8,
        widget=forms.PasswordInput
    )

    confirm_password = forms.CharField(
        widget=forms.PasswordInput
    )

    def clean_username(self):
        username = self.cleaned_data["username"]

        if " " in username:
            raise forms.ValidationError(
                "Username cannot contain spaces."
            )

        return username

    def clean_password(self):
        password = self.cleaned_data["password"]

        if not any(char.isdigit() for char in password):
            raise forms.ValidationError(
                "Password must contain at least one digit."
            )

        return password

    def clean(self):
        cleaned_data = super().clean()

        password = cleaned_data.get("password")
        confirm_password = cleaned_data.get("confirm_password")

        if password and confirm_password:
            if password != confirm_password:
                self.add_error(
                    "confirm_password",
                    "Passwords do not match."
                )

        return cleaned_data

This one form demonstrates:

  • min_length
  • max_length
  • EmailField
  • min_value
  • max_value
  • PasswordInput
  • clean_<field>()
  • clean()
  • custom validation
  • ValidationError
  • add_error()

31. Validation Pipeline — Very Important

You should understand what happens internally.

Suppose:

PYTHON
form = RegisterForm(request.POST)

Then:

PYTHON
form.is_valid()

starts the validation process.

Conceptually:

TEXT
             request.POST
                  ↓
             Bound Form
                  ↓
             is_valid()
                  ↓
        Field-level processing
                  ↓
      Field type/required checks
                  ↓
          Built-in validators
                  ↓
        clean_<field>() methods
                  ↓
             clean()
                  ↓
          Validation complete
             ↙          ↘
          valid         invalid
            ↓              ↓
    cleaned_data       form.errors

This flow is worth remembering for viva.

33. Important: Don't Process Invalid Data

Bad:

PYTHON
form = StudentForm(request.POST)

name = form.cleaned_data["name"]

Why bad?

Because validation has not happened.

Correct:

PYTHON
form = StudentForm(request.POST)

if form.is_valid():
    name = form.cleaned_data["name"]

views.py

PYTHON
from django.shortcuts import render
from .forms import StudentForm


def student_form(request):

    if request.method == "POST":

        form = StudentForm(request.POST)

        if form.is_valid():

            name = form.cleaned_data["name"]
            age = form.cleaned_data["age"]
            email = form.cleaned_data["email"]

            return render(
                request,
                "success.html",

                    "name": name,
                    "age": age,
                    "email": email

    else:

        form = StudentForm()

    return render(

        "student_form.html",

35. Built-in vs Custom Validation

Built-in validation

Use:

PYTHON

    min_value=18,
    max_value=60
)

when Django already provides the rule.

Custom validation

Use:

PYTHON
def clean_age(self):

when your application's specific rule isn't covered by built-in field options.

Example:

PYTHON
def clean_age(self):
    age = self.cleaned_data["age"]

    if age % 2 != 0:
        raise forms.ValidationError(
            "Age must be an even number."
        )

    return age

37. clean_<field>() vs Validator Functions

Django also supports validators.

38. Very Important Viva Questions

Q1. What is form validation?

Answer:

Form validation is the process of checking whether submitted form data is present, correctly formatted, type-correct, within allowed limits, and satisfies application-specific rules.

Q2. What does is_valid() do?

Answer:

is_valid() runs the form's validation process and returns True if the submitted data is valid, otherwise False.

Q3. What is cleaned_data?

Answer:

cleaned_data is a dictionary containing validated and cleaned form data after successful form validation.

Q4. When is cleaned_data available?

Answer:

It should be accessed after form.is_valid() has been called.

Q5. What is clean_<field>()?

Answer:

It is a custom validation method used to validate or transform a specific form field.

Example:

PYTHON
def clean_email(self):
    ...

Q6. What is clean()?

Answer:

clean() is used for form-wide or cross-field validation when the validation rule depends on multiple fields.

Q7. Difference between clean_name() and clean()?

Answer:

TEXT
clean_name() → validates name only
clean()      → validates multiple fields/form-wide rules

Q8. What is ValidationError?

Answer:

ValidationError is raised when submitted data does not satisfy a validation rule.

Example:

PYTHON
raise forms.ValidationError("Invalid name")

Q9. What is add_error()?

Answer:

add_error() manually adds a validation error to a particular form field.

Example:

PYTHON
self.add_error("age", "Age is invalid.")

Q10. Why do we use super().clean()?

Answer:

It calls Django's parent clean() implementation and provides the cleaned data needed for further form-wide validation.

Q11. What does required=False mean?

Answer:

It makes a form field optional.

Q12. What is min_length?

Answer:

It specifies the minimum number of characters allowed for a field.

Q13. What is min_value?

Answer:

It specifies the minimum numeric value accepted by a field.

Q14. Does is_valid() return cleaned data?

No.

It returns:

PYTHON
True

or:

PYTHON
False

The cleaned data is accessed through:

PYTHON
form.cleaned_data
