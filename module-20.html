Module 20 — HTML Forms & HTTP in Django

We are now starting Unit IV — Forms.

Before learning Django's built-in Form class, you need to understand HTML forms and how browsers send data to Django.

This is extremely important because later:

TEXT
HTML Form
   ↓
HTTP GET/POST
   ↓
Django View
   ↓

   ↓
Validation
   ↓
Database

will become the foundation of login forms, registration, CRUD applications, search forms, etc.

1. What Is a Form?

A form is an HTML mechanism used to collect information from a user.

Examples:

  • Login
  • Registration
  • Search
  • Contact form
  • Student registration
  • Product creation
  • Feedback

A simple form:

HTML
<form>
    <input type="text">
    <button type="submit">Submit</button>
</form>

The user enters information and submits it.

2. Basic HTML Form Structure

The general syntax is:

HTML
<form method="POST" action="/students/">

    <input type="text" name="name">

    <button type="submit">
        Submit
    </button>

</form>

There are three important concepts here:

TEXT
form
 ├── method
 ├── action
 └── form fields

3. The method Attribute

The method determines how the browser sends the form data.

Most commonly:

HTML
method="GET"

or:

HTML
method="POST"

Example:

HTML
<form method="GET">

or:

HTML
<form method="POST">

4. The action Attribute

action specifies where the form data should be sent.

Example:

HTML
<form action="/students/" method="POST">

This means:

When submitted, send the form data to /students/.

You can also use Django URL reversing:

HTML
<form action="{% url 'students' %}" method="POST">

This is generally preferable to hardcoding URLs.

5. What Is <input>?

input creates a field where users can enter/select data.

Example:

HTML

Common input types:

6. The name Attribute ⭐

This is very important.

Consider:

HTML

The:

If the user enters:

7. id vs name

Beginners often confuse these.

Example:

HTML

    type="text"

>

id

Primarily identifies the HTML element in the page and is commonly used by:

  • JavaScript

name

Identifies the form field when form data is submitted.

For Django form processing, name is crucial.

10. Why Does GET Put Data in the URL?

GET requests commonly use the query string.

For example:

TEXT

Break it down:

TEXT

   ↓
path

?
   ↓
start of query string

query=Django
   ↓
key=value

11. Multiple GET Parameters

Suppose:

HTML

<input type="number" name="age">

TEXT

12. Receiving GET Data in Django

View:

PYTHON
from django.http import HttpResponse

def search(request):

    query = request.GET.get("query")

    return HttpResponse(
        f"You searched for: {query}"
    )

Suppose the browser requests:

TEXT
/search/?query=Django

Then:

PYTHON
request.GET.get("query")

returns:

TEXT
Django

13. Why Use .get()?

You learned this earlier.

Instead of:

PYTHON
query = request.GET["query"]

prefer:

PYTHON
query = request.GET.get("query")

when the parameter may be missing.

If missing:

PYTHON
request.GET.get("query")

normally returns:

PYTHON
None

while direct indexing can raise a KeyError.

You can also provide a default:

PYTHON
query = request.GET.get(
    "query",
    ""
)

17. GET vs POST

This is a must-know viva question.

GET POST
Commonly used to retrieve/search data Commonly used to submit/change data
Data commonly appears in URL query string Form data is sent in request body
Can be bookmarked/shared as a URL Usually not represented by the form data in the URL
Suitable for search/filtering Suitable for create/update/login operations
Should not be relied on for sensitive data Better suited for sensitive/state-changing submissions
Parameters commonly accessed via request.GET Parameters commonly accessed via request.POST

18. Important Security Point

A common misconception is:

"POST is automatically secure."

False.

POST does not encrypt data.

If you need confidentiality in transit, use:

TEXT
HTTPS

So:

TEXT
POST + HTTP

is not automatically secure.

Whereas:

TEXT
POST + HTTPS

encrypts the network connection.

19. GET Is Usually Used for Retrieval

Examples:

TEXT
Search
Filter
Sort
Pagination
Viewing resources

Example:

TEXT
/products/?category=laptops

The request is asking:

Give me products matching this criterion.

20. POST Is Usually Used for State Changes

Examples:

TEXT
Create student
Submit feedback
Register user
Login
Create order
Update data through a form

The key idea is:

GET is generally safe/read-oriented; POST is generally used when submitting data that can cause a state change.

33. Processing the Form

View:

PYTHON
from django.http import HttpResponse

def student_create(request):

    if request.method == "POST":

        name = request.POST.get("name")
        age = request.POST.get("age")
        course = request.POST.get("course")

        return HttpResponse(
            f"Name: {name}, Age: {age}, Course: {course}"
        )

    return render(
        request,
        "student_form.html"
    )

Notice:

PYTHON
if request.method == "POST":

We only process submitted data when the request is POST.

34. GET and POST in the Same View

This pattern is extremely common.

PYTHON
def student_create(request):

    if request.method == "POST":

        name = request.POST.get("name")

        return HttpResponse(
            f"Student: {name}"
        )

    return render(
        request,
        "student_form.html"
    )

Meaning:

TEXT
GET
 ↓
Display form

POST
 ↓
Process submitted form

35. Why Is This Pattern Useful?

When the user first opens:

TEXT
/students/create/

the browser sends:

TEXT
GET

Django displays the form.

After clicking Submit:

TEXT
POST

Django processes the submitted data.

So one URL can handle both stages.

36. Form With action

You can explicitly specify:

HTML
<form
    action="{% url 'student_create' %}"
    method="POST"
>

This is usually better than:

HTML

because URL names make templates less dependent on hardcoded paths.

37. The action Can Be Empty

You may also see:

HTML
<form method="POST">

This submits to the current URL.

For example, if you're on:

TEXT
/students/create/

the form submits to that URL unless another action is specified.

40. One Important Problem

Our POST form currently lacks:

HTML
{% csrf_token %}

In Django, POST forms should normally include CSRF protection.

So a proper Django POST form is:

HTML
<form method="POST">

    {% csrf_token %}

    <input
        type="text"
        name="name"
    >

    <button type="submit">
        Submit
    </button>

</form>

Don't worry about the detailed mechanics yet.

CSRF is the next important Forms topic, and we'll study it properly in Module 23.

41. Why Does Django Require CSRF?

CSRF stands for:

Cross-Site Request Forgery

It's a security attack where a malicious site attempts to cause a user's browser to send an unwanted request to a site where the user is authenticated.

Django provides CSRF protection for state-changing requests such as POST.

We'll go deeply into:

TEXT
CSRF token
middleware
{% csrf_token %}
403 errors
CSRF_COOKIE

later.

42. GET Does Not Usually Need CSRF Token

You normally don't write:

HTML
<form method="GET">
    {% csrf_token %}

for a normal GET form.

CSRF protection is primarily relevant to unsafe/state-changing HTTP methods such as POST.

49. Common Mistakes

Mistake 1 — Forgetting name

Wrong:

HTML
<input type="text" id="name">

Correct:

HTML
<input
    type="text"
    id="name"
    name="name"
>

Mistake 2 — Reading POST data from request.GET

Wrong:

PYTHON
name = request.GET.get("name")

for a POST submission.

Correct:

PYTHON
name = request.POST.get("name")

Mistake 3 — Reading GET data from request.POST

Wrong:

PYTHON
query = request.POST.get("query")

for a GET search form.

Correct:

PYTHON
query = request.GET.get("query")

Mistake 4 — Forgetting CSRF

For a normal Django POST form:

HTML
<form method="POST">
    {% csrf_token %}

Mistake 5 — Thinking POST Encrypts Data

It doesn't.

Use HTTPS for encryption in transit.

Mistake 6 — Trusting Browser Validation

HTML validation can be bypassed.

Always validate on the server.

50. ⭐ Viva Questions

Q1. What is an HTML form?

An HTML form is a mechanism for collecting user input and submitting it to a server.

Q2. What are the common HTTP methods used with forms?

GET and POST.

Q3. What is the purpose of the method attribute?

It specifies the HTTP method used when submitting the form.

Q4. What is the purpose of action?

It specifies the URL to which the form data is submitted.

Q5. What is the purpose of the name attribute?

It identifies the form field's key in the submitted form data.

51. Viva — GET

Teacher:

Where is GET form data commonly visible?

Answer:

In the URL query string.

Example:

TEXT
/search/?query=Django

52. Viva — POST

Teacher:

Where is POST form data sent?

Answer:

It is sent in the HTTP request body rather than as the normal query string in the URL.

53. Viva — GET vs POST

Teacher:

Which one should you use for login?

Answer:

POST should generally be used because login is a form submission involving credentials and represents a stateful/authentication operation. HTTPS must also be used because POST itself does not encrypt data.

54. Viva — request.POST

Teacher:

What is request.POST?

Answer:

request.POST is a Django QueryDict containing form data submitted using POST.

55. Viva — request.GET

Teacher:

What is request.GET?

Answer:

request.GET is a Django QueryDict containing query parameters submitted through the URL, commonly by GET requests.

56. Viva — name vs id

Teacher:

Why is name important in a form?

Answer:

The name attribute identifies the field in the submitted form data, while id primarily identifies the HTML element for the document, CSS, JavaScript, and labels.
