Module 31 — Django Relationships & Foreign Keys

This is a very important Django module because real applications almost never have only one table.

For example, a college application might have:

TEXT
Department
    ↓
Students
    ↓
Courses
    ↓
Teachers

The database needs a way to connect these tables.

Django provides:

  • ForeignKey → many-to-one
  • OneToOneField → one-to-one
  • ManyToManyField → many-to-many

We'll start with ForeignKey, because it is the most commonly asked one.

1. Why Do We Need Relationships?

Suppose we have a Student model:

PYTHON
class Student(models.Model):
    name = models.CharField(max_length=100)
    course = models.CharField(max_length=50)

This works, but imagine 500 students.

You might have:

TEXT
Aman   → CSE
Rahul  → CSE
Priya  → CSE
Neha   → ECE
Karan  → ECE

The word CSE is repeatedly stored.

A better database design is:

Department table

TEXT
id    name
1     CSE
2     ECE
3     IT

Student table

TEXT
id    name      department_id
1     Aman      1
2     Rahul     1
3     Priya     1
4     Neha      2

Now students are connected to departments.

This is called a relationship.

2. Foreign Key

Django syntax:

PYTHON
department = models.ForeignKey(
    Department,
    on_delete=models.CASCADE
)

This creates a relationship between:

TEXT
Student → Department

A student belongs to one department, while a department can have many students.

Therefore:

ForeignKey represents a many-to-one relationship.

3. Complete Example

Let's create:

PYTHON
class Department(models.Model):
    name = models.CharField(max_length=100)

    def __str__(self):
        return self.name

Then:

PYTHON
class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField()
    department = models.ForeignKey(
        Department,
        on_delete=models.CASCADE
    )

    def __str__(self):
        return self.name

Conceptually:

TEXT
Department
    │
    ├── Student
    ├── Student
    └── Student

4. Why Is It Called Foreign Key?

The Student table contains a reference to a record in another table.

Conceptually:

TEXT
Student.department_id
          ↓
Department.id

The referenced field is generally the primary key of the related model.

Django handles the relationship for you.

5. Many-to-One

Suppose:

TEXT
Department: CSE

has:

TEXT
Aman
Rahul
Priya

Then:

TEXT
One Department
      ↓
Many Students

From the student's perspective:

TEXT
Many Students → One Department

That's why we call it:

Many-to-One

8. Using the Department ID

You can also assign the primary key directly using the _id form:

PYTHON
student = Student.objects.create(
    name="Rahul",

    department_id=1
)

Here:

TEXT
department

expects a Department object.

Whereas:

TEXT
department_id

expects the related object's primary-key value.

This is a very common viva question.

PYTHON

For example:

TEXT

PYTHON

TEXT
1

Memorize:

TEXT

        ↓
Department object

student.department_id
        ↓
Department primary-key value

Suppose:

PYTHON

PYTHON

TEXT

  ↓

11. on_delete

This is one of the most important ForeignKey concepts.

When we write:

PYTHON
department = models.ForeignKey(
    Department,
    on_delete=models.CASCADE
)

we are telling Django:

What should happen to related students if the department is deleted?

12. CASCADE

PYTHON
on_delete=models.CASCADE

means:

Delete related objects too.

Suppose:

TEXT
CSE
 ├── Aman
 ├── Rahul
 └── Priya

Delete CSE:

TEXT
CSE ❌
Aman ❌
Rahul ❌
Priya ❌

This is cascading deletion.

13. PROTECT

PYTHON
on_delete=models.PROTECT

means:

Don't allow the referenced object to be deleted if related objects still exist.

Example:

TEXT
CSE
 ├── Aman
 └── Rahul

Attempt to delete CSE:

TEXT
❌ Deletion prevented

This is useful when you don't want deleting a parent record to accidentally remove dependent data.

14. SET_NULL

PYTHON
department = models.ForeignKey(
    Department,
    on_delete=models.SET_NULL,
    null=True
)

If the department is deleted:

TEXT
Department ❌
     ↓
Student remains
     ↓
department = NULL

Important:

SET_NULL requires the field to allow NULL, normally with null=True.

15. SET_DEFAULT

You can use:

PYTHON
on_delete=models.SET_DEFAULT

Then the relationship is changed to the field's default value when the referenced object is deleted.

Example conceptually:

PYTHON
department = models.ForeignKey(
    Department,
    default=1,
    on_delete=models.SET_DEFAULT
)

The default must be meaningful and valid for the relationship.

16. DO_NOTHING

PYTHON
on_delete=models.DO_NOTHING

Django does not perform an automatic action.

Depending on the database's foreign-key constraints, deletion may result in a database error.

This is an advanced option and should be used carefully.

17. on_delete Cheat Sheet

Option Meaning
CASCADE Delete related objects
PROTECT Prevent deletion
SET_NULL Set relation to NULL
SET_DEFAULT Set relation to default
DO_NOTHING Django takes no automatic action

The most commonly encountered:

TEXT
CASCADE
PROTECT
SET_NULL

18. Reverse Relationship

Here's where things become interesting.

We have:

PYTHON
class Student(models.Model):
    department = models.ForeignKey(
        Department,
        on_delete=models.CASCADE
    )

From Student:

PYTHON
student.department

But what if we have a department and want its students?

Django automatically provides a reverse relationship.

By default:

PYTHON
department.student_set.all()

Example:

PYTHON
cse = Department.objects.get(name="CSE")

students = cse.student_set.all()

This returns all students belonging to CSE.

19. Why student_set?

Because the model is named:

PYTHON
Student

Django's default reverse manager is:

TEXT
student_set

For example:

PYTHON
department.student_set.all()

means:

Give me all Student objects related to this Department.

20. related_name

You don't have to use student_set.

You can define your own name:

PYTHON
department = models.ForeignKey(
    Department,
    on_delete=models.CASCADE,
    related_name="students"
)

Now:

PYTHON
cse.students.all()

instead of:

PYTHON
cse.student_set.all()

This is much more readable.

21. related_name Example

PYTHON
class Student(models.Model):
    name = models.CharField(max_length=100)

    department = models.ForeignKey(
        Department,
        on_delete=models.CASCADE,
        related_name="students"
    )

Now:

PYTHON
cse.students.all()

returns all students in CSE.

22. Forward vs Reverse Relationship

Forward

Starting from Student:

PYTHON
student.department

means:

TEXT
Student → Department

Reverse

Starting from Department:

PYTHON
department.students.all()

means:

TEXT
Department → Students

This distinction is commonly asked in interviews.

23. Querying Across Relationships

Suppose:

PYTHON
class Department(models.Model):
    name = models.CharField(max_length=100)

and:

PYTHON
class Student(models.Model):
    name = models.CharField(max_length=100)
    department = models.ForeignKey(
        Department,
        on_delete=models.CASCADE
    )

You can find all CSE students:

PYTHON
Student.objects.filter(
    department__name="CSE"
)

Notice:

TEXT
department__name

The double underscore means:

Traverse the relationship and query the related field.

24. More Relationship Queries

Students from CSE:

PYTHON
Student.objects.filter(
    department__name="CSE"
)

Students from departments whose name starts with C:

PYTHON
Student.objects.filter(
    department__name__startswith="C"
)

Students from departments containing "Engineering":

PYTHON
Student.objects.filter(
    department__name__icontains="Engineering"
)

25. Reverse Relationship Query

If you use:

PYTHON
related_name="students"

you can query from Department:

PYTHON
Department.objects.filter(
    students__name="Aman"
)

Meaning:

Find departments that have a student named Aman.

Without related_name, the reverse query name is based on Django's default reverse relationship.

26. Relationship + Q Objects

You can combine relationships with Q.

Example:

PYTHON
from django.db.models import Q

Student.objects.filter(
    Q(department__name="CSE") |
    Q(department__name="ECE")
)

Meaning:

TEXT
Department = CSE
OR
Department = ECE

27. Relationship + Ordering

Find students in CSE and order by marks:

PYTHON
Student.objects.filter(
    department__name="CSE"
).order_by(
    "-marks"
)

28. Relationship + Aggregation

Now relationships become extremely powerful.

Suppose we want:

Number of students in each department.

We can use:

PYTHON
from django.db.models import Count

Department.objects.annotate(
    student_count=Count("student")
)

If using:

PYTHON
related_name="students"

then:

PYTHON
Department.objects.annotate(
    student_count=Count("students")
)

Each department gets an additional calculated value:

TEXT
CSE → 3
ECE → 2
IT  → 5

This is a major reason annotate() is important.

29. annotate() + ForeignKey

Conceptually:

PYTHON

Then:

PYTHON

    print(

TEXT

ECE 2
IT 5

30. One-to-One Relationship

Now consider:

TEXT
Student
   ↓
Profile

Each student has exactly one profile.

And each profile belongs to exactly one student.

That's:

One-to-One

Django:

PYTHON
profile = models.OneToOneField(
    Student,
    on_delete=models.CASCADE
)

31. Example One-to-One

PYTHON
class StudentProfile(models.Model):

    student = models.OneToOneField(
        Student,
        on_delete=models.CASCADE
    )

    phone = models.CharField(max_length=15)
    address = models.TextField()

Relationship:

TEXT
Student 1 ───── 1 StudentProfile

32. Why Use One-to-One?

Suppose the Student model has:

TEXT
name
age
email
course

You could put everything in one model.

But perhaps profile information is separate:

TEXT
Student
 ├── name
 ├── age
 └── email

StudentProfile
 ├── phone
 ├── address
 └── photo

One-to-one connects them.

A classic real-world Django example is:

TEXT
User → Profile

33. Accessing One-to-One

Suppose:

PYTHON
profile = StudentProfile.objects.get(
    student=student
)

Then:

PYTHON
profile.student

returns the Student.

From the Student side, Django gives a reverse relationship based on the model name unless you specify a related_name.

For example, depending on the model naming:

PYTHON
student.studentprofile

can access the profile.

You can make it clearer:

PYTHON
student = models.OneToOneField(
    Student,
    on_delete=models.CASCADE,
    related_name="profile"

Then:

PYTHON
student.profile

48. select_related()

Now we're entering an important optimization concept.

Suppose you have:

PYTHON
students = Student.objects.all()

and inside a loop:

PYTHON
for student in students:
    print(student.department.name)

Django may need additional database queries to retrieve departments.

select_related() can optimize ForeignKey/OneToOne relationships:

PYTHON
students = Student.objects.select_related(
    "department"
)

Then:

PYTHON
for student in students:
    print(student.department.name)

Django can fetch the related department data together using a SQL join.

49. select_related() Applies To

Primarily:

TEXT
ForeignKey
OneToOneField

Think:

select_related = SQL JOIN for single-valued relationships

50. prefetch_related()

For multi-valued relationships such as:

TEXT
ManyToMany
Reverse ForeignKey

use:

PYTHON
prefetch_related()

Example:

PYTHON
departments = Department.objects.prefetch_related(
    "students"
)

Then:

PYTHON
for department in departments:
    for student in department.students.all():
        print(student.name)

Django can efficiently fetch the related collections.

51. select_related() vs prefetch_related()

Very important interview question.

Method Common use
select_related() ForeignKey, OneToOne
prefetch_related() ManyToMany, reverse ForeignKey

Simple memory trick:

TEXT
select_related
    ↓
single related object
    ↓
JOIN

prefetch_related
    ↓
multiple related objects
    ↓
separate optimized query + Python-side joining

57. Viva Masterclass

Q1. What is a relationship in a database?

A relationship defines how records in one table are associated with records in another table.

Q2. What is a ForeignKey?

ForeignKey defines a many-to-one relationship between two Django models.

Q3. Give an example.

Many students can belong to one department, so Student can have a ForeignKey to Department.

Q4. What is on_delete?

on_delete specifies what Django should do with related objects when the referenced object is deleted.

Q5. What does CASCADE mean?

Deleting the referenced object also deletes related objects.

Q6. What does PROTECT mean?

It prevents deletion of the referenced object while related objects still exist.

Q7. What does SET_NULL mean?

It sets the foreign-key value to NULL when the referenced object is deleted, and the field must allow NULL.

Q8. What is related_name?

related_name defines the name used to access the reverse relationship from the related model.

Q9. What is the difference between:

PYTHON
student.department

and:

PYTHON
student.department_id
student.department returns the related Department object, while student.department_id gives its primary-key value.

Q10. What is a One-to-One relationship?

A relationship where each object on one side is associated with at most one object on the other side.

Django:

PYTHON
OneToOneField

Q11. What is a Many-to-Many relationship?

A relationship where multiple objects on each side can be associated with multiple objects on the other side.

Django:

PYTHON
ManyToManyField

Q12. How do you add a Many-to-Many relationship?

PYTHON
student.courses.add(course)

Q13. How do you remove it?

PYTHON
student.courses.remove(course)

Q14. How do you remove all relationships?

PYTHON
student.courses.clear()

Q15. What is select_related()?

It optimizes queries involving ForeignKey and OneToOne relationships by fetching related objects using SQL joins.

Q16. What is prefetch_related()?

It optimizes fetching multi-valued relationships such as ManyToMany and reverse ForeignKey relationships, typically using separate queries and combining the results in Python.

Q17. Difference between select_related() and prefetch_related()?

select_related() is generally used for single-valued relationships such as ForeignKey and OneToOne, while prefetch_related() is generally used for multi-valued relationships such as ManyToMany and reverse ForeignKey.
