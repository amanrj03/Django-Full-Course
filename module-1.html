Module 1 — Web & Django Fundamentals

We’ll start from zero. By the end of this module, you should be able to explain the basic working of a web application and confidently answer the common viva questions about Django.

1. What is a Website?

A website is a collection of web pages that can be accessed through the internet using a web browser.

Examples:

  • Google
  • YouTube
  • Amazon
  • Wikipedia

A website generally contains:

  • HTML → structure
  • CSS → styling
  • JavaScript → behavior/interactivity
  • Backend → processing and business logic
  • Database → storing information

For example, when you open an online shopping website:

TEXT
You → Browser → Website Server → Database
                       ↓
                    Response
                       ↓
                    Browser

2. What is a Web Application?

A web application is a website that allows users to perform operations and interact with data.

For example:

Simple website

A page that says:

TEXT
Welcome to my website

There may be little or no user interaction.

Web application

An online shopping application allows you to:

TEXT
Register
Login
Search products
Add products to cart
Place orders
Make payments
View previous orders

So:

A web application is an application that runs through a web browser and allows users to interact with data and functionality provided by a server.

Django is mainly used for developing the backend of web applications.

3. Client and Server

This is VERY important for understanding Django.

Client

The client is usually the user's device/browser that sends requests to a server.

For example:

TEXT
Chrome
Firefox
Edge
Safari

Server

The server is a computer/program that receives requests, processes them, and sends responses.

For example, when you type:

TEXT
youtube.com

your browser sends a request to YouTube's servers.

The server processes it and sends information back.

4. Request and Response

The basic communication is:

TEXT
Client
   |
   | Request
   ↓
Server
   |
   | Response
   ↓
Client

Request

The browser says:

"Give me this webpage."

Response

The server says:

"Here is the webpage."

This concept is the foundation of Django.

5. Example of Request-Response

Suppose you visit:

TEXT
example.com/about

The process is approximately:

TEXT
1. Browser sends request
          ↓
2. Server receives request
          ↓
3. Django processes request
          ↓
4. Django determines what should happen
          ↓
5. Django generates response
          ↓
6. Server sends response
          ↓
7. Browser displays webpage

Later, we'll learn exactly how Django performs steps 3–5.

6. What is HTTP?

HTTP = HyperText Transfer Protocol

HTTP is a protocol used for communication between a client and a web server.

It defines how requests and responses are exchanged.

For example:

TEXT
Browser ─── HTTP Request ───→ Server

Browser ←── HTTP Response ─── Server

Common HTTP methods include:

TEXT
GET
POST
PUT
PATCH
DELETE

For your Django syllabus, GET and POST are particularly important.

We'll study them deeply in Unit II and Unit IV.

7. GET vs POST — Basic Idea

Don't worry about the details yet.

GET

Generally used to request/retrieve data.

Example:

TEXT
/products
/products/10

POST

Generally used to send data to the server.

For example, submitting a registration form:

TEXT
Name: Aman
Email: aman@example.com
Password: ********

The browser can send that information to the server using POST.

We'll study this properly later.

8. Frontend vs Backend

A web application generally has two major sides.

Frontend

The frontend is what the user sees and interacts with.

Technologies include:

TEXT
HTML
CSS
JavaScript
React
Angular
Vue

Example:

TEXT
+---------------------------+
|       My Website          |
|                           |
| Name: [____________]      |
|                           |

+---------------------------+

That's frontend.

9. Backend

The backend handles things that happen behind the scenes.

For example:

TEXT
User submits login
        ↓
Backend receives username/password
        ↓
Backend checks database
        ↓
Is user valid?
      /    \
    Yes     No
     ↓       ↓
 Dashboard  Error

Backend can handle:

  • Authentication
  • Database operations
  • Business logic
  • Form processing
  • Security
  • APIs
  • Sessions
  • User permissions

Django is a backend web framework.

Suppose you create an account.

The information needs to be stored somewhere:

TEXT
Username

ORM — Object Relational Mapping

11. What is a Framework?

Before understanding Django, you need to understand framework.

Suppose you want to build a house.

You could create everything from raw materials yourself:

TEXT
Bricks
Cement
Doors
Windows
Electrical system
Plumbing
etc.

Or you could use an established structure/design that makes construction easier.

A software framework provides a similar advantage.

A framework is a collection of tools, libraries, conventions, and structures that helps developers build applications more efficiently.

12. Why Do We Need Frameworks?

Imagine building a web application completely from scratch.

You would have to handle:

  • URL routing
  • HTTP requests
  • Database connections
  • Authentication
  • Security
  • Forms
  • Sessions
  • Error handling
  • HTML rendering

Doing everything manually would take a lot of time.

A framework provides many of these facilities.

So instead of reinventing everything, you can focus on your application's functionality.

13. What is Django?

Now the main question.

Django is a high-level, open-source Python web framework used for building web applications quickly, securely, and maintainably.

Important keywords for viva:

Django

  • Python-based
  • Web framework
  • Open-source
  • High-level
  • Used for web application development

You should remember this definition.

14. Why is Django Called a Python Web Framework?

Because Django is:

TEXT
Python
   ↓
Django
   ↓
Web Application

You write Django applications primarily using Python.

For example, a very simple Django view can look like:

PYTHON
from django.http import HttpResponse

def home(request):
    return HttpResponse("Hello World")

Don't worry if you don't understand this yet.

We'll build this from scratch in later modules.

15. Why Use Django?

Django provides many things out of the box.

1. URL Routing

It helps map URLs to application logic.

Example:

TEXT
/about → about view
/login → login view
/products → products view

2. Templates

Django allows Python-generated data to be displayed in HTML.

For example:

TEXT
Hello, Aman

can be dynamically generated.

3. Forms

Django provides tools for creating and validating forms.

4. Database Support

Django provides an ORM for working with databases using Python.

Instead of writing SQL for everything, you can write:

PYTHON
Student.objects.all()

5. Authentication

Django provides built-in support for:

TEXT
Users
Login
Logout
Passwords
Permissions
Groups

6. Security

Django provides protections/features for common web security concerns, including:

TEXT
CSRF protection
SQL injection protection through ORM usage
Clickjacking protection
XSS-related protections
Secure password handling

7. Admin Panel

One of Django's famous features is its built-in admin interface.

You can manage database data through a web interface.

Conceptually:

TEXT
Django Application
       ↓

       ↓
   Django Admin
       ↓
Manage data

16. Django's "Batteries Included" Philosophy

You may hear this phrase in a viva.

Django is often described as having a "batteries-included" philosophy.

It means Django provides many commonly needed features as part of the framework.

For example:

TEXT
Authentication
Admin
ORM
Forms
Sessions
Security
Templates
URL routing

You don't need to build all of these from scratch.

17. What is MVT?

This is VERY IMPORTANT for your viva.

Django follows an architectural pattern commonly described as:

MVT = Model – View – Template

The three components are:

TEXT
Model
View
Template

Let's understand each.

18. Model

The Model deals mainly with data and database structure.

Suppose you have students.

A model might represent:

TEXT
Student
----------------
id
name
email
age
course

Django can use this model to interact with the database.

Think:

Model = Data + Database logic

19. View

The View contains the logic that processes a request and determines what response should be returned.

For example:

PYTHON
def home(request):
    return HttpResponse("Welcome")

Think:

View = Business/request processing logic

20. Template

The Template is generally the presentation layer.

It usually contains HTML with Django Template Language.

Example:

HTML
<h1>Welcome {{ name }}</h1>

If the name is:

TEXT
Aman

the resulting page can display:

TEXT
Welcome Aman

Think:

Template = Presentation/UI

TEXT

TEXT

24. What is 127.0.0.1:8000?

When we start Django's development server, you'll commonly see:

TEXT
Starting development server at http://127.0.0.1:8000/

127.0.0.1

This means the local machine (localhost).

8000

This is the port on which Django's development server is listening by default.

So:

TEXT
127.0.0.1:8000

means:

"Access the Django development server running on this computer at port 8000."

26. Django vs Flask

You may be asked this in an interview/viva.

Both are Python web frameworks.

A simplified comparison:

Django Flask
More batteries-included More minimal
Built-in ORM Doesn't force a specific ORM
Built-in admin No built-in Django-style admin
Built-in authentication tools Usually assembled through extensions/code
More structured More flexible/minimal
Suitable for large structured applications Useful for lightweight/custom applications too

Don't say:

"Django is always better than Flask."

Instead say:

"Both are useful Python web frameworks. Django provides more built-in functionality, while Flask is more lightweight and minimal."

29. What You Should Be Able to Explain Now

If your teacher asks:

"What is Django?"

Answer:

Django is a high-level, open-source Python web framework used to develop web applications quickly, securely, and maintainably.

"What is MVT?"

Answer:

MVT stands for Model, View, and Template. Model handles data and database-related operations, View handles request and application logic, and Template handles presentation.

"What is a Model?"

Answer:

A Model is a Python class that represents the structure of application data and provides an interface for interacting with the database.

"What is a View?"

Answer:

A View is responsible for processing a request and returning an appropriate response.

"What is a Template?"

Answer:

A Template is used to define the presentation layer, usually HTML, and can contain Django Template Language for displaying dynamic data.
