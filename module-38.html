Module 38 — Django Login & Logout

This is one of the most important modules in the entire Django syllabus.

By now you know:

TEXT
Cookies
Sessions
Users
Authentication
Authorization

Now we're going to connect them together and build an actual login/logout system.

The three most important Django functions are:

PYTHON
authenticate()
login()
logout()

1. What Happens During Login?

Suppose a user enters:

TEXT
Username: aman
Password: StrongPassword123

The flow is:

TEXT
Login Form
    ↓
POST Request
    ↓
authenticate()
    ↓
Are credentials valid?
    ↓
YES
    ↓
login()
    ↓
Session established
    ↓
User is logged in
    ↓
request.user

If credentials are incorrect:

TEXT
authenticate()
    ↓
None

2. Authentication vs Login

These two are related but not the same thing.

authenticate()

Checks credentials.

PYTHON
user = authenticate(
    username=username,
    password=password
)

It essentially asks:

"Are these credentials valid?"

login()

Logs the authenticated user into the current session.

PYTHON
login(request, user)

It essentially says:

"Associate this authenticated user with this request/session."

3. logout()

Logs the user out.

PYTHON
logout(request)

It ends the user's authenticated session state.

4. Required Imports

A typical login view uses:

PYTHON
from django.contrib.auth import authenticate, login, logout

So:

PYTHON
from django.contrib.auth import authenticate, login, logout

Memorize this.

5. Basic authenticate()

Example:

PYTHON

    username="aman",
    password="StrongPassword123"
)

If credentials are valid:

TEXT

If credentials are invalid:

TEXT

6. Why Does authenticate() Return None?

Suppose:

PYTHON
user = authenticate(
    username="aman",
    password="wrongpassword"
)

Then:

PYTHON
user is None

because Django couldn't authenticate the credentials.

So the common pattern is:

PYTHON
if user is not None:
    # authentication successful
else:
    # authentication failed

7. Basic Login

Once you have a valid user:

PYTHON
login(request, user)

Example:

PYTHON
from django.contrib.auth import authenticate, login
from django.http import HttpResponse


def login_view(request):

    user = authenticate(
        username="aman",
        password="StrongPassword123"
    )

    if user is not None:

        login(request, user)

        return HttpResponse(
            "Login successful"
        )

    return HttpResponse(
        "Invalid credentials"
    )

This is the basic concept.

11. Complete Login View

PYTHON
from django.contrib.auth import authenticate, login
from django.shortcuts import render, redirect


def login_view(request):

    if request.method == "POST":

        username = request.POST.get(
            "username"
        )

        password = request.POST.get(
            "password"
        )

        user = authenticate(
            request,
            username=username,
            password=password
        )

        if user is not None:

            login(request, user)

            return redirect("dashboard")

        return render(
            request,
            "login.html",
            {
                "error": "Invalid username or password"
            }
        )

    return render(
        request,
        "login.html"
    )

This is a very important piece of Django code.

Let's understand every part.

No.

You still need:

31. Logout Link

You may see:

HTML
<a href="{% url 'logout' %}">
    Logout
</a>

But for a real application, state-changing logout is often better implemented as a POST action, with CSRF protection, rather than exposing logout as a simple GET link.

For example:

HTML
<form method="POST"
      action="{% url 'logout' %}">

    {% csrf_token %}

        Logout
    </button>

</form>

Then the view can perform logout on POST.

32. Secure Logout View

PYTHON
def logout_view(request):

    if request.method == "POST":

        logout(request)

        return redirect("login")

    return redirect("dashboard")

This follows the principle that state-changing operations should not casually be triggered by GET requests.

33. Login Form With Django Forms

You can also create a Django form.

For example:

PYTHON
from django import forms


class LoginForm(forms.Form):

    username = forms.CharField(
        max_length=150
    )

    password = forms.CharField(
        widget=forms.PasswordInput
    )

Then:

PYTHON
def login_view(request):

    if request.method == "POST":

        form = LoginForm(request.POST)

        if form.is_valid():

            username = form.cleaned_data[
                "username"
            ]

            password = form.cleaned_data[
                "password"
            ]

            user = authenticate(
                request,
                username=username,
                password=password
            )

            if user is not None:

                login(request, user)

                return redirect(
                    "dashboard"
                )

            form.add_error(
                None,
                "Invalid username or password"
            )

    else:

        form = LoginForm()

    return render(
        request,
        "login.html",
        {"form": form}
    )

37. Failed Login Should Not Reveal Too Much

A good login error is:

TEXT
Invalid username or password.

Rather than:

TEXT
Username exists but password is wrong.

Why?

Because revealing whether an account exists can help attackers enumerate valid usernames.

So a generic error message is generally preferable.

50. Very Important Viva Questions

Q1. What is authenticate()?

authenticate() verifies the supplied credentials using Django's authentication system and returns a user object if authentication succeeds, otherwise None.

Q2. Does authenticate() log the user in?

No. It verifies credentials. login(request, user) establishes the authenticated session.

Q3. What does login() do?

It associates the authenticated user with the current request/session so that subsequent requests can identify the user.

Q4. How do you log out?

PYTHON
logout(request)

Q5. What is request.user?

It represents the user associated with the current request.

Q6. What is request.user before login?

It is generally an AnonymousUser.

Q7. What is request.user after successful login?

It represents the authenticated User object.

Q8. How do you check whether the user is logged in?

PYTHON
request.user.is_authenticated

Q9. Why use redirect() after successful login?

It follows the POST-Redirect-GET pattern, preventing accidental form resubmission when the user refreshes the resulting page.

Q10. Why use {% csrf_token %} on login POST forms?

To provide Django's CSRF protection for the state-changing POST request.

Q11. Where is login state maintained?

Django commonly maintains authenticated login state using the session framework, with a session identifier stored in a cookie.

Q12. Difference between authenticate() and login()?

TEXT
authenticate()
       ↓
Verify credentials

login()
       ↓
Establish authenticated session

51. Interview Question

"What happens internally when a user logs in?"

A strong answer:

"The submitted credentials are passed to Django's authenticate() function. If authentication succeeds, it returns the user object. I then call login(request, user), which establishes the user's authenticated session. The browser subsequently sends the session identifier with future requests, allowing Django to populate request.user."

That's a very good interview-level answer.

52. Another Interview Question

"Can I use authenticate() without login()?"

Yes.

For example:

PYTHON
user = authenticate(
    request,
    username=username,
    password=password
)

You could use the result to determine whether credentials are valid.

But the user won't be logged into the normal Django session unless you subsequently call:

PYTHON
login(request, user)

53. Another Interview Question

"Can I call login() without authentication?"

Technically the function takes a user object, but your application should only establish authenticated state for a properly authenticated/trusted user.

Normal flow:

PYTHON
user = authenticate(...)

if user is not None:
    login(request, user)
