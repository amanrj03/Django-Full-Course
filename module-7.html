Module 7 — URL Routing in Depth

Now we're going deeper into Django URLs.

You already know the basic flow:

TEXT
Browser
   ↓
URL
   ↓
urls.py
   ↓
View
   ↓
Response

In this module we'll understand exactly how Django matches URLs and how to write different types of URL patterns.

This is important for both viva and coding questions.

1. What is URL Routing?

URL routing is the process of determining which view should handle a particular URL.

For example:

TEXT
/students/

might be mapped to:

PYTHON
views.students

while:

TEXT
/teachers/

might be mapped to:

PYTHON
views.teachers

Conceptually:

TEXT
URL
 ↓
URL Pattern
 ↓
View

2. urlpatterns

Django looks for URL patterns inside a variable conventionally named:

PYTHON
urlpatterns

Example:

PYTHON
from django.urls import path
from . import views

urlpatterns = [
    path('home/', views.home),
    path('about/', views.about),
]

Here there are two URL patterns.

3. What is path()?

path() is used to define URL patterns.

Basic syntax:

PYTHON
path(route, view)

Example:

PYTHON
path('home/', views.home)

Meaning:

If the requested URL matches home/, call views.home.

4. Basic URL Mapping

Suppose:

PYTHON
path('about/', views.about)

The user visits:

TEXT
/about/

Django calls:

PYTHON
views.about(request)

Flow:

TEXT
/about/
   ↓
path('about/', views.about)
   ↓
views.about(request)

5. Multiple URL Patterns

You can define multiple routes:

PYTHON
urlpatterns = [
    path('', views.home),
    path('about/', views.about),
    path('contact/', views.contact),
    path('students/', views.students),
]

So:

TEXT
/              → home
/about/        → about
/contact/      → contact
/students/     → students

6. Does Django Check All URLs?

Django checks URL patterns in order.

Conceptually:

TEXT
Request
   ↓
Pattern 1?
   ↓
No
   ↓
Pattern 2?
   ↓
No
   ↓
Pattern 3?
   ↓
Yes
   ↓
Call View

Once Django finds a matching URL pattern, it uses that match rather than continuing through later patterns.

This is why URL ordering can matter.

7. Example of URL Ordering

Suppose:

PYTHON
urlpatterns = [
    path('students/', views.students),
    path('students/profile/', views.profile),
]

A request for:

TEXT
/students/profile/

does not simply mean Django will always choose the first pattern. Django's path() route matching requires the route to match the URL path appropriately; students/ does not consume the extra profile/ segment as a complete match.

So this is different from a prefix-based router.

However, ordering becomes especially important when patterns can match the same URL, such as dynamic converters.

For example:

PYTHON
urlpatterns = [
    path('<str:value>/', views.string_view),
    path('about/', views.about),
]

The request:

TEXT
/about/

can match the dynamic string route first.

So Django calls:

TEXT
string_view

instead of:

TEXT
about

This is why specific patterns should generally come before broad dynamic patterns.

8. Empty Path ''

You have already seen:

PYTHON
path('', views.home)

The empty route means:

Match the empty path at this URL configuration level.

For example, if project URLs contain:

PYTHON
path('students/', include('students.urls'))

and app URLs contain:

PYTHON
path('', views.home)

then:

TEXT
/students/

calls:

TEXT
views.home

9. URL Prefix + App URL

Let's understand this carefully.

Project:

PYTHON
path('students/', include('students.urls'))

App:

PYTHON
path('', views.home)

Final URL:

TEXT
/students/

If app URL is:

PYTHON
path('profile/', views.profile)

final URL:

TEXT
/students/profile/

So:

TEXT
Project prefix
      +
App route
      =
Final URL

10. include()

Syntax:

PYTHON
include('students.urls')

It tells Django to include URL patterns from another URL configuration.

Example:

PYTHON
from django.urls import path, include

urlpatterns = [
    path('students/', include('students.urls')),
]

This is useful for organizing URLs by app.

11. Why Use include()?

Imagine your college project has:

TEXT
students
teachers
courses
accounts

Project URL:

PYTHON
urlpatterns = [
    path('students/', include('students.urls')),
    path('teachers/', include('teachers.urls')),
    path('courses/', include('courses.urls')),
    path('accounts/', include('accounts.urls')),
]

Now each app handles its own URLs.

This provides better organization.

12. URL Parameters

Now we reach an important concept.

Suppose you want:

TEXT
/students/10/

where:

TEXT
10

is the student's ID.

You don't want to create a separate URL for every student.

Instead, use a dynamic URL parameter.

PYTHON
path('students/<int:id>/', views.student_detail)

Now:

TEXT
/students/10/
/students/20/
/students/50/

can all use the same URL pattern.

13. Passing the Parameter to the View

URL:

PYTHON
path('students/<int:id>/', views.student_detail)

View:

PYTHON
def student_detail(request, id):
    return HttpResponse(f"Student ID: {id}")

If the user visits:

TEXT
/students/25/

Django calls approximately:

PYTHON
student_detail(request, id=25)

Response:

TEXT
Student ID: 25

14. Why Must the View Have id?

Because Django captures the URL value and passes it to the view.

URL:

PYTHON
<int:id>

means:

TEXT
capture integer
     ↓
call it id

Therefore your view needs to accept:

PYTHON
def student_detail(request, id):

15. Important Syntax

The general syntax is:

PYTHON
path('<converter:name>/', view)

For example:

PYTHON
path('<int:id>/', views.student)

Here:

TEXT
int
 ↓
Converter

id
 ↓
Parameter name

16. Common Path Converters

Django provides several built-in path converters.

str

PYTHON
path('user/<str:name>/', views.user)

Matches a non-empty string excluding /.

Example:

TEXT
/user/Aman/
/user/Rahul/

int

PYTHON
path('student/<int:id>/', views.student)

Matches integers.

Examples:

TEXT
/student/10/
/student/25/

slug

PYTHON
path('post/<slug:title>/', views.post)

Useful for URL-friendly strings such as:

TEXT
/my-first-post/
/django-tutorial/

A slug generally contains letters, numbers, hyphens, and underscores.

uuid

PYTHON
path('item/<uuid:id>/', views.item)

Used for UUID values.

path

PYTHON
path('files/<path:file_path>/', views.file)

Can capture a path including /.

For example:

TEXT
/files/docs/django/chapter1/

17. Path Converter Table

Remember:

Converter Purpose
str String excluding /
int Integer
slug Slug-style string
uuid UUID
path String that can include /

18. str vs int

Suppose:

PYTHON
path('student/<int:id>/', views.student)

Request:

TEXT
/student/25/

✅ Matches.

Request:

TEXT
/student/abc/

❌ Doesn't match this pattern because abc isn't an integer.

Now:

PYTHON
path('student/<str:id>/', views.student)

Both:

TEXT
/student/25/
/student/abc/

can match because they're strings.

19. Multiple URL Parameters

You can have multiple parameters.

Example:

PYTHON
path(
    'student/<int:id>/<str:name>/',
    views.student
)

View:

PYTHON
def student(request, id, name):
    return HttpResponse(
        f"ID: {id}, Name: {name}"
    )

URL:

TEXT
/student/10/Aman/

Result:

TEXT
ID: 10, Name: Aman

20. Parameter Names Matter

Suppose URL:

PYTHON
path('student/<int:id>/', views.student)

View:

PYTHON
def student(request, student_id):

This doesn't match Django's keyword argument name.

Django passes:

PYTHON
id=10

but your function expects:

PYTHON
student_id

So use matching names:

PYTHON
def student(request, id):

or change the URL:

PYTHON
path(
    'student/<int:student_id>/',
    views.student
)

and:

PYTHON
def student(request, student_id):

21. Query Parameters vs URL Parameters

This distinction is important.

URL parameter

TEXT
/students/10/

Defined with:

PYTHON
path('students/<int:id>/', ...)

Query parameter

TEXT
/students/?name=Aman

The name=Aman portion is a query parameter.

It's accessed through:

PYTHON
request.GET

We'll study query parameters properly in the HTTP requests module.

22. Named URLs

Now an important Django feature.

Suppose:

PYTHON
path('about/', views.about, name='about')

We have given the URL a name:

TEXT
about

Why?

Because instead of hardcoding:

TEXT
/about/

throughout your application, you can refer to the URL by its name.

This becomes extremely useful when URLs change.

23. Why Name URLs?

Suppose you have:

TEXT
/about/

and use this URL in 20 templates.

Later you change it to:

TEXT
/company/about/

If you've hardcoded /about/ everywhere, you may need to modify many files.

Named URLs allow Django to resolve the correct URL from the name.

This is called URL reversing.

24. Example Named URL

PYTHON
urlpatterns = [
    path('about/', views.about, name='about'),
]

Now Django associates:

TEXT
about
 ↓
/about/

Later we can use:

DJANGO
{% url 'about' %}

inside a template.

We'll study this properly in the Templates module.

25. URL Names in Python

You can also reverse URLs in Python using:

PYTHON
from django.urls import reverse

Example:

PYTHON
url = reverse('about')

This could produce:

TEXT
/about/

We'll use this later.

26. URL Names with Parameters

Suppose:

PYTHON
path(
    'student/<int:id>/',
    views.student,
    name='student'
)

To reverse it, Django needs the ID.

Conceptually:

PYTHON
reverse('student', kwargs={'id': 10})

Result:

TEXT
/student/10/

This becomes very useful when working with dynamic pages.

27. Namespaces

When multiple apps have URLs with the same name, namespaces help avoid conflicts.

Suppose:

TEXT
students → detail
teachers → detail

Both might have:

PYTHON
name='detail'

Without namespaces, it can become ambiguous.

You can organize them using an application namespace.

We'll cover this more deeply once we start building larger applications.

For now, know:

Namespaces help distinguish URL names belonging to different applications.

28. app_name

Inside an app's urls.py, you can define:

PYTHON
app_name = 'students'

Example:

PYTHON
from django.urls import path
from . import views

app_name = 'students'

urlpatterns = [
    path(
        'profile/',
        views.profile,
        name='profile'
    ),
]

Now the URL name can be referenced as:

TEXT
students:profile

For example in a template:

DJANGO
{% url 'students:profile' %}

This is especially useful when several apps have similarly named URLs.

29. Complete Example

Let's build a small app URL configuration.

students/views.py

PYTHON
from django.http import HttpResponse

def home(request):
    return HttpResponse("Students Home")

def about(request):
    return HttpResponse("About Students")

def student_detail(request, id):
    return HttpResponse(f"Student ID: {id}")

students/urls.py

PYTHON
from django.urls import path
from . import views

app_name = 'students'

urlpatterns = [
    path('', views.home, name='home'),
    path('about/', views.about, name='about'),
    path(
        '<int:id>/',
        views.student_detail,
        name='detail'
    ),
]

College/urls.py

PYTHON
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path(
        'students/',
        include('students.urls')
    ),
]

Now:

TEXT
/students/           → home
/students/about/     → about
/students/10/        → student_detail(id=10)
/students/25/        → student_detail(id=25)

30. How Django Chooses a URL

Suppose user requests:

TEXT
/students/25/

Project:

PYTHON
path('students/', include('students.urls'))

Django passes the remaining portion:

TEXT
25/

to students.urls.

Then:

PYTHON
path('<int:id>/', views.student_detail)

matches it.

Django extracts:

TEXT
id = 25

and calls:

PYTHON
views.student_detail(request, id=25)

31. URL Routing Mental Model

Think of URL routing like a chain:

TEXT
Full URL
   ↓
Project URL
   ↓
Prefix removed
   ↓
App URL
   ↓
Converter captures parameters
   ↓
View receives parameters

Example:

TEXT
/students/25/
      ↓
students/
      ↓
25/
      ↓
<int:id>

This understanding is much more useful than memorizing syntax.

32. path() vs re_path()

Your syllabus specifically mentions:

Regular expressions in URLs

For most modern URL routing, use:

PYTHON
path()

because built-in converters handle common cases.

For more complex matching, Django provides:

PYTHON
re_path()

Example:

PYTHON
from django.urls import re_path

urlpatterns = [
    re_path(
        r'^student/(?P<id>[0-9]+)/$',
        views.student
    ),
]

Don't worry about regex syntax yet.

We'll dedicate a later module specifically to it.

33. Common URL Errors

Error 1 — Forgetting include

Wrong:

PYTHON
from django.urls import path

urlpatterns = [
    path('students/', include('students.urls')),
]

include wasn't imported.

Correct:

PYTHON
from django.urls import path, include

Error 2 — Wrong parameter in view

URL:

PYTHON
path('<int:id>/', views.student)

View:

PYTHON
def student(request, student_id):

Mismatch.

Correct:

PYTHON
def student(request, id):

Error 3 — App URLs Not Included

You create:

TEXT
students/urls.py

but forget:

PYTHON
path('students/', include('students.urls'))

Then Django's project-level routing won't reach those app URL patterns.

34. Viva Questions

Q1. What is URL routing?

URL routing is the process of mapping requested URLs to the appropriate Django views.

Q2. What is urlpatterns?

It is the list containing URL patterns used by Django's URL dispatcher.

Q3. What is path()?

path() is used to define URL patterns in Django.

Q4. What is include()?

include() allows URL patterns from another URL configuration, commonly an app's urls.py, to be included in the current URL configuration.

Q5. What is a path converter?

A path converter defines the type of value that Django should capture from a dynamic URL segment, such as an integer or string.

Q6. Name Django's built-in path converters.

str, int, slug, uuid, and path.

Q7. How do you create a dynamic integer URL?

PYTHON
path('<int:id>/', views.view_name)

Q8. How is the captured parameter passed to the view?

Django passes it as an argument to the view using the parameter name defined in the URL pattern.

35. Viva Trap ⚠️

Teacher:

What happens if the URL contains /student/abc/ but the pattern is:
PYTHON
path('student/<int:id>/', views.student)

Answer:

The pattern does not match because abc cannot be converted to an integer.

Django will continue looking for another matching pattern. If none matches, the request results in a 404 response.

36. Another Viva Trap

Teacher:

Is /student/10/ and /student/abc/ the same type of URL?

Not necessarily.

With:

PYTHON
<int:id>

the first can match, while the second cannot.

With:

PYTHON
<str:id>

both can match.
