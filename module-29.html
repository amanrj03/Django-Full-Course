Module 29 — Django Shell & CRUD

Now we're going to actually work with database records.

CRUD is one of the most important practical topics in Django:

C — Create
R — Read
U — Update
D — Delete

By the end, you should be able to perform all four operations using Django ORM and explain them in a viva.

1. What Is CRUD?

CRUD represents the four basic database operations:

CRUD Meaning Django
C Create Create a record
R Read Retrieve records
U Update Modify records
D Delete Remove records

Example:

TEXT
Student
    ↓
Create → Add student
Read   → View student
Update → Change student details
Delete → Remove student

2. Why Django Shell?

You can interact with your Django project using:

BASH
python manage.py shell

The Django shell gives you a Python environment where Django is already configured.

You can directly work with:

PYTHON
Student.objects.all()
Student.objects.create(...)
Student.objects.filter(...)

This is extremely useful for:

  • Learning ORM
  • Testing queries
  • Debugging
  • Creating test data
  • Inspecting database records
  • Practical exams

3. Starting the Django Shell

From the folder containing manage.py:

BASH
python manage.py shell

TEXT

>>>

Now you're inside the Django shell.

PYTHON

PYTHON

5. CREATE — Method 1

Create an object:

PYTHON
student = Student(
    name="Aman",
    age=21,
    email="aman@gmail.com",
    course="CSE",
    marks=85
)

At this point:

The object exists in Python memory, but it has not necessarily been saved to the database yet.

Now:

PYTHON
student.save()

This saves it.

6. CREATE — Method 2: objects.create()

A shorter approach:

PYTHON
student = Student.objects.create(
    name="Aman",
    age=21,
    email="aman@gmail.com",
    course="CSE",
    marks=85
)

This:

  1. Creates the object
  2. Saves it to the database

So:

TEXT
Student(...)
     ↓
Python object
     ↓
save()
     ↓
Database

whereas:

TEXT
Student.objects.create(...)
     ↓
Create + Save

7. create() vs save()

Method 1

PYTHON
student = Student(
    name="Aman"
)

student.save()

Method 2

PYTHON
student = Student.objects.create(
    name="Aman"
)

The second is shorter.

Viva answer:

objects.create() creates and saves the model instance immediately, while instantiating a model with Model(...) only creates the Python object until save() is called.

8. Verify the Record

Now:

PYTHON
Student.objects.all()

Something like:

The exact representation depends on your model's __str__() method.

9. __str__() — Very Useful

By default, Django may display:

TEXT
<Student: Student object (1)>

In models.py:

PYTHON
class Student(models.Model):

    name = models.CharField(max_length=100)
    age = models.IntegerField()
    email = models.EmailField()

    def __str__(self):
        return self.name

PYTHON
Student.objects.all()

TEXT

This is especially useful in:

  • Django shell
  • Django admin
  • Debugging

12. get() Requires Exactly One Result

Remember:

PYTHON
Student.objects.get(id=1)

expects exactly one object.

If none exists:

TEXT
Student.DoesNotExist

If multiple records match:

TEXT
MultipleObjectsReturned

For a unique primary key lookup, multiple matches aren't possible, but other conditions can produce multiple results.

20. UPDATE — Method 1

Suppose:

PYTHON
student = Student.objects.get(id=1)

Change:

PYTHON
student.marks = 95

Then:

PYTHON
student.save()

Flow:

TEXT

    ↓
Change attribute
    ↓
save()
    ↓
Database updated

21. Updating Multiple Fields

PYTHON
student.name = "Aman Ranjan"
student.age = 22
student.marks = 95

student.save()

Now all changed fields are saved.

22. UPDATE — Method 2: update()

You can update directly through a QuerySet:

PYTHON
Student.objects.filter(
    id=1
).update(
    marks=95
)

This directly performs a database update.

23. Updating Multiple Records

Suppose we want to give every CSE student 5 additional marks:

PYTHON
Student.objects.filter(
    course="CSE"
).update(
    marks=100
)

This updates every matching record.

Be careful.

Bulk updates can affect many records at once.

24. save() vs update()

This is an important viva question.

save()

PYTHON
student.marks = 95
student.save()

Works with a model instance.

update()

PYTHON
Student.objects.filter(id=1).update(
    marks=95
)

Works on a QuerySet and performs a direct bulk database update.

Remember an important consequence:

QuerySet.update() does not call each model instance's save() method.

So if your model has custom save() behavior, don't assume update() will execute it.

25. UPDATE Using get()

Another common pattern:

PYTHON
student = Student.objects.get(
    email="aman@gmail.com"
)

student.marks = 90

student.save()

This is useful when you want to work with the actual model object.

26. DELETE — Method 1

Get an object:

PYTHON
student = Student.objects.get(id=1)

Then:

PYTHON
student.delete()

The record is removed.

27. DELETE — Method 2

Delete directly:

PYTHON
Student.objects.filter(
    id=1
).delete()

This deletes matching records.

28. Delete Multiple Records

Suppose we want to delete inactive students:

PYTHON
Student.objects.filter(
    is_active=False
).delete()

All matching records are deleted.

Again:

Be very careful with bulk delete operations.

31. get_or_create()

Django provides a useful method:

PYTHON
Student.objects.get_or_create(...)

Suppose:

PYTHON
student, created = Student.objects.get_or_create(
    email="aman@gmail.com",
    defaults={
        "name": "Aman",
        "age": 21,
        "course": "CSE"
    }
)

It attempts to:

  1. Find an existing matching object
  2. If it doesn't exist, create one

It returns:

TEXT
(object, created)

where:

TEXT
created = True

if a new object was created.

Otherwise:

TEXT
created = False

if an existing object was found.

32. Why get_or_create() Is Useful

Suppose you want to make sure a record exists without writing:

PYTHON
try:
    ...
except:
    ...

yourself.

You can use:

PYTHON
get_or_create()

This is especially useful for initialization/setup-type operations.

33. update_or_create()

Another useful method:

PYTHON
Student.objects.update_or_create(...)

It:

  • Updates an existing matching object
  • Or creates it if it doesn't exist

Example:

PYTHON
student, created = Student.objects.update_or_create(
    email="aman@gmail.com",
    defaults={
        "name": "Aman",
        "age": 22,
        "marks": 95
    }
)

The lookup fields are used to find the object, while defaults contains values to update/create.

34. get_or_create() vs update_or_create()

Method Behavior
get_or_create() Get existing or create
update_or_create() Update existing or create

35. delete() Return Value

When deleting objects:

PYTHON
student.delete()

Django returns information about the deletion, including the number of objects deleted and a breakdown by model.

For basic coding questions, you usually only need:

PYTHON
student.delete()

36. Creating Multiple Records

You can use:

PYTHON
Student.objects.bulk_create([
    Student(
        name="Aman",
        age=21,
        email="aman@gmail.com",
        course="CSE"
    ),
    Student(
        name="Rahul",
        age=22,
        email="rahul@gmail.com",
        course="ECE"
    ),
])

This is useful for efficiently inserting many objects.

It's an advanced operation; don't use it when you need individual save() behavior for every object.

37. Bulk Update

For example:

PYTHON
Student.objects.filter(
    course="CSE"
).update(
    is_active=True
)

This updates all matching records in one database operation.

38. Bulk Delete

PYTHON
Student.objects.filter(
    age__lt=18
).delete()

This removes all students under 18.

39. Important Difference: delete() vs update()

Both can operate on QuerySets:

PYTHON
Student.objects.filter(...).update(...)

and:

PYTHON
Student.objects.filter(...).delete()

But they perform completely different actions:

TEXT
update() → changes records
delete() → removes records

40. Using get_object_or_404() in Views

Shell:

PYTHON
student = Student.objects.get(id=1)

View:

PYTHON
from django.shortcuts import get_object_or_404

student = get_object_or_404(
    Student,
    id=1
)

Why?

Because a web request should normally produce an HTTP 404 response rather than an unhandled DoesNotExist exception.

41. CRUD in a Django View

Let's make a simple read view:

PYTHON
from django.shortcuts import render
from .models import Student


def student_list(request):

    students = Student.objects.all()

    return render(
        request,
        "students.html",
        {"students": students}
    )

42. Create Through a View

Example:

PYTHON
from django.shortcuts import redirect, render
from .forms import StudentForm
from .models import Student


def create_student(request):

    if request.method == "POST":

        form = StudentForm(request.POST)

        if form.is_valid():

            Student.objects.create(
                name=form.cleaned_data["name"],
                age=form.cleaned_data["age"],
                email=form.cleaned_data["email"],
                course=form.cleaned_data["course"]
            )

            return redirect("student_list")

    else:
        form = StudentForm()

    return render(
        request,
        "create_student.html",
        {"form": form}
    )

Notice how many previous modules are now connecting:

TEXT
Form
 ↓
Validation
 ↓
ORM
 ↓
Create
 ↓
Redirect

43. Update Through a View

Conceptually:

PYTHON
from django.shortcuts import get_object_or_404, redirect, render


def update_student(request, id):

    student = get_object_or_404(
        Student,
        id=id
    )

    if request.method == "POST":

        form = StudentForm(request.POST)

        if form.is_valid():

            student.name = form.cleaned_data["name"]
            student.age = form.cleaned_data["age"]
            student.email = form.cleaned_data["email"]
            student.course = form.cleaned_data["course"]

            student.save()

            return redirect("student_list")

    else:
        form = StudentForm(
            initial={
                "name": student.name,
                "age": student.age,
                "email": student.email,
                "course": student.course,
            }
        )

    return render(
        request,
        "update_student.html",
        {"form": form}
    )

Don't worry if this seems long. We're going to build complete CRUD projects later.

44. Delete Through a View

A safer basic pattern is to use POST for destructive operations:

PYTHON
from django.shortcuts import get_object_or_404, redirect


def delete_student(request, id):

    student = get_object_or_404(
        Student,
        id=id
    )

    if request.method == "POST":

        student.delete()

        return redirect("student_list")

Template:

HTML
<form method="POST">
    {% csrf_token %}

    <button type="submit">
        Delete
    </button>
</form>

Notice:

+
redirect()

56. Viva Masterclass

Q1. What is CRUD?

CRUD stands for Create, Read, Update, and Delete, the four basic operations performed on persistent data.

Q2. How do you enter Django shell?

BASH
python manage.py shell

Q3. How do you import a model in the shell?

PYTHON
from students.models import Student

Q4. How do you create a model object?

PYTHON

    name="Aman"
)
student.save()

Q5. How do you create and save in one operation?

PYTHON
Student.objects.create(...)

Q6. Difference between create() and save()?

create() creates and saves an object immediately, while save() explicitly persists a model instance to the database.

Q7. How do you retrieve all objects?

PYTHON
Student.objects.all()

Q8. How do you retrieve one object?

PYTHON
Student.objects.get(id=1)

Q9. What happens if get() doesn't find an object?

It raises the model's DoesNotExist exception.

Q10. How do you update a model?

PYTHON
student.marks = 95
student.save()

Q11. How do you perform a bulk update?

PYTHON
Student.objects.filter(
    course="CSE"
).update(
    marks=90
)

Q12. How do you delete a model object?

PYTHON
student.delete()

Q13. How do you delete multiple objects?

PYTHON
Student.objects.filter(
    is_active=False
).delete()

Q14. What is get_or_create()?

It attempts to retrieve an existing object matching the lookup parameters and creates one if no matching object exists.

Q15. What does update_or_create() do?

It updates an existing matching object or creates one if it doesn't exist.

Q16. What is __str__() used for?

It defines the human-readable string representation of a model instance.
