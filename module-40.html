11. What Is ModelForm?

A ModelForm creates a form based on a Django model.

Instead of manually writing:

PYTHON
name = forms.CharField(...)
email = forms.EmailField(...)
age = forms.IntegerField(...)

Django derives the form fields from:

PYTHON
class Student(models.Model):

12. Meta.model

PYTHON
class Meta:
    model = Student

This tells Django:

This form is associated with the Student model.

13. Meta.fields

PYTHON
fields = [
    "name",
    "email",
    "course",
    "age",
    "marks",
]

This determines which model fields appear in the form.

You can also use:

PYTHON
fields = "__all__"

but explicitly listing fields is often safer and clearer.

22. Step 9 — Create Student

Now implement Create.

In views.py:

PYTHON
from django.shortcuts import (
    render,
    redirect
)

from .forms import StudentForm


def student_create(request):

    if request.method == "POST":

        form = StudentForm(
            request.POST
        )

        if form.is_valid():

            form.save()

            return redirect(
                "student_list"
            )

    else:

        form = StudentForm()

    return render(
        request,
        "students/student_form.html",
        {
            "form": form
        }
    )

23. Understand Create Flow

Initial request:

TEXT

def student_update(request, id):

    )

30. The Important Part of Update

Look carefully:

PYTHON

    request.POST,
    instance=student
)

The:

PYTHON
instance=student

is what tells the ModelForm:

"Update this existing student rather than creating a new student."

44. Validation

Our ModelForm already gets many validation rules from the model.

45. Add Validation

In forms.py:

PYTHON
from django import forms
from .models import Student


class StudentForm(forms.ModelForm):

    class Meta:
        model = Student

        fields = [
            "name",
            "email",
            "course",
            "age",
            "marks",
        ]

    def clean_marks(self):

        marks = self.cleaned_data["marks"]

        if marks < 0 or marks > 100:

            raise forms.ValidationError(
                "Marks must be between 0 and 100."
            )

        return marks

46. Understand clean_marks()

This method:

PYTHON
clean_marks()

is called for the marks field.

We retrieve:

PYTHON
marks = self.cleaned_data["marks"]

Then:

PYTHON
if marks < 0 or marks > 100:

checks the business rule.

If invalid:

PYTHON
raise forms.ValidationError(...)

If valid:

PYTHON
return marks

62. Why Doesn't Create Use GET?

A GET request should generally be safe and shouldn't change server state.

So:

TEXT

only displays the form.

Then:

TEXT

65. One Very Important Interview Question

"Explain your Django CRUD project."

A strong answer:

"I created a Student model containing fields such as name, email, course, age and marks. I created a ModelForm from that model for input handling and validation. The list view uses Django ORM to retrieve students and passes them to a template. The create and update views process POST requests using the ModelForm and follow the POST-Redirect-GET pattern after successful submission. The update form uses instance=student so the existing record is modified rather than creating a new one. For deletion, I retrieve the object with get_object_or_404(), require a POST request with CSRF protection, delete the object, and redirect back to the list. 66. Common Viva Questions

Q1. What is CRUD?

Create, Read, Update and Delete.

Q2. What is a ModelForm?

A Django form class that is associated with a model and can generate form fields and save model instances.

Q3. Why use instance during update?

It tells the ModelForm which existing model instance should be updated instead of creating a new record.

Q4. Why use get_object_or_404()?

It retrieves an object or raises an HTTP 404 response if the object doesn't exist.

Q5. Why use redirect() after saving?

To follow the POST-Redirect-GET pattern and prevent duplicate form submissions on refresh.

Q6. Why use CSRF token?

To protect POST requests against CSRF attacks.

Q7. Why shouldn't deletion happen through GET?

GET should generally be safe and read-only; destructive operations should use an appropriate state-changing method such as POST.

Q8. Why use ModelForm instead of manually creating every form field?

It reduces repetitive code and connects form validation and saving directly to the model.

Q9. Where does form.save() save data?

It saves the model instance to the configured database.

Q10. How does update differ from create?

PYTHON
# Create
StudentForm(request.POST)

# Update
StudentForm(
    request.POST,
    instance=student
)
